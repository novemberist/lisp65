# lisp65 2.0.0 Release Notes

Release date: 2026-09-02

lisp65 2.0.0 makes public library domain behavior fail explicitly instead of
returning plausible but invalid values.  Twenty-two Tier-1 functions move 62
contract cells from silently wrong results to errors.  The measured public
surface is now **545 error-raised / 179 documented-permissive / 110
silently-wrong** over the same 834-cell population.

The release retains the lossless native input path and native prompt editor
from 1.9.  Physical MEGA65 acceptance crossed a forced collection with all
four counters equal and nonzero at 138 events:
`raw = seen = stored = taken = 138`.

## Domain discipline

Tier 1 covers cold library paths where an unsupported domain must no longer
produce an ordinary value.  For example, `(length "abc")` now raises a VM
type error and returns to one live prompt.  The contract table was measured
again from the executed successor world; its 62 changes were not obtained by
subtracting from an earlier count.

The hottest `car`/`cdr` opcodes remain deliberately permissive in this
release: `(car nil)` and `(car 1)` both return `nil`.  A fully checked Tier-2
implementation was measured but did not fit the resident text budget without
an unacceptable per-key latency cost.  This inconsistency is therefore
documented rather than hidden.

## Input and delivery architecture

The native `lisp65>` prompt continues to own the insertion-mode editor.
Cursor movement, insertion and deletion use the hardware-proven v1.9 editor
path byte-for-byte.  Capture remains armed while `read-line` is active, and
the delivered consumer takes events from the ring; the final host wall is
94/94/94/94 and the device wall is 138/138/138/138.

The product is assembled as one resident, generation-coherent world.
Transitive closure and generation coherence are checked over the bytes read
back from the packed medium.  Build authorities, generated constants,
placement geometry and qualifier roots are derived from their phase-owned
producers rather than silent historical defaults.

The obsolete duplicate `v16core` library is not delivered.  The editor is
resident, so no optional editor library is required or supported.

## Retained native behavior

The once-per-boot `INIT.L65` hook and A0 empty-journal recovery remain.  An
absent INIT file is silent; a valid INIT runs exactly once before banner and
prompt; a VM error returns to one usable prompt.  The release medium contains
no `INIT.L65`.

Release-terminal D5 measured **107 free symbol slots and 1,467 free name
bytes**, above the mandatory 32/384 floor.  Four representative performance
bodies completed in at most one frame, and the final single-key path measures
902 VM steps, identical to the v1.9 hardware-green reference.

## Claim boundary

v2.0.0 claims the 62 Tier-1 domain corrections, lossless native-prompt input
across a forced collection, the native editor and INIT/A0 behavior, and the
resident delivery-chain gates.  It does not claim evaluation-time type-ahead,
Comfort, balanced multiline input/history, delimiter matching, cursor
blinking or Tier-2 `car`/`cdr` checks.  Those remain sealed return candidates
for the 2.x series.
