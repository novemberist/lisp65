# lisp65 1.6.0 Release Notes

Release date: pending publication

lisp65 1.6.0 is a deliberately focused release. It adds editable cursor
navigation to the native REPL and ships the independent safety repairs found
while qualifying that work. The larger Comfort REPL, Attic-write boundary and
startup optimization remain post-1.6 work. The visible banner is
`WORKBENCH 1.6.0`.

## Cursor navigation in the REPL

Load the one-row v1.6 library medium and activate the editor once per cold
session:

```lisp
(require 'v16core)
```

The native `lisp65>` prompt then supports insertion at the cursor rather than
overwrite:

- Cursor Left / Cursor Right, with `C-b` / `C-f` aliases;
- `C-a` / `C-e` for the beginning and end of the line;
- Delete for backward deletion and `C-d` for forward deletion;
- no-op movement or deletion at the corresponding line boundary; and
- the existing 250-character input limit with a cursor-following viewport.

The accepted physical session typed `abde`, moved left twice and inserted
`c`; the returned string was `abcde`. Mixed cursor/control navigation returned
`abcdef`, endpoint and deletion probes returned `abcd`, and both left and
right boundary operations were harmless. Ordinary native echo still returned
`(1 3)` for `(list 1 3)`.

This release does not include the balanced multiline/history Comfort REPL. Its
implementation and diagnostic evidence are retained for v1.7, but neither its
library nor its input-capture path is present in the selected v1.6 product.

## Boot-refill and delivered-byte safety

v1.5.0 contained one generated boot-refill path that could report success
before DMA content was safely visible. Under unfavorable timing the visible
symptom could be a sporadic `*** vm: bad bytecode` during startup or library
loading. v1.6 removes that exception: the final linked boot reader uses the
same MAP CPU transport and content-convergence discipline as the other mutable
readers.

The structural final-ELF gate now finds zero unsafe content-consuming DMA
readers, generated code included. Completion also materializes the mapped
facade into the delivered PRG, and a permanent gate compares the packed PRG
facade byte-for-byte with the linked ELF. The safety claim therefore ends at
the shipped byte, not at an intermediate object.

MAP-arena code is checked transitively: a mapped body may not reach another
MAP enter/leave pair. Address-based analyses in overlapping arenas use an
address plus mapping domain rather than treating a numeric address as a unique
identity.

## Error recovery at retired overlay boundaries

The runtime now has a carrier-independent execution-boundary backstop for a
transfer into a retired overlay generation. Recovery sanitizes all seven
control/status register pairs before completing its non-local return, so the
recovery path cannot immediately re-arm the stale target it just caught.

The physical acceptance session exercised the ordinary type error
`(>= nil 32)`. It printed `*** vm: type error` and returned to a usable native
prompt; `(list 1 3)` then evaluated normally. The claim is bounded to the
shipped backstop and observed recovery path, not to arbitrary memory
corruption.

## Input and language behavior retained

- The interactive WYSIWYG boundary still normalizes PETSCII Shift-Space `$A0`
  to ordinary space and visibly rejects non-displayable controls.
- Several forms on one line are still evaluated left to right. A reader error
  in trailing input does not undo forms already completed on that line.
- RUN/STOP retains its independent matrix authority.
- Durable definitions continue to use transactional publication; ordinary
  non-persistent expressions retain the direct path introduced in v1.5.

## Known limitations and scope

The maintained [Known Issues and Retired Exceptions](../known-issues.md) holds
the complete boundary. In particular, enter the Freezer only while the REPL is
idle; fail-closed stops that are outside the recovered retired-window class
still do not print their cause; storage and session metadata remain bounded;
and standalone Ship RUN/STOP still lacks independent `$91` verification.

The v1.6 optional-library image contains `v16core`. The v1.5 optional package
set (`string-extra`, `inspect`, `place`, and `defstruct`) is not part of the
v1.6 selected artifact set or its hardware claim.

## Claim boundary

v1.6.0 claims the exact 22-role product/library set above, the physical cursor
navigation rows, ordinary error recovery row and D5 headroom/performance rows.
It does not claim the Comfort REPL, lossless capture input, Attic writes,
sub-30-second startup, active-persistence Freezer safety, line-atomic REPL
input, or arbitrary live-session shipping.
