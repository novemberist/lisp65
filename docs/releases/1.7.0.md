# lisp65 1.7.0 Release Notes

Release date: pending publication

lisp65 1.7.0 adds a native, fail-safe `INIT.L65` startup hook and makes the
empty-journal recovery path substantially faster. It also ships the composed
Bank-2 and MAP-geometry checks developed while qualifying those changes. The
visible banner is `WORKBENCH 1.7.0`.

The optional `v16core` cursor-navigation library from v1.6 remains available.
The experimental Comfort REPL and the delimiter-matcher/blinking-cursor block
are not present in the selected v1.7 product.

## Native `INIT.L65` hook

After the resident world is ready, lisp65 looks for `INIT.L65` on the mounted
boot/library medium and evaluates it before the first banner and native prompt.
Absence is a silent, zero-work result. A startup file is attempted once per
cold boot: an open or VM error follows the ordinary abort path and returns to
one usable `lisp65>` prompt rather than retrying or bricking the boot.

The selected release medium intentionally contains no `INIT.L65`, so an
unmodified release boots exactly as before. Hardware acceptance used three
artifact-only media variants over one frozen product pair:

- the absent variant booted normally;
- a valid file established a value of `17` before the first prompt; and
- a type-error file printed `*** vm: type error`, returned immediately to a
  usable prompt, and then evaluated `(list 1 3)` as `(1 3)`.

The host publication-boundary fixture composes external library append over
the final static plane. This prevents startup-library qualification from
silently measuring an uncomposed source or object world.

## Faster empty-journal recovery

The recovery driver formerly transported and verified eight overlays even
when the persistent journal was empty. Its measured lower bound was 17,852
CRC bytes. v1.7 derives the empty condition from all 64 physical C2J bytes and
uses the prepriced A0 fast path, reducing the empty case to two overlays and
6,110 CRC bytes without adding a shadow state bit.

The serial recovery driver is byte-identical on every non-empty or uncertain
path; any read uncertainty fails closed into that unchanged driver. On the
physical MEGA65, the accepted startup type error returned to the prompt
"practically immediately". This is a hardware observation, not a general
latency ceiling.

## Bank-2 and MAP composition

The final Bank-2 product is qualified as one composed ownership map rather
than as independent free-space totals. Eight owners occupy disjoint physical
intervals; capacity is reported as the largest contiguous hole. The two MAP
tenants are anchored downward from the bank end, their VMAs remain unchanged,
and congruence-required gaps and end reserve are named owners rather than
unaccounted padding.

MAP source tuples are derived from the same linker `LOADADDR` authority that
places their bytes. Placement proves the hardware's page-congruence rule
before linking, and qualification proves emitted tuple equality afterward.
The final header extent and every post-link consumer likewise bind the
candidate's generated authority rather than a predecessor snapshot.

These are build and delivery guarantees. They do not expose a new language
surface.

## Retained v1.6 behavior

The optional `v16core` package remains on the library medium. Requiring it
adds insertion-mode cursor navigation to the native one-line REPL: cursor
left/right, `C-b`/`C-f`, `C-a`/`C-e`, backward Delete and `C-d` forward
delete, including harmless endpoint operations and the 250-character
cursor-following viewport.

The verified MAP-CPU boot refill, delivered-byte facade proof, transitive MAP
nesting prohibition, queue single-owner discipline, and retired-overlay
execution backstop with sanitized recovery all remain in force.

## Known limitations and scope

The maintained [Known Issues and Retired Exceptions](../known-issues.md) holds
the complete boundary. In particular, the selected medium does not deliver
the balanced multiline/history Comfort REPL, lossless capture input,
delimiter matching, or cursor blinking. Those development worlds remain
sealed evidence rather than partial product claims.

Enter the Freezer only while the REPL is idle. Fail-closed stops outside the
recovered retired-window class still do not print their cause. Storage and
session metadata remain bounded, and standalone Ship RUN/STOP still lacks
independent `$91` verification.

## Claim boundary

v1.7.0 claims the exact 22-role product/library set above, native `INIT.L65`
absence/valid/error behavior, the observed A0 empty-recovery responsiveness,
the retained v1.6 cursor-navigation and recovery behavior, and the release D5
rows. It does not claim Comfort, lossless capture input, matcher/blink,
Attic writes, a general startup-time ceiling, line-atomic REPL input, or
arbitrary live-session shipping.
