# lisp65 1.8.0 Release Notes

Release date: pending publication

lisp65 1.8.0 is a substrate maintenance release. It ships the qualified native
Capture/Hybrid infrastructure in a deliberately closed state, retains the
native `INIT.L65` hook and fast empty-journal recovery from 1.7, and makes the
delivery boundary visible as `WORKBENCH 1.8.0`.

The Capture ring is present in the final ELF with its tail initialized to
`$FF`; no delivered client arms it. Consequently this release makes no
lossless-input claim and the long-standing fast-typing limitation remains
open. The native-client activation is registered for v1.9.

## Retained native behavior

The release medium contains no `INIT.L65`. If a user supplies one, it is
evaluated once after the resident world is ready and before the banner. An
absent file remains silent; a VM error returns to one usable `lisp65>` prompt.
The A0 empty-journal path retains the hardware-observed, practically immediate
error recovery.

The optional library medium contains `v16core`. Its `(read-line)` function
provides insertion-mode cursor navigation. The surrounding bare native
`lisp65>` prompt still uses the minimal C line collector: Cursor Left/Right are
not editing commands there and visibly produce `*** reader: invalid token`.
Host replay of both the v1.7 and v1.8 final ELFs proves that this is a
pre-existing boundary, not a v1.8 regression. See
[Known Issues and Retired Exceptions](../known-issues.md).

## Closed Capture substrate

The final product contains the native Capture owner, scalar Hybrid consumer,
PETSCII normalization and queue-single-owner guard. Qualification on the final
ELF re-proved the 94/94 laboratory loss wall, zero drops, 512/512 normalization
parity and 29.358% responsiveness margin. These are substrate qualification
facts, not an activation or user-facing losslessness promise.

Comfort, the delimiter matcher/blinking cursor work and the native Capture
client are absent. The product starts with the Capture lifecycle closed.

## Claim boundary

v1.8.0 claims the exact 22-role product/library set above, the visible 1.8.0
banner, retained 1.7 native behavior and a qualified but closed Capture/Hybrid
substrate. It does not claim Capture activation, lossless user input, Comfort,
delimiter matching, cursor blinking, or Cursor Left/Right editing at the bare
native `lisp65>` prompt.
