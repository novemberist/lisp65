# lisp65 1.2.0 Release Notes

Release date: 2026-07-27

lisp65 1.2.0 replaces the 1.1 compiler-reload execution path with C2-lite, a
hardware-validated Chip-RAM execution foundation. The release keeps Dialect V2
and deliberately stays narrow: it delivers the runtime foundation, latency
cure, input ownership, and recovery work that completed the C2.2 acceptance
chain. Later language and library freight remains later work.

## Definition-to-call latency cure

The dated 1.1 latency exception is retired.

- On the reference MEGA65, the bound Link-66 acceptance run measured the first
  call of a newly published nullary function at **1 frame** and the immediately
  following warm call at **0 frames**.
- The final G5 repeat measured **0 frames** for both calls.
- The release claims the predeclared ceilings, not zero-time execution:
  first call at or below 16 frames and warm call at or below 10 frames.
- The 1.1 baseline was 95--98 frames for the first call and 10 frames warm.

The cure is a direct-call path for published nullary functions. Calls with
arguments are not covered by that performance claim; the final hardware run
recorded 68 frames for the informative `(f 1)` case with no limit attached.

## C2-lite execution foundation

- Static bytecode and native runtime families are staged into dedicated
  Chip-RAM planes before publication. Target CRCs, generation binding, and
  publish-last ordering make READY an evidence-backed state.
- Runtime execution no longer depends on an Attic read/refill path. Attic
  remains a cold staging source; consumers execute from verified Chip RAM.
- C2D-v6 provides one emission format for static and dynamic entries, strict
  root-surrogate classification, transient high-edge handles, and
  generation-bound lookup.
- L65R-v4 supplies region-qualified runtime records. A bounded second session
  region carries cold rollback freight without weakening the 64-KiB primary
  store.
- A cold boot detects and repairs deliberately damaged Chip-RAM staging before
  publishing the session.

## Native post-boot ownership and L-full input

After cold staging, lisp65 takes ownership of the post-boot machine context:

- the KERNAL mapping is removed from the product-owned execution closure;
- native input, output, frame accounting, RUN/STOP, and Freezer return use
  explicit product contracts;
- the generated L-full keymap is wired end to end, including physical
  `C-Space`, `M-x`, and `C-x C-c`;
- RUN/STOP aborts evaluation and returns to a usable REPL.

Cold boot and hardware reset still begin in the firmware-owned environment.

## Transactional definitions and recovery

- Persistent and transient appends use one journaled, publish-last path.
- Normal completion and RUN/STOP abort restore the C2D counters and suffix
  byte-for-byte; the final hardware acceptance compared the complete affected
  C2D region before and after abort.
- Nested evaluation returns without directory growth.
- A failed append rolls back to a usable REPL rather than leaving a half-
  published definition.
- Undefined-function errors preserve the inner lookup identity and render a
  symbol name when one is available, for example
  `*** vm: undefined function: name`.

## Upgrade notes from 1.1.0

- Use the same BASIC-first, one-drive workflow, but allow roughly 27 seconds
  for the staging-heavy cold boot on the reference setup. The recorded
  27.653-second value was an upper bound to a captured screen, not a boot-time
  guarantee.
- Load IDE, optional IDEX, and M65D while `L65SYS` is mounted, then swap to the
  work disk.
- Use the generated 1.2 keymap. `C-Space` sets the mark, `M-x` opens the
  command launcher, `C-x C-c` leaves the editor, and F3 returns from the
  Freezer.
- Existing 1.1 source modules remain Dialect V2 source. Runtime records and
  internal C2 metadata are product formats and are not a user interchange
  promise.

## Known limitations

- Open the Freezer only while the REPL prompt is visible or evaluation is
  otherwise idle. Freezer entry during a persistent definition or append is
  not supported in C2.2. Return with F3, then cold-restart lisp65 before
  relying on the interrupted definition. This crossing is explicitly deferred
  to C2.3 and is not claimed by the 1.2 acceptance seal.
- The published nullary-call latency cure does not generalize yet to calls
  with arguments. The final G5 run recorded 68 frames for an informative
  one-argument call, with no release limit.
- The final G5 GC envelope recorded 89 frames for one collection and 96
  contract block reads. It is an informative measurement, not a latency limit.
- There is no dependency-safe `unload` or product-local `restart-repl`.
- The compiler produces Workbench modules, not standalone runtimes or bootable
  application disks.
- Editor buffers remain fixed-capacity and there is no undo/redo, interactive
  completion, integrated help, or full structural editing.
- M65D/editor saves support 1--8,192 bytes. Evaluator `load` retains its
  separate 38,400-byte staging ceiling.
- Xemu remains a logic prefilter. Timing, Freezer, F011, SD-buffer, reset, and
  media-swap claims require physical hardware.

The maintained list, including the formal retirement of the 1.1 latency
exception, is in [Known Issues and Retired Exceptions](../known-issues.md).
