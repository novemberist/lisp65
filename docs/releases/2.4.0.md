# WORKBENCH 2.4.0


This is a product release. The qualified product still displays
`WORKBENCH 2.0.0` in its boot banner; the package version is 2.4.0.

The release candidate is the nested-error recovery Final: runtime ELF
`66165507a8e5ad1d857afdd967f9056be2ce7bbccc332d5328e981398078b47b`,
product D81 `87cb0f6ea9b2dc690f66ee11d9c76d5138e11f28452254a9b5730c78cabc5f5d`.
Its device rows were run on one physical MEGA65 on 2026-09-24 by automated
virtual-keyboard input (see [device evidence](#device-evidence)). Cycle and
second figures marked *emulator* are Xemu measurements at 40.5 MHz, not
device timings. Device timings marked *tool clock* come from the host tool's
clock around screen polls; they are not stopwatch readings.

## Included

- Faster cold start. On the release-candidate medium, RUN to
  `Initializing...` took 21.0 s and RUN to the prompt 32.7 s (tool clock).
  Earlier in this cycle, on a development world, the same boot took about
  50 s by the owner's stopwatch. On the emulator, stager entry to banner
  return is about 31.3 s. Most of the saving comes from a table-driven
  CRC32 in the boot stager, a boot-time name index and export publication
  over that index.
- Startup message. The blue start phase now shows `Initializing...` until the
  banner is ready; the banner and the prompt are unchanged.
- Faster `require`. The package index checksum is computed natively instead
  of in Lisp. Each of the five packages loads at least 11.24 s faster
  (emulator); before, a `require` took 18–22 s on the emulator. Truncated
  index records are refused natively.
- Faster `defstruct`. A five-slot `defstruct` now publishes its 18 generated
  definitions as one code image instead of 18. It fell from 31.21 s to
  16.84 s (emulator).
- Faster REPL typing. The cost per typed key at the native prompt fell by
  about 38 % (0.617× single-key cycles against the preceding development
  world of this cycle, emulator).
- Larger symbol table. It holds 1,008 symbols, up from 795. The name pool
  moved to the top of bank 1. On the device, three five-slot structures took
  the session from 761 to 822 symbols, with every accessor returning 42.
- Clean refusal at the code-image capacity. A definition group that no
  longer fits the 64-image directory is refused with `*** VM: OUT OF MEMORY`.
  The prompt stays live and earlier definitions keep working. This also
  holds for a definition loop running inside a form: from 15 images,
  `(dotimes (n 60) (eval '(defun capn () 7)))` stopped at 63/64 images with
  `*** VM: OUT OF MEMORY`, and `(capn)` then returned 7 (device).
- `compile-string` works again. After 2.3.0, a positive `compile-string`
  was found to fail on the development world, because the delivered compiler
  called a missing private function (`%c2-control`); no claim is made about
  which public release first acquired this inherited defect. 2.4.0 repairs
  that bridge and the relocation of anonymous helpers in later definitions. Compile, save, reload and call
  returned 7 on the host and on a physical development world. The
  persistence row on this release candidate's medium was not run (see
  [not verified on the device](#not-verified-on-the-device)).
- Two defects shipped in 2.3.0 are fixed. See
  [Known Issues](../known-issues.md) for both entries.
  - A `defun` published from inside a running form, for example
    `(dotimes (n 1) (eval '(defun f1 () 7)))`, was silently destroyed; the
    next call failed with `VM: BAD BYTECODE`. The temporary-code cleanup now
    wipes only the retiring image's own code. On the device, `(f1)` returned 7.
  - An error raised through `eval` inside a running form, for example
    `(let ((q 1)) (eval '(capzz)))`, left the REPL without a prompt until a
    reset. Recovery now retires the form's temporary code exactly as a
    normal form does. On the device the exact
    `*** UNDEFINED FUNCTION: CAPZZ` appeared at a live prompt, and
    `(+ 4 5)` then returned 9.

## Measured boundaries

Reserves at the nested-error recovery Final, measured on the host: ordinary
text 1,209 bytes free against a floor of 32; E000 146 against 54; capture
136 against 57; high BSS 10 against 5. Session region 0 / 1 / 2 have 1,351 /
140 / 872 bytes free; the unique overlay catalog uses 63 of 64 slots.
Source: `docs/planning/nested-error-recovery-final-report.md`.

Named costs accepted in this cycle are recorded in the card reports. The
last one is a garbage-collection placement cost of +2,905 cycles per
natural collection (about 0.05 % of a collection, emulator). It is
attributed to ten branch sites that moved across a page boundary; the
collector code is unchanged.

These are host and emulator measurements. They are not a typing-feel or
wall-clock claim.

## Device evidence

On 2026-09-24 the release candidate medium was uploaded as a new SD file
and read back byte-identical. Every row was driven automatically; the owner
was not at the machine.

- Boot to a settled prompt with the emulator's banner (times above).
- `(+ 4 5)` → 9, `(setf (car (list 1 2)) 9)` → 9, `(capitalize "abc")` →
  `"Abc"`, `(require "inspect")` → t, `(who-calls 'no-such)` → nil,
  `(require "buffer")` → t, `(buffer-length (make-buffer 3))` → 3,
  `(require "defstruct")` → t and `(load-lib "ide")` → t.
- `M-x`, then 17 characters typed with a 250 ms pause between keys: complete
  and in order; `C-g` restored the status row. A 17-character REPL line was
  read back in full and returned 28. This is automated virtual-keyboard
  input, not a physical-keyboard fidelity witness.
- The storage, retained-callable, nested-error and over-cap rows described
  above; the lambda row gave the exact `*** VM: BAD BYTECODE` with a live
  prompt.
- A normal reset of the still-mounted medium auto-booted to a settled idle
  prompt with 8/64 images.

Rows D (symbol count) and G (image count) were checked against expectations
recalibrated on the emulator and the host gate; the device numbers match
them exactly. The full record is
`docs/planning/release-candidate-device-report-2026-09-24.md`.

### Not verified on the device

These rows need the owner at the machine and were not run on this medium:

- RUN/STOP inside a running form;
- a cold power cycle, and the stopwatch feel of boot and typing;
- the physical `C-x C-c` exit from the IDE. The virtual keyboard cannot
  deliver `C-c`: the product drains key-queue code `$03`;
- compile, save, reload and call on a writable copy of the medium;
- the end-of-session SD readback of the uploaded files.

## Not included and remaining limitations

No Comfort, code-object cache, Matcher/Blink or Tier-2 promotion is claimed.

- An anonymous `lambda` at the top level, outside a `defun` body, is refused
  with `VM: BAD BYTECODE`. Lambdas inside `defun` bodies, and closures
  returned from them, work.
- Code-image slots are not reused. A redefinition still consumes an image,
  and the directory holds 64 images per session.
- `require` inside a temporary compiled form, such as
  `(time (require "inspect"))`, is refused deliberately: it returns `nil`
  without loading. Use plain `require`.

The 12-argument call/apply bound and the 16-frame soft-stack capacity are
unchanged. Read the [Known Issues](../known-issues.md) before use.
