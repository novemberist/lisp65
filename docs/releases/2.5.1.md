# lisp65 2.5.1 — IDE exit, faster editing and multi-line strings

2.5.1 includes C-x q IDE exit, the small Backspace tail change, editor list
walk reductions and the Comfort multi-line string repair. The public product
is the STRINGS Final (`build/strings-final-r1`), D81 SHA-256
`9978daa146b89cf71ad1d3f290d80cf74b197911e7854859f9e4aa9bb2fce441`.
The Backspace-targeted preparation remains historical. Owner authorization
covers the full chain including Ship/Publish; reviewer sealing and the owner
device session remain release steps.

## Editing and measured typing latency

Use **C-x q** to exit the IDE with buffers preserved; release Ctrl before q.
Plain q inserts text. Physical `C-x C-c` does not reach the IDE and remains
a known issue. RUN/STOP leaves with the buffer kept.

Typing latency in the **MEASURED native lane** falls from **3.24 M -> 1.58 M
cycles/key** (approximately **80 -> 39 ms** at 40.5 MHz). This is the native
lane measurement for the editor list-walk change, not a physical-device
stopwatch result. Backspace code-object reads fall from roughly
**1,200–1,800 -> 53 reads/key** in the projected lane; device feel is pending
the owner session. See the walks Final report in the proof bundle.

The earlier small Backspace tail change reuses the existing list tail at
both prompts. Host VM instructions fell by −7/−19/−26 % at 10/40/70 chars.
Its historical BS251.D81 device session passed after a power cycle, but the
owner found that earlier change barely noticeable. That feedback predates
the editor list-walk reduction and does not characterize the Strings Final.
Emulator settle-window timings are not key-processing latency.

## Comfort multi-line strings fixed

Comfort multi-line strings now evaluate and display correctly. For example,
type `(print "hello`, press Return, then type five spaces followed by
`world")` and press Return. 2.5.1 preserves those five spaces, carries string
and escape state across lines, and displays accepted continuation lines
before the result. It adds no automatic indentation inside an open string;
ordinary depth-based indentation resumes outside strings.

In 2.5.0 this example never evaluated normally; the recorded workaround was
a line containing only `)`. This known issue and workaround are superseded
by the 2.5.1 fix. Host semantic/framebuffer checks and 72/72 retained emulator
rows passed; they do not close physical device or stopwatch rows.

## Remaining editing and device rows

- Continuation lines are not editable after Return.
- Up/Down always walk history; they do not navigate pending multi-line input.
  The multi-line editing card follows this release work.
- Physical C-x C-c remains unavailable; physical C-x q and RUN/STOP need
  owner confirmation. Predecessor virtual-keyboard passes remain separate.
- Stopwatch cold boot, current-product physical keys and typing/Backspace
  feel remain pending the owner session on the Strings Final.

Boot a freshly uploaded medium under a new name after a power cycle. The
Backspace Final device PASS is historical evidence for its own D81, not
physical acceptance of the Strings Final.

## Inherited behavior and limits

The product starts in Comfort at `l65>`: balanced multiline input, indentation,
parenthesis tracking and ten-line history. Errors and RUN/STOP preserve
definitions and history. An empty line leaves to `lisp65>`; `(repl)` re-arms
Comfort. The library occupies 1,060 Bank-2 bytes.

The owner accepted the named Comfort GC cost: +8 symbols, +105 name bytes,
+1 code image, +7 C2D entries/roots and five more boot collections; after exit,
+12 live cells and +2.1% matched forced-collection cycles (natural cycles −1.7%).
Boot was +7.65 s over 2.4.0 in the emulator; the 2.5.0 automated device session
reported 40.4 s to the prompt, about +6.7 s, on a host tool clock. These are
not stopwatch measurements, hardware pause guarantees or new 2.5.1 timings.

Set B and Card L remain outside this release. Top-level anonymous lambdas
outside defun remain refused; code-image slots are not reused; calls have a
12-argument bound; absent require prints LOADING before NIL. Physical C-x C-c,
stopwatch cold boot and physical key/typing rows remain open.
