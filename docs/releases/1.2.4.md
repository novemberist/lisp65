# lisp65 1.2.4 Release Notes

Release date: 2026-07-30

lisp65 1.2.4 adds fixed-point arithmetic and on-device timing to the base
composition. A sprite can now move by a fraction of a pixel without loading a
library:

```lisp
(setq x (int->fx 100))
(setq v (fx 0 32))              ; 0.25 pixels per step
(setq x (fx+ x v))
(fx->int x)                     ; whole pixel for drawing
```

Four steps accumulate to exactly one pixel. The value remains an ordinary
fixnum, so it can be stored, passed and compared like every other number.

## Fixed-point arithmetic

The new `fx`, `int->fx`, `fx->int`, `fx+`, `fx-`, `fx*`, `fx/` and
`fx->string` functions use signed Q8.7 values: seven fractional bits over the
existing fixnum representation, with no new type and no library load.

- Range: `-128.0` through `127.9921875`.
- Resolution: `0.0078125` (1/128).
- Multiplication and division round to nearest; exact halves round away from
  zero.
- Overflow and division by zero raise the normal arithmetic error instead of
  wrapping or saturating.
- `fx->string` renders every value exactly and always includes a fractional
  digit.

The device smoke covered multiplication, division and the exact-half result
`0.0078125`. The implementation uses the MEGA65 math unit through the existing
byte-I/O surface. It adds 1,451 Bank-2 bytes and no resident code, state, roots,
native primitives or overlay records.

## Measuring a form

`(time form)` evaluates `form` exactly once, prints its elapsed raster-frame
count and returns the value unchanged:

```lisp
(time (random 100))
```

The accepted hardware session measured the product-owned counter at
**51.966 Hz**, within the preregistered 48–52 Hz band. Durations through
16,383 frames are reported; 16,384 frames or more fail with a named duration
overflow rather than silently wrapping. `(time)` adds 282 Bank-2 bytes and no
resident or native dependency.

## Known issues

The maintained [Known Issues and Retired Exceptions](../known-issues.md)
contains the complete user-facing boundary. In particular:

- enter the Freezer only while the evaluator is idle;
- do not use interrupt-generating cartridges while lisp65 is running;
- preserve the exact workload if the intermittent post-GC out-of-memory
  symptom returns;
- if `require` unexpectedly returns `nil`, cold-restart lisp65 and retry once;
  and
- `defstruct`, dynamic package freight, `gc`, `room`, `error` and
  `restart-repl` are not delivered.

The intermittent observations are carried forward unchanged. No cause or fix
for either is claimed by this release.

## Claim boundary

v1.2.4 claims the exact sealed C2-lite product and hardware results above.
The `fx` arithmetic and 51.966 Hz `(time)` calibration are device
measurements. It does not claim Freezer safety during an active persistent
definition, interrupt-generating cartridge support, cryptographic randomness,
a GC latency ceiling, `defstruct`, dependency-safe unload, a general condition
system, a tick callback, color-RAM scrolling or C2-full transport safety.

The current-core L10 remeasurement remained delayed: at 2 ms, 1,132 of 1,156
bytes differed; from 714 ms onward the capture was exact. That diagnostic keeps
the C2-full gate closed and is not a C2-lite regression claim.
