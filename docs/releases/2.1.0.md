# WORKBENCH 2.1.0

This is a product release of the qualified renderer world, not a documentation-only
update. The bundled documentation and archive directory are versioned 2.1.0.
The unchanged, device-tested product still displays the banner `WORKBENCH 2.0.0`.

## Source-package correction

The 2.0.1 source archive inherited private absolute path metadata and a prebuilt
host shared library. The 2.1.0 source package corrects this packaging defect:
path metadata is repository-relative, and the host entry emitter is built from
the included source. The export check covers the complete source population,
including declared binary inputs, rather than only a selected subtree. Existing
releases are unchanged. This correction does not change the qualified product
bytes.

The new source snapshot also applies the curated export exclusions to historical
proof records and compiled evidence artifacts. The retained serialized Plane,
library inputs and binary test fixtures are explicitly declared, with identities,
source provenance and their consumers. Reproducing the product consumes these
frozen inputs byte-identically; it does not claim to regenerate them from Lisp.

## Accepted changes

- Buffered F011 reads use the core's actual completion semantics. Spin-up is
  followed immediately by READ; completion waiting is bounded. Read failures
  propagate as `LOAD_OPEN` instead of being mistaken for a missing library.
- The renderer and MAP-reader assembly no longer use the incorrectly encoded
  relaxed 16-bit branches. A permanent gate rejects PCRel16 instructions in the
  executable population. The renderer's null-context failure and the MAP
  reader's forced failure path have executed regression tests.
- The Known Issues document describes the remaining hardware-stack limitation
  and correctly identifies the proposed protections as future work.

## Device acceptance and measured capacity

The accepted session used variant B: power-off, followed by Freezer mounting and
product start after power-on. It does not establish automatic boot from an SD
image already mounted at power-on. The four native performance smokes returned
`0 2`, `0 (9 2)`, `0 98`, and `1 42`.

The terminal RAM measurement, in the session configuration before the destructive
recursion test, left **107 symbol slots and 1,467 name bytes** free. The required
floors are 32 slots and 384 bytes. This is a measured value, not a projection.

## Not included and remaining limitations

Comfort, its trampoline, and the hardware-stack floor are **not included**.
Neither are the deferred wrap-safe selector hardening, Matcher/Blink, or Tier 2.
The native editor remains the selected input path; this release does not claim a
new typing-latency improvement.

For the documented non-tail recursion example, depth 12 returned 12 and depth 13
entered the repeated `E29` failure; the owner then reset to BASIC. This is a
reproduction of a Known Issue, not successful recovery. The example does not
define a universally safe recursion depth. Deep printer nesting remains covered
by host evidence, not by a new device claim. See [Known Issues](../known-issues.md).

The full source check has the explicitly accepted historical Carrier-SHA-pin
exception; it is not reported as an unconditional Exit 0. The separately accepted
`check-host` residual inventory is not claimed to have been repaired by this
release.
