# WORKBENCH 2.3.0


This is a product release. The qualified product still displays
`WORKBENCH 2.0.0` in its boot banner; the package version is 2.3.0.

Unless a sentence says otherwise, the behavioural results below were accepted
on a physical MEGA65. Cycle figures are Xemu emulator cycles at 40.5 MHz and
are never device wall-clock timings.

## Included

- Default library loading from `INIT.L65`. The product disk ships an
  `INIT.L65` containing `(require "place")` and `(require "string-extra")`.
  Both packages load at boot without any loading text: neither the loader's
  `LOADING` progress line nor `require`'s own `loading <name>...` echo
  appears, and the banner renders exactly as it does without an `INIT.L65`.
  An interactive `(require ...)` at the prompt keeps its `loading <name>...`
  echo. `buffer`, `inspect` and `defstruct` continue to load by hand.
- `require` accepts a string as well as a quoted symbol, and returns `nil`
  for a missing package. A nested `load` from a loading source is refused
  cleanly, without corrupting the loader's sector scratch; `require` inside
  `INIT.L65` is supported and supplies the default loading described above.
  A library name longer than 16 characters is refused.
- Case-insensitive library names for `load-lib` and `require`. On the device
  both `(load-lib "IDE")` and `(load-lib "ide")` returned `t`. A library file
  that the loader refuses — wrong format, or larger than the 8,192-byte
  envelope — now returns `nil` and leaves the running world and the prompt
  intact. The 2.2.0 defect in which an uppercase name fell into an
  incompatible disk path and left the REPL in an endless
  `vm: undefined function` loop is fixed. It was never a Known Issues entry.
- Minibuffer rework. The open path no longer rebuilds the buffer area.
  Opening `M-x` and Find-file went from about 278 M cycles (≈ 6.9 s) in
  2.2.0 to about 21 M cycles (≈ 0.5 s); 16 typed keys went from 171.7 M
  cycles (≈ 4.2 s) to 49.5 M cycles (≈ 1.2 s). Every key is at or below its
  2.2.0 cost, per-key work is O(1) in input length, and the whole pending key
  queue is drained before one render.
- Prompt-only minibuffer frame. While the minibuffer is active the bottom row
  shows only the prompt and the input — `M-x [find-file]`, `Find file:
  [scratch]`, `Goto line: ` — with no buffer name, modified mark or symbol
  counter. The status row returns on exit or cancel.
- The interactive Ship sample is buildable again from the product sources,
  through a standalone editor variant over the public input interface. On the
  device the standalone sample boots to a blue screen, accepts `alex` and
  Return, and prints `Hello, alex!`.
- The native prompt moves up on wrapped lines: when input wraps, `lisp65>`
  stays beside the start of the input on the upper row. Shrinking back across
  the wrap boundary moves the prompt down and leaves the released upper row
  empty.
- Delivery cleanup. The obsolete disk images `IDE`, `IDEX` and `M65D` are
  removed from the product D81, reclaiming 193 blocks and reducing the medium
  from 22 to 19 files. Their static implementations and the `load-lib` routes
  remain. `BUFFER` stays as the 398-byte L65S package read by
  `(require "buffer")`. The cold-start descriptor and the stager use one
  derived ten-role population; the physical cold start from the new medium
  through the ten-role stager was device-accepted.

## Measured boundaries

On the device, 17 rapidly typed characters appeared complete and in order in
the minibuffer. That is a witness for that sequence, not a general zero-loss
guarantee. `C-g` restored the status row, re-entry showed empty input, and a
missing file name reported `source missing` and returned the cursor to the
buffer.

The named cost of the prompt-only frame is the equal-state garbage collection:
37,665 cycles more per collection, about 0.93 ms. It is attributed to heap
layout — nine live cons cells moved from the local to the external heap — with
the collector code unchanged. This is an emulator measurement, not a
worst-case pause guarantee.

With the IDE and all five packages loaded, the symbol reserve is exactly
32 free symbols and 387 free name bytes, against the 32/384 floor. These
independent resources cannot be assumed to be exhaustible simultaneously.

Reserves at the INIT-Echo final, measured on host/emulator: ordinary text 2,294 bytes
free against a floor of 32; E000 345 against 54; capture 335 against 57; low
BSS 166 and high BSS 22 against 5; session carrier 64,558 of 65,536. Both VM
lanes are 1.0000×. Against the immediate predecessor, the native prompt lanes
read **1.024× / 1.115× raw over all samples**, with the accepted phase
attribution (five collections in each world, one moved from boot into typing
by 39 fewer startup allocations, per-key work within the bound), and
**1.005× / 1.010× in the same-phase reading**.
Source for these reserves and both lane readings:
`docs/planning/init-echo-final-report.md`, included unchanged in the release
bundle as `proof/init-echo-final-report.md`.
These are host and emulator measurements, not a typing-feel or wall-clock claim.

The final ELF is byte-identical to its seed. The Lisp runtime is unchanged
between the frame card and the delivery card.

## Not included and remaining limitations

No Comfort, code-object cache, Matcher/Blink, or Tier-2 promotion is claimed.
The storage-owner rework is planned for the next release and is not shipped
here.

The 12-argument call/apply bound and the 16-frame soft-stack capacity are
unchanged. The compiler's measured self-compile peak still exceeds the
16-frame product capacity, so deep forms may be refused; printer recursion
remains a separate native-stack limitation. Read the Known Issues before use.

D2, the refused-envelope recovery, is host/emulator-proven. It was not re-run
on the device. No device wall-clock timing is claimed anywhere in this
release.
