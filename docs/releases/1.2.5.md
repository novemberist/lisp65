# lisp65 1.2.5 Release Notes

Release date: 2026-07-31

lisp65 1.2.5 is a focused correctness release for `require`.

In v1.2.3 and v1.2.4, calling `require` after an ordinary persistent
definition deterministically returned `nil`, even with valid package media
mounted. The resolver's world proof required every persistent Session row to
appear in the package index. Ordinary definitions are valid Session rows, but
they are not package-index entries, so validation stopped before any package
load began.

v1.2.5 keeps the C2D-v6 format unchanged. It checks source kind, source slot,
generation, base address and authenticated size for every persistent row.
Package size and combined-identity checks apply only when a row matches an
L65INDEX entry. A geometrically valid row that does not match the index is an
ordinary Session definition and no longer invalidates the package world.

The correction adds 19 Bank-2 bytes and no resident code, roots, native
primitives, state or overlay records. All closed memory walls are unchanged.

## User-visible result

This sequence now works:

```lisp
(defun %ra (x) x)
(defun %rb (x) (+ x 1))
(require 'place)
(require 'place)
```

Both `require` calls return `t`. The second call remains idempotent and does
not reload the package. The former workaround—cold-restart and run every
`require` before defining anything—is withdrawn.

This correction does not deliver `defstruct` or other parked dynamic-package
freight. The accepted product continues to display `WORKBENCH 1.2.4` in its
banner; v1.2.5 identifies the correction-release package and its sealed
artifacts.

## Known issues

The maintained [Known Issues and Retired Exceptions](../known-issues.md)
contains the complete user-facing boundary. In particular:

- enter the Freezer only while the evaluator is idle;
- do not use interrupt-generating cartridges while lisp65 is running;
- preserve the exact workload if the intermittent post-GC out-of-memory
  symptom returns; and
- `defstruct`, dynamic package freight, `gc`, `room`, `error` and
  `restart-repl` are not delivered.

The old `require` ordering issue is retired by this release.

## Claim boundary

v1.2.5 claims the exact sealed C2-lite product and hardware results above. It
does not claim Freezer safety during an active persistent definition,
interrupt-generating cartridge support, a GC latency ceiling, `defstruct`,
dependency-safe unload, a general condition system, a tick callback,
color-RAM scrolling or C2-full transport safety.
