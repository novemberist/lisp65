# lisp65 1.9.0 Release Notes

Release date: 2026-08-30

lisp65 1.9.0 completes the native input path. The `lisp65>` prompt now owns
the insertion-mode Lisp line editor, and the native Capture/Hybrid ring is
armed while that editor reads. On physical hardware, all four counters agreed
at 136 events while a fixed input sequence crossed a forced collection:
`raw = seen = stored = taken = 136`.

This retires two long-standing limitations at once: ordinary input is no
longer lost during collection, and Cursor Left/Right edit the active native
prompt instead of producing `*** reader: invalid token`.

## Native prompt editor

Prompt, editable input and cursor share one editor-owned screen line. Cursor
Left/Right, insertion and deletion work directly at `lisp65>`; explicit
`(read-line)` uses the same framebuffer and input semantics. The editor is
resident product freight, so no `v16core` load or optional library disk is
needed.

The product medium also contains IDE, IDEX and M65D. The release package ships
one product D81 and one blank work D81.

## Lossless input boundary

The capture IRQ is the sole owner of ordinary keyboard-queue events while
`read-line` is active, and the delivered consumer takes those events from the
ring. Qualification re-proved the 94/94 host wall, zero drops, 512/512
normalization parity and 29.272% responsiveness margin on the final client
world. The device test then proved the armed lifecycle and consumer together
with the four equal nonzero counters above.

The claim is deliberately narrower than universal type-ahead: keystrokes
entered while Lisp evaluation is running remain outside the release claim.

## Retained native behavior

The once-per-boot `INIT.L65` hook and A0 empty-journal recovery remain as in
1.7. An absent INIT file is silent; an INIT or VM error returns to one usable
prompt. The product medium intentionally contains no `INIT.L65`.

Comfort, balanced multiline input/history, delimiter matching, cursor blink,
the unresolved `$22` mechanism and the domain findings are not delivered.

## Claim boundary

v1.9.0 claims lossless native-prompt input across a forced collection, the
native prompt editor, the exact 19-role product set above, and retained
INIT/A0 behavior. It does not claim type-ahead during evaluation, Comfort,
balanced multiline input/history, delimiter matching, cursor blinking, the
`$22` mechanism or the parked domain findings.
