# lisp65 1.4.0 Release Notes

Release date: 2026-08-09

lisp65 1.4.0 makes persistent compilation materially cheaper and adds three
small, explicitly loaded tools without growing the resident core. The visible
Workbench banner is `WORKBENCH 1.4.0`.

## Persistent-path performance

The compiler carrier now keeps definitions and their consumers closer in the
external code image. Against the reconstructed `defstruct` workload, the
change reduces window events by about one fifth, shrinks the external image by
336 bytes, and lowers the structural full-sequence price from 788 to 677
seconds. The post-require definition price is 179 seconds.

Those values are structural prices, not completion upper bounds. The hardware
delivery row for `defstruct` reached a red fail-closed frame within its quiet
180-second window, so `defstruct` is not shipped in this release.

## Optional libraries

The selected Base library D81 contains two independent packages:

- `(require 'string-extra)` publishes `capitalize` and `string-split`;
- `(require 'inspect)` publishes `who-calls`, generated from the exact compiled
  shelf call graph.

Mount `media/lisp65-library.d81`, remount through M65D when necessary, and
require only the package needed by the session. The hardware session exercised
all three public names.

`trace` and `untrace` are not delivered. Correct `untrace` needs the exact old
function-cell value, which the Link-92 core ABI cannot expose. The restart
contract requires that getter (or equivalent journal old-value exposure) and
atomic wrapper publication/restoration before tracing can become public.

## Editor evidence corrected

The low-allocation renderer remains. A prior virtual-input row persisted only
56 of 64 requested keys, but the v1.4 device session persisted 64 of 64
physical keystrokes with no observation during the active window. The current
product boundary therefore makes no editor-stall claim from the virtual result.

## Acceptance boundary

The accepted candidate uses one product core and the Halt-#1-selected Base
library medium. The selection did not rebuild either variant.

- resident PRG SHA-256:
  `fcc785365d2a6d7a3269367a4234cb372783d46b9debdee6ad37e758f6e20a52`;
- selected Base library D81 SHA-256:
  `1a77a2f5d71c58ef8e9650316d7d0103675fd419b5aa96d37e8f44e7b24186b7`;
- remaining Bank-2 capacity after the selected freight: 14,270 bytes;
- resident freight delta: 0 bytes.

On physical MEGA65 hardware, the candidate booted to the `WORKBENCH 1.4.0`
banner and REPL, passed Q8.7, `(time ...)`, base-string and optional-library
smokes, and persisted the physical editor row 64/64. The `defstruct` row was a
delivery red only: it establishes neither an infinite hang nor an inner
failure mechanism.

The release bundle is self-verifying. Its manifest binds the exact product,
selected library medium, documentation and accepted device receipts. The
public clean-build receipt records varied fresh-checkout reproduction; private
acceptance evidence is not a public build input.

## Known issues

The maintained [Known Issues and Retired Exceptions](../known-issues.md)
contains the complete boundary. In particular, `defstruct`, `trace`, and
`untrace` are absent; Freezer entry during persistent publication remains
unsupported; standalone Ship RUN/STOP still lacks an independent `$91`
verification; and fail-closed stops do not yet print their cause.

## Claim boundary

v1.4.0 claims the exact selected Base candidate, its three optional library
names, the locality/performance transformation, and the hardware rows above.
It does not claim `defstruct`, function tracing, a completion-time ceiling,
arbitrary live-session shipping, active-persistence Freezer safety, or any
parked parity/ownership feature.
