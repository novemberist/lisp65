# lisp65 1.2.1 Release Notes

Release date: 2026-07-29

lisp65 1.2.1 is the first feature update on the C2-lite foundation. It adds a
native `while` form and a base-composition pseudo-random number generator,
extends the direct-call latency cure to published functions with arguments,
hardens interrupt ownership, and makes repeated `require` resolution much
cheaper. Dialect V2 and the v1.2 media model are unchanged.

## `while`

Dialect V2 now provides:

```lisp
(while test form*)
```

`test` is evaluated before each iteration. `nil` stops the loop; any other
value runs the body from left to right. Body values are discarded, an empty
body is legal, and normal termination returns `nil`.

`while` is a native compiler special form in all four shipped execution views.
It uses the existing relative branch bytecodes and introduces no new VM
opcode, root, journal field, or resident runtime state.

There is one MEGA65-specific performance property worth knowing. Code is
executed through a 128-byte window. If a loop's backward jump crosses that
window boundary, each iteration reloads the target window. The acceptance
fixture measured one such refill per admitted iteration. Keep tight loops
small, or put the loop in a small helper function, when refill cost matters.
This affects speed, not loop semantics.

## `random`

The base composition now includes:

```lisp
(random n)
(random-seed seed)
```

`random` accepts a positive fixnum `n` and returns a value from zero through
`n - 1`. Rejection sampling avoids modulo bias. The generator is an additive
lagged-Fibonacci generator with lags 24 and 55 and a 55-value Lisp state; it
adds no native state or resident code.

Call `(random-seed seed)` for reproducible sequences. If no seed was supplied,
the first use derives one from read-only MEGA65 timer state and human input
timing. This is suitable for games and simulations, not cryptography.

## Published calls with arguments

The C2-lite direct-call path now covers published functions with fixed
arguments as well as nullary functions. The fresh v1.2.1 G5 run measured:

- newly published nullary call: **0 frames**;
- immediately repeated nullary call: **0 frames**;
- informative one-argument call: **0 frames**.

The established nullary release ceilings remain 16 frames cold and 10 frames
warm. The one-argument value is a measurement, not a new hard limit. It
replaces the 68-frame informative position published with v1.2.0.

## Interrupt ownership

Before enabling its owned raster interrupt, lisp65 now disables the internal
Ethernet, Auto-IEC, and audio-DMA interrupt enables in addition to the sources
already covered by v1.2.0. Hardware readback confirmed all three new masks as
zero after boot.

Interrupt-generating expansion cartridges remain outside the supported
hardware profile because the product has no device-independent way to mask or
acknowledge them. Passive cartridges are unaffected. See
[Known Issues](../known-issues.md).

## Faster repeated `require`

An already-loaded, generation-matching library is now recognized before its
full description is parsed again. Against the same host workload, the repeat
path used **97.96% fewer VM steps** and **93.23% fewer C2D byte reads**.
Identity, generation, and resolution-lock mismatches still take the complete
checked path.

This update does not ship `defstruct` or make the parked dynamic-library
freight part of the release surface.

## Known issues

The maintained [Known Issues and Retired Exceptions](../known-issues.md)
contains the full user-facing boundary. New or newly visible in v1.2.1:

- interrupt-generating cartridges can drive the product into its deliberate
  red fail-closed screen;
- one post-GC out-of-memory event was observed in a 1,200-allocation loop and
  was not reproduced by the follow-up run;
- an undefined-function error can display a shortened or padded function name;
- `defstruct` and the related dynamic-library freight remain parked.

The undefined-function error itself remains valid; only its printed name
detail is unreliable. Its two-store renderer correction is attributed and
scheduled after this sealed release rather than folded into v1.2.1.

## Claim boundary

v1.2.1 claims the exact sealed C2-lite product and the hardware results above.
It does not claim Freezer safety during an active persistent definition,
interrupt-generating cartridge support, a GC latency ceiling, a standalone
application builder, `defstruct`, dependency-safe unload, or a general
condition system.
