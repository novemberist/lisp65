# lisp65 1.2.3 Release Notes

Release date: 2026-07-30

lisp65 1.2.3 delivers the first post-1.2 language and library freight in the
reproducible public product:

- `while` provides structured iteration without adding a new VM opcode;
- `random` returns an unbiased fixnum below a positive bound, and
  `random-seed` makes generated sequences reproducible;
- repeated `require` calls use a generation-bound identity fast path; and
- interrupt ownership is hardened for Ethernet, Auto-IEC, and audio-DMA
  sources.

The REPL banner now displays `WORKBENCH 1.2.3`. The complete-name
undefined-function diagnostic fixed in 1.2.2 is carried forward unchanged.

## Language and library additions

`while` repeatedly evaluates its body while its test is non-`nil` and returns
`nil` on normal termination:

```lisp
(setq n 0)
(while (< n 6)
  (setq n (+ n 1)))
```

A loop whose backward edge crosses a streamed code-window boundary reloads that
window once per iteration. Keep tight loops small or place them in small
functions when this cost matters.

`random` is intended for programs, simulations, and games:

```lisp
(random-seed 123)
(random 6)                    ; a value from 0 through 5
```

The generator is not a cryptographic random-number generator.

## `require` repeat path

In the bound host measurement, an already-loaded `require` used **97.96% fewer
VM steps** and **93.23% fewer one-byte C2D reads** than the first load. These
percentages are host measurements, not device timing claims.

Hardware confirms the repeat semantics: after an asserted cold start,
`(require 'place)` returned `t` twice, and the second call left the C2D header
and `place` row byte-identical. The logical-analyzer phase markers 17 through
20 were not read on the device; this release therefore claims hardware
idempotence, not hardware timing for the fast path.

## Acceptance and reproducibility

The candidate was accepted under its own product identity; no earlier release
green was inherited.

- The full equivalence chain executed **447 cases across 11 lanes**.
- The 25-row cross-invariant matrix re-derived the 9 rows reachable from the
  Link-80 delta and explicitly retained, without re-deriving, the other 16.
- G5 passed 9/9 fresh hardware cases, including 0-frame cold and warm
  published calls, RUN/STOP recovery, idle Freezer return, and destructive
  restage.
- G6 passed 5/5 offline, cold-boot, destructive-restage, work-media, and
  product-media cases on one physical MEGA65.

## Known issues

The maintained [Known Issues and Retired Exceptions](../known-issues.md)
contains the complete user-facing boundary. In particular:

- enter the Freezer only while the evaluator is idle;
- do not use interrupt-generating cartridges while lisp65 is running;
- preserve the exact workload if the intermittent post-GC out-of-memory
  symptom returns;
- if `require` unexpectedly returns `nil`, cold-restart lisp65 and retry once;
  and
- `defstruct` and dynamic package freight are not delivered.

The `require` issue was observed once late in a long session and did not recur
after an asserted cold start. No cause or fix is claimed.

## Claim boundary

v1.2.3 claims the exact sealed C2-lite product and hardware results above. It
does not claim Freezer safety during an active persistent definition,
interrupt-generating cartridge support, cryptographic randomness, device-side
fast-path timing, a GC latency ceiling, `defstruct`, dependency-safe unload, or
a general condition system.
