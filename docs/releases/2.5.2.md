# lisp65 2.5.2 — Faster editing and a disk-directory fix

This release adds faster line editing, lets you reopen earlier Comfort input, and fixes a disk-directory bug. It was accepted on a physical MEGA65, including typing and Backspace feel, reopening input, C-x q, RUN/STOP and the directory fix on a real disk.

## Editing

At an empty Comfort continuation line, press Backspace to reopen the previous line. The prompt prints `[edit previous line]`. Delete any automatic indentation first: moving to the start of a nonempty line is not enough. To go back another line, empty the reopened line and press Backspace again. Up/Down still browse history.

Editing rules at the native `lisp65>` prompt and in ordinary `read-line` remain unchanged in the checked host comparisons. The update also reduces temporary memory use when submitting long lines and when deleting and replacing recalled text.

Comfort input has these limits:

- Up to **32 pending continuation lines**, followed by a completing line.
- **640 bytes** of accepted source in total, including line-feed bytes and indentation.
- **250 characters** in the active editor line.
- **Ten history entries**, each at most **250 bytes**.

`*** input limit` discards the current pending input and starts a fresh input. A valid submission longer than 250 bytes prints `*** history limit` and is omitted from history; evaluation is still attempted. Staying within the source limit does not guarantee that a form can compile.

Multiline strings continue to preserve typed whitespace, as in 2.5.1.

## Measured typing cost

For the same 40-character Comfort typing test, with one key delivered at a time, emulator measurements give:

| Version | Mean cycles per key |
|---|---:|
| 2.5.1 | 1,635,493 |
| 2.5.2 | 1,130,909 |

That is a **30.85% reduction**, equivalent to about **40.4 → 27.9 ms/key at 40.5 MHz**. These are emulator cycle measurements, not physical keyboard timings. Return and evaluation costs vary with the input.

## Fixed: saving could hide later directory entries

Saving into the first entry of a directory sector could erase its link to the next sector. Files listed in later sectors then disappeared from the directory, although their data remained on disk.

The fix preserves that link. It is present in the release disk image and was confirmed on a physical MEGA65 with a real disk. Source history traces the defect to the implementation included in releases since 1.0.0.

## Known issues: IDE and disk

Saving with `C-x C-s` and running `eval-buffer` still build a character list for the entire buffer. Some files can therefore load but be too large to save or evaluate.

In host fixtures with a budget of 588 additional heap cells, the last successful test buffers were 20–23 lines of 20 characters, 10–12 lines of 40 characters, or 6–7 lines of 70 characters, depending on the edit cache. **These are test results, not guaranteed limits.** Other live data and the program being evaluated can require more memory.

The reproduced failure while joining the buffer occurs before disk writing and leaves the disk file and buffer intact. Keep IDE files small or split them.

`eval-buffer` also has a GC-root defect: collection during compilation can reclaim its source string and stop evaluation early without an error message. A native host test read only one of five forms. Check that expected definitions exist, or evaluate forms individually. Heap and reader-root fixes are planned for 2.5.3; they are **not included in 2.5.2**.

Other disk limitations remain:

- Interrupted saves can leave allocated blocks with no owning file. Repeated interruptions can reduce free space. Host tests between completed logical-sector writes preserved the old or new target file; this does not establish protection against interrupted physical writes or power loss.
- Loading text removes trailing spaces and line endings at the **end of the file**, and removes carriage-return bytes throughout. Saving the loaded buffer makes those changes permanent.
- A completely full directory of **144 files** is rejected on remount, preventing subsequent replacement through that failed mount. Use a disk with a free directory entry.
- A previously damaged allocation map can pass the free-count checks while marking another file's block as free. Saving can then overwrite that block. A successful mount is not a complete disk-consistency check.
- Directory listing can return partial results after a read failure or exhausted traversal limit. A partial listing is not proof that the omitted files are absent.
- RUN/STOP in the IDE can discard the most recent input batch; a host test lost three recently typed characters.

Switching buffers in the IDE while only one buffer exists can reactivate an older state of that buffer: characters typed just before the switch disappear without a message. Avoid switching when only one buffer is open. A mark kept across text edits can point past the end of the text; typing then may insert an unexpected line.

Use **C-x q** to leave the IDE with buffers preserved; release Ctrl before typing q. Physical C-x C-c remains unavailable.

## Other known limitations

- Recalling multiline history containing a comment can leave Comfort waiting for more input even when the recalled form is complete. Retype the form without recalling that entry.
- RUN/STOP after Home on a wrapped Comfort line can leave a stale inverse cursor above the next prompt. This is cosmetic.
- Individual string literals over **255 bytes** fail to compile with `*** VM: BAD BYTECODE`. The 640-byte source limit does not enlarge the literal format.
- Printing a cyclic list can run indefinitely. Printed symbols are not always safe to read back: number-like names, case, special characters and generated-symbol identity can change the result. `intern` truncates names at an embedded NUL; strings containing NUL cannot make a print/read round trip. Some byte values appear as spaces on screen.
- `write-string` does not append a newline; `write-line` does. Some existing documentation reverses these descriptions.
- `defstruct` does not check its generated names against each other; for example a slot named `p` produces the same function name as the structure predicate. `mapcan` fails with more than 12 input elements (it exceeds the 12-argument call limit internally).
- Anonymous lambdas at top level, outside `defun`, remain refused. Code-image slots are not reused, and calls are limited to **12 arguments**. Use `string=` for string contents; `equal` compares string identity.
- Run `require` as a plain top-level form. It is refused inside temporary compiled forms, even for an already loaded package. A missing package at the interactive prompt prints LOADING before NIL. A NIL load result is not always a distinct “file not found” diagnosis.
- At the native REPL, a syntax error in trailing input does not undo earlier forms already executed from that input.

Host compiler tests also report that LCC can drop later pairs in a multi-pair `setq` and skip surplus arguments to some builtins, including their side effects. Confirmation on the current release medium is still pending. Until resolved, use one assignment per `setq` and the documented argument counts.

Additional host findings concern a temporary generated name passed to the internal macro-install service and a disk chain changed between the loader's two read passes. The macro finding has not been demonstrated for ordinary `defmacro` with an interned name. Recovery concerns based only on an artificially injected abort during arena relocation or a suspected persistent OOM flag remain under investigation; they are not confirmed ordinary RUN/STOP failures.

Existing operating restrictions still apply: enter the Freezer only while evaluation is idle, and do not use interrupt-generating cartridges. Standalone Ship RUN/STOP remains independently unverified. Older open observations include an unreproduced post-GC out-of-memory error, a protective stop without a diagnostic, and cosmetic color remnants during scrolling. The source bundle's `docs/known-issues.md` describes inherited limits, including stack depth.

A stopwatch cold-boot measurement remains open; the tool-clock boot on the device was 40.9 s to the prompt.
