# C2.1 single-source GC-root correction

Status: **Option B2 owner-approved; product decoder and substitution link authorized**

Date: 2026-07-19
Machine-readable contract: `config/c2-gc-root-single-source-proposal.json`

## Why the approved wording needs one correction

The owner approved a fixed-cost C2D-v2 root solution and added the stronger
rule that root membership is emission-derived rather than maintained by the
runtime. Taken literally, the earlier Option B does not satisfy that rule: it
stored every heap value once in the normal resolution table and a second time
in a compact root-value vector.

Replacing that vector with 284 immutable resolution ordinals removes the
duplicate values, but no longer has the approved cost. The collector would
read the 568-byte ordinal list in 18 transfers and then perform 284 scattered
two-byte reads to obtain the values. The total is 302 DMA jobs, worse than the
141 jobs of the rejected complete-resolution scan.

There is a second contract correction. C2D is the mutable, session-specific
plane and currently has no content CRC of its own. Its final header is the
publication marker and binds the verified shelf catalog CRC. The immutable
root-membership fact belongs to C2I metadata, which is already protected by
the per-metadata, per-image and catalog CRC chain. Recomputing a C2D CRC over
session object values would not make membership emission-derived.

No product or proof format is changed by recording this correction.

## Option B2 — descriptor-tagged single-source roots (recommended)

C2D-v2 keeps the two-byte resolution record and appends the approved compact
root-value section. The record's interpretation is selected only by the
identity-bound immutable C2I descriptor kind:

| C2I descriptor kind | C2D resolution word |
|---|---|
| kind 3 string or kind 7 pair | canonical `root_index_u16` |
| every other legal kind | resolved `obj_u16` |

For kind 3 and kind 7 the resolution word is **not** an `obj`. The object value
exists exactly once, at `root_values[root_index]`. Root indices are canonical:
they are the zero-based rank of that descriptor among all preceding kind-3
and kind-7 descriptors. The decoder may not choose or maintain membership.

The immutable descriptor stream is therefore the root-membership map. It is
emission-derived, self-described by C2I-v2 and protected by the existing shelf
CRC chain. C2D binds that exact catalog CRC and carries only the session's
canonical mutable values. A mismatch between descriptor census, root count,
canonical root index or final cursor is a format error.

Current geometry remains the approved geometry:

```text
C2D-v1:             10,480 bytes
canonical roots:       568 bytes (284 obj values)
C2D-v2:             11,048 bytes
Bank-5 headroom:     39,768 bytes
GC scan:                568 bytes / 18 reads at 32-byte quantum
```

No object tag is reserved and no second root value is created.

## Hot-window rule

The VM must not interpret a root index as an `obj`. When an entry becomes the
hot code-window owner, the refill seam reads its contiguous C2I descriptor
range and contiguous C2D resolution range. For heap descriptors it follows
the canonical index into the contiguous root-value section; for all other
descriptors it consumes the resolution word directly. It writes the resulting
values into the Bank-0 hot literal cache before executing the entry.

The current composition has at most 23 literals and at most nine heap literals
in any entry. Root indices belonging to one contiguous entry range are
monotonic and contiguous after non-root descriptors are ignored, so at most
one contiguous root-value span is needed per hot-window materialization.
`PUSHLIT`, `CALL` and related consumers continue to read the already
materialized hot literal cache; they acquire no new object tag or per-opcode
Attic lookup.

Nested-call restoration must rematerialize the caller's literal cache together
with its immutable header. C2.2 must measure this entry/refill cost on hardware;
the present host proof makes no latency claim.

## Construction and GC invariant

Before the first allocating descriptor, the root-value section is zeroed and
the collector is bound to its full declared span. After a string or pair
allocation returns, the decoder writes the value to its canonical root slot
before any further allocation. It then writes the root index to the logical
resolution record. There is never a second value write.

The collector is non-moving. It DMA-reads the 284 canonical values, marks the
referenced cells and never writes a root value back. This read-only scan is
correct only while GC is non-moving. Introducing a copying or compacting GC
invalidates the C2D-v2 root contract and requires a new root-update/publication
protocol.

## Permanent gates

The host proof rejects:

- C2D-v1 presented to the v2 decoder and v2 presented to the v1 decoder;
- root count different from the immutable kind-3/kind-7 census;
- root section overlap, truncation or trailing data;
- a heap-kind resolution without its canonical root index;
- a reordered, duplicated or out-of-range root index;
- a direct-kind resolution that is interpreted as a root index;
- zero or non-pointer canonical root values in a published plane;
- catalog identity drift;
- final root cursor different from the declared root count.

The allocation stress runs GC after every kind-3 and kind-7 allocation and
proves that all earlier values survive and that every root word remains
byteidentical across collection.

No C2D format has shipped in a product. C2D-v1 remains historical proof
evidence and C2D-v2 may become the sole product decoder without compatibility
or migration debt. The same change after a product seal would require a
migration contract.

## Decision — approved 2026-07-19

The owner confirmed Option B2 and the CRC-domain correction. Product-decoder
work and the real substitution link are authorized. The approval preserves the
568-byte/18-read GC geometry and all three owner conditions: immutable
membership is CRC-bound in C2I/Shelf; C2D contains the one canonical runtime
value plane and binds the verified catalog identity.
