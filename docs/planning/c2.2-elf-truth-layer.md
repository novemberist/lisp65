# C2.2 shared ELF truth layer

Owner commissioned on 2026-07-21 after the fourth recurrence of a gate
modelling ELF ownership through a private textual view.  The layer is host
infrastructure and emits no product bytes.

`tools/host-lisp/elf_truth.py` consumes one structured
`llvm-readobj --elf-output-style=JSON` document.  It preserves section indices,
symbol `st_shndx`, symbol size/type, relocation source section and target
symbol/addend.  A VMA query returns every overlapping section; it never elects
an owner.  Absolute symbols are usable as identities only when the consumer
registers their exact name and value.  Sized ELF symbols and contractual
intervals resolve only when exactly one interval owns the queried
`(section,address)`.

The Boot-lifetime gate is the first client.  Its immediate regression matrix
retains the four overlay-identity mutations and adds four parser-boundary
cases: the section-bound Workbench marker and exact Absolute runtime-VMA marker
pass; an unknown Absolute at the same address and an external installer target
fail.  The authorized pure replay is bound to ELF `c82b9bd...` and contains no
compiler, linker, WPLTO, product-link or hardware action.

The post-v1.2 housekeeping pass completed the staged migration across
Pre-Ownership, Boot-Lifetime, fixed facade, profile-data references,
KERNAL/control-flow and final section inventory.  Their Section, Symbol,
STT_FUNC-size and Relocation identities now come exclusively from this shared
layer.  `llvm-objdump` remains at the KERNAL/facade gates only as an instruction
decoder; rendered labels, addresses and section ownership are not accepted as
ELF truth.  `tools/host-lisp/c2_elf_truth_migration_gate.py` permanently derives
the six-client inventory from the contract and rejects a return to
`llvm-nm`, `llvm-size` or human-column `llvm-readobj` parsing.

Each client's existing mutation suite remains its semantic regression net; the
post-promotion migration gate adds four private-view rejection mutations.
