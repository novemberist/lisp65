# C2.1 mutable session-directory addendum

Status: **Option A owner-approved; product-layout probe authorized**

Date: 2026-07-19
Machine-readable proposal: `config/c2-session-directory-proposal.json`

## Finding

The approved C2I envelope now lets a decoder discover every immutable entry,
literal descriptor and string. The next C2.1 step exposed a separate missing
envelope: the mutable session directory has semantic fields, but no byte-level
representation. A product-layout link would have to hard-code the active image
count or invent arrays that the later product decoder need not share.

That would repeat the proof-diverges-from-product error which stopped the
metadata-envelope work. The link therefore pauses before any product source or
capacity changes.

The current full composition provides exact sizing input:

| Input | Current value |
| --- | ---: |
| Images (resident plus shelf tenants) | 6 |
| Callable entries | 583 |
| Literal resolutions | 2,084 |
| Existing Bank-0 directory arrays retired by C2 | 761 B |
| Post-boot Bank-0 reserve | 1,907 B |
| Bank-0 reserve target | 1,536 B |
| Current steady EXT code use | 24,584 B |
| Old L65M runtime slices | 28 / 36,744 B |
| Runtime-overlay-bank headroom | 64 B |

The six inputs are `stdlib-p0`, IDE, IDEX, M65D, Buffer and the compiler tier.
The counts are read from their generated manifests, not copied into the proof.

## Option A — external self-describing session directory (recommended)

Use the code region freed in Bank 5 for a `C2D-v1` mutable table. It contains a
32-byte header, 20-byte image records, 10-byte entry records and two-byte
resolved `obj` values. For the complete current composition:

```text
32 + 6*20 + 583*10 + 2084*2 = 10,150 bytes
```

Replacing the current 24,584-byte steady code allocation leaves 40,666 bytes
of that 50,816-byte region free. Bank 0 keeps only a 64-byte hot state (DMA
descriptor plus header/image/entry/resolution caches); retiring the existing
761-byte directory arrays yields a 697-byte data credit before code is linked.

The local header is self-describing: magic/version, all record widths, nonzero
session generation, image/entry/resolution counts, section offsets, total
length and the verified shelf catalog CRC. Checked arithmetic closes the
sections before any record is read. The final header is the mutable-plane
commit marker and is published only after the export journal succeeds.

## Option B — descriptor-on-call fallback

Keep only the image table and resolved `obj` values in Bank 5 and fetch an
immutable C2I entry from Attic on each call. This uses 4,320 bytes and saves
5,830 bytes relative to Option A, but it changes the approved statement that
the runtime directory maps code length and resolution base. It also adds an
Attic metadata DMA to the call path and therefore needs a contract amendment
and hardware latency proof. It is a fallback, not a free optimization.

## Option C — fixed Bank-0 arrays (rejected)

Putting the same records in Bank 0 costs 10,150 bytes. Even after removing the
old 761-byte arrays, the net debit is 9,389 bytes; the measured post-boot
reserve becomes -7,482 bytes and misses the 1,536-byte target by 9,018 bytes
before decoder or refill code exists. No packing argument can repair that
currency mismatch.

## Decision — approved 2026-07-19

The owner approved Option A without amendment. The C2.1 product-layout probe
must use the exact C2D-v1 directory decoder that C2.2 will consume. Option B
remains an unselected fallback requiring a contract amendment and hardware
latency proof. Option C stays structurally rejected.

This addendum changes no product byte, spends no capacity and does not enlarge
the execution claims already bound by the C2.1 direct proof.
