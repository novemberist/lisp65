# v1.6 Comfort input-fidelity pricing

Date: 2026-08-18  
Authority: `89369d50`  
Status: **priced; hybrid selected; owner resident-byte decision required**

## Outcome

The lossless boundary is mandatory. A synchronous editor, even one that
allocates zero cells per key, cannot pass the commissioned test: while the
explicitly forced 89-frame collection owns the CPU, the sixth event still
arrives at a full five-event hardware queue. Removing periodic collections is
useful, but it is not a proof that an independently forced collection cannot
lose input.

The winning price is therefore a hybrid:

1. the owned raster IRQ drains ordinary PETSCII codes into a raw ring before
   Lisp can block queue service;
2. Comfort reads those scalar bytes directly through the existing `peek` and
   `poke` primitives, so `key-event` no longer allocates its three-cell tuple
   on this path;
3. the current mutable editor remains intact and allocates only its one
   insertion cell for a printable key.

This is the least expensive candidate that passes the common loss test. It
does, however, break the zero-resident promise and therefore is **not
authorized for implementation by this report**.

## The loss model

The permanent input contract is one physical event per 50 Hz frame. This
covers the core's held-key repeat cadence and is already well above ordinary
human character entry. It is a product acceptance bound, not a claim that the
keyboard hardware is incapable of generating contrived faster edge patterns.

| Term | Events |
|---|---:|
| Hardware queue already full | 5 |
| 89-frame collection × 1 event/frame | 89 |
| Capture requirement | **94** |
| Raw ring capacity (112 slots, one kept empty) | **111** |
| Margin | **17** |

The executable model captures all 94 events in order, including event six,
with zero drops. Event six survives because the raster IRQ continues to drain
the hardware queue into storage that is independent of the Lisp heap while
the collector owns the mainline.

This corrects the host-card lesson directly: cells per key are only one term.
The acceptance quantity is queue capacity relative to the worst service gap
and the admitted producer rate.

## Exact selected price

The target-shaped assembly was compiled with the MEGA65 llvm-mos toolchain;
the Bank-2 shape was compiled by the real P0 compiler.

| Component | Bytes | Placement |
|---|---:|---|
| IRQ wrapper | 17 | mapped C2 window |
| Hardware-queue drain | 52 | mapped C2 window |
| Error/longjmp disable | 5 | ordinary Bank-0 text |
| **New emitted resident code** | **74** | 69 C2-window + 5 ordinary |
| Ring head/tail | 2 owned bytes | existing reserved `$FF8C/$FF8D` state |
| Raw ring | 112 lifetime-reused bytes | existing `repl.buf` tail `$BC90..$BCFF` |
| New emitted state/BSS | 0 | no section growth |
| Bank-2 bytecode | +251 | three existing functions, no new name |

Placement remains possible but tight:

- ordinary text falls from 11 to **6 free bytes**;
- the C2-window gap falls from 606 to **537 free bytes**;
- no public name, private name, primitive ID, or public `key-event` ABI is
  added;
- the largest changed bytecode object is 237 bytes, below the 255-byte limit.

The existing native buffer is reused only during the lifetime of the Comfort
editor. Its first seven bytes — the canonical `(repl)` activation plus NUL —
remain untouched. Capture is disabled before evaluation, on normal Comfort
exit, and from native error recovery. The `$A0`-to-space boundary remains on
the raw Comfort consumer, and physical RUN/STOP remains the independent matrix
authority rather than becoming a raw PETSCII event.

Although no state section grows, the cost is not zero: 112 existing Bank-0
bytes gain an exclusive Comfort-time lifetime, two formerly unnamed fixed
state bytes gain owners, and 74 code bytes are emitted. Calling this
"zero-resident" would be false.

## Rejected alternatives

### Capture full event tuples

The Comfort editor consumes only the code, but a transparent capture of the
current `(code, modifiers)` hardware tuple needs two bytes per event. Even the
entire 185-byte native-buffer tail would hold only 91 usable events, three
short of the 94-event contract. It therefore needs new Bank-0 state and loses
to the raw-code hybrid.

### Synchronous zero-allocation editor

Zero allocation removes the periodic collection caused by typing; it does not
preserve event six across the explicitly forced collection. It fails the
common acceptance test before its placement price matters.

### Capture plus fully preallocated editor

Once capture exists, removing the remaining insertion cell adds no
losslessness. It also requires a non-local editor refactor: `%rl-cut` and
`%rl-put` are already 253-byte objects, `%repl-read` is 249 bytes, and the
measured symbol margin is zero. The selected hybrid instead increases the
printable interval between hot-path collections from at most 48 to at most
192 while the ring makes those collections lossless.

## Required implementation acceptance

If the owner accepts the resident price, the implementation card inherits
these walls:

- begin with five pending ordinary events;
- inject one new physical event per frame through a forced 89-frame
  collection;
- observe all 94 codes in exact order, including event six, with zero loss;
- verify ring full/empty and producer/consumer commit ordering;
- preserve `$A0 → $20`, the independent matrix RUN/STOP authority, public
  `key-event`, and native-REPL fallback;
- prove capture disabled before evaluation and on every normal or exceptional
  exit;
- carry the resident deltas honestly: +69 mapped-window code, +5 ordinary
  code, two fixed-state owners, and a 112-byte Bank-0 lifetime alias.

mutation-backed receipt are
