## Outcome

One complete `make -k check-source` execution took **1,080.398 seconds
(18:00.398)**. GNU Make's own target start/end edges account for 1,079.985
seconds of that wall time: 612 executed target instances, 612 distinct target
names and all 363 direct `check-source` prerequisites. Nothing was missing,
incomplete or red.

The decision is **tiering**, not incremental revalidation. The ordinary
`check-source` target is unchanged as the only closing-commit certification.
The new `check-source-inner` convenience target traverses the same live target
graph but explicitly holds the eight measured direct targets at or above ten
seconds. Every new direct target enters the inner loop by default. The command
prints the complete-only set before it runs and carries no certification
claim.

Incremental archive revalidation was rejected because it would create a
second cache-validity authority over sealed evidence. A shorter developer loop
is useful; a second definition of "fully checked" is not.

The implemented inner target subsequently completed the living successor
graph in **552.140 seconds (9:12.140), Exit 0**. Against the bound full-run
wall this is a reduction of 528.258 seconds, or **48.89%**. The successor graph
already includes the new Block-2.5 and v2.0 planning checks, so this is a
conservative end-to-end validation of the tier rather than a subtraction
estimate. Its untracked 152,793-byte log is bound by SHA-256
`b20d6785288947cd1d64f4647a986564ee1e3a5c1b8c9ab50bc18276103fc053`.

## Midnight idempotence finding

The first complete closing run crossed into 2026-08-31 and exited zero, but
the clean-tree check correctly refused to certify it: three historical
producers rewrote `recorded_on` from August 30 to August 31, and two mapped-far
receipts followed those changed hashes. No semantic field changed.

The producers now preserve the creation date already carried by their receipt;
only a genuinely new receipt receives today's date. The three direct receipts
and two transitive receipts were regenerated in dependency order after the
driver change, then regenerated a second time with byte-identical SHA-256s.
This converts the date-rollover failure into a permanent producer property
instead of accepting five daily rewrites as evidence drift.

The complete target remains the block-exit bar and runs twice on the final
closing commit, exactly as commissioned.
