## Authorized package and stopping point

The authorized package combined the C2D-v5 high-handle contract, disjoint
nested transient appends, the Bank-5 C2J unwind seam including RUN/STOP, and
their fixtures.  Capacity had to be proven before any successor product link.

The target-shaped `-Oz`, no-LTO section probe reached its first hard wall in
the existing `c2append_capacity` slice:

| Slice | Link-32 source baseline | C2D-v5 candidate | 1,792-B cap | Result |
|---|---:|---:|---:|---|
| `c2append_capacity` | 1,398 B | 3,950 B | 1,792 B | **first red: +2,158 B** |
| `c2append_rollback` | 1,305 B | 2,235 B | 1,792 B | diagnostic from the same object: +443 B |

The baseline target-object sizes agree exactly with the Link-32 session
manifest for the first red slice.  Rollback differs by four bytes from the
LTO-linked baseline (1,305 vs. 1,301), which does not affect its 443-byte
target-object overrun and is reported rather than normalized away.

No product closure was linked.  C2J cleanup and the B2 RUN/STOP fixture were
not reached, so neither is claimed green.  The Link-32 product and protected
fallback evidence remain untouched.

## Architectural decision now required

The hard 1,792-byte slice cap cannot be relaxed.  The closed `$e000` window,
the effectively full Island and Bank-0 resident regions cannot absorb the
excess.  The measured session runtime bank has ample aggregate space, so the
smallest viable direction is a **semantic session-slice split**:

1. separate transient-front discovery/reservation from metadata root counting
   and have the resident driver call the phases serially;
2. separate rollback's publish-first invalidation from record/Attic wiping and
   C2J completion, again driven serially rather than by an overlay calling an
   overlay;
3. place the B2 central cleanup only after those phase boundaries exist, so
   RUN/STOP and errors share the same transported C2J restoration path.

This is a residence decision, not an authorization.  Any such split needs a
reviewed slot/phase contract, full runtime-bank attribution, rollback-cutpoint
fixtures, and a fresh capacity probe before a product link.

The Freezer disposition is independent and is now a permanent row in
`config/c2-hot-refill-hardware-presmoke.json`.
