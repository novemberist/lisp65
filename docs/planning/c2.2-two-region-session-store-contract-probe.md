# C2.2 two-region Session store contract probe

Status: **FIRST RED before product implementation**, 2026-07-24.

The Bank-5 placement is feasible, but the current strict L65R-v3 format cannot
name it.  L65R-v3 has one family-wide storage base.  Its 32-byte record carries
an existing `capability_mask` field at bytes 24–27, but the product decoder
requires all bytes 24–31 to be zero.  Treating one of those bytes as a region
without a version change would silently weaken the strict-v3 contract.

No product source, emitter, decoder, slice, linker input or binary was changed.
No WPLTO, product link or hardware run was made.

## Exact Bank-5 geometry

The apparent 16,976-byte suffix after the 33,840-byte C2D image is not wholly
uncommitted.  It is the lifetime-managed area for the eight-byte export plan,
the 336-byte emitter-root store and the 64-byte C2J:

| Interval | Bytes | Owner |
|---|---:|---|
| `$0000..$842f` | 33,840 | canonical C2D-v6 |
| `$8430..$bcff` | 14,544 | retained export/Append growth floor |
| `$bd00..$c4ef` | 2,032 | proposed Session overflow region |
| `$c4f0..$c63f` | 336 | emitter-root state |
| `$c640..$c67f` | 64 | C2J |
| `$c680…` | — | external symbol arena |

The proposed region is 256-byte aligned and 16 bytes smaller than 2 KiB so it
can end exactly before the emitter roots.  The retained 14,544-byte floor holds
1,818 eight-byte export-plan rows.  With 590 current entries that leaves 1,228
worst-case dynamic export rows.  The root table has 1,253 unused ordinals, so
the new floor becomes binding only 25 entries before the old root ceiling when
every appended entry also owns one root and one export row.  This is the
capacity debit that the rough “16,976 bytes free” description concealed.

Only 192 bytes of the old suffix were uncommitted at the full 2,048-row export
cap.  The second region therefore consumes 1,840 bytes of potential export
scratch; it is not a free credit.

## Width-neutral successor model

The probe models a strict L65R-v4 rather than changing v3:

- header and record remain 32 bytes;
- record byte 24 is `region_id` (`0` = main Bank-3 Session store, `1` =
  Bank-5 overflow);
- record bytes 25–31 remain zero;
- the existing record CRC at bytes 22–23 covers the region ID;
- `file_offset:u16` is relative to the selected region;
- the v4 decoder rejects v3, unknown region IDs, cross-region bounds,
  misalignment and reserved-byte use;
- the old header-reserved `u32` is the proposed binding for the used Bank-5
  payload span, while base and hard cap remain generated contract constants.

Nine record mutations were rejected.  The model is representable without
record widening, but it is a real format evolution.  It needs an explicit
Class-C decision before the emitter, decoder or packing gates may change.

## Aggregate construction

The measured write-completion package projects the main Session image to
66,974 bytes.  A semantic finalize split costs one 256-byte quantum.  Moving
the measured 758-byte rollback-unpublish phase and the three measured wipe
bodies (195 + 432 + 292 = 919 bytes) uses 1,792 packed bytes in the second
region:

```text
66,974 + 256 - 1,792 = 65,438
```

That restores the exact 98-byte main-region reserve.  The Bank-5 payload spans
1,687 bytes and fits under the 2,032-byte hard cap.  This is arithmetic
feasibility, not a linked-size claim: the later semantic split must remeasure
its wrapper and entry bodies under Whole-Program LTO.

The resident serial driver remains the only loader.  It selects the record's
authenticated region and loads each phase; no overlay calls an overlay.
Bank-5-to-Bank-0 copying uses the same `c2_facade_vm_code_load` transport class
as ordinary C2D reads, so this adds no new hardware transport assumption.  A
successor closure gate must nevertheless prove that every region-1 record
selects that seam and that no Attic fallback exists.

## Separate resident walls

The two-region construction does not solve the independent resident deficits.

- Ordinary text remains 17 bytes red after the legitimate 33-byte
  `vm_ext_write` wrapper removal.  No second named fossil or duplicate was
  found in this probe.
- The coldest exact `$e000` candidate is
  `c2_append_run_rollback_plan` at 29 bytes.  It is not presently relocatable:
  it is the serial overlay driver, so placing it in either Session region would
  violate “no overlay calls an overlay”; placing it in ordinary text merely
  transfers 29 bytes into an already-red currency.  `c2_session_emit_reset`
  (47 bytes) and `c2_append_begin` (513 bytes) are also cold but own shared
  resident state/driver responsibilities.  There is therefore no legal
  28-byte window evacuation under the current walls.

## Required review

The geometry is green and the width-neutral strict-v4 model is green.  The
overall probe is red because the authorized product format is strict v3 and
contains no region identity.  The next decision is deliberately narrow:

1. authorize strict L65R-v4 with the same widths and the region byte above; or
2. reject the two-region Session-store direction.

Until then, finalize remains unsplit, Link 59 remains the rollback line and C1
remains open.
