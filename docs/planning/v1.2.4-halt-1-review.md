## M1 harness First Red

The original M1 script split input writes and result reads across a REPL
return.  The prompt/result renderer may use the same hardware math unit, so
the later read observed zeros.  This was a measurement-harness error, not a
product failure.

The correction remained inside the same physical session and changed no
product bytes: all eight input writes and all eight result reads were placed
inside one Lisp evaluation.  Both the original zero result and the corrected
atomic results are retained in the Phase-M receipt.  Future math-unit
fixtures must enforce the existing transaction contract mechanically:
compute first, then perform only input writes, busy-bit/control operations,
and result reads until the final byte has been captured.
