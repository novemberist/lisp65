qualified native Capture/Hybrid infrastructure in a deliberately closed state,
retains the hardware-accepted native `INIT.L65` and A0 recovery behavior from

`lisp65>` Cursor Left/Right behavior as a pre-existing, non-claimed boundary:
the optional `v16core` editor supplies cursor navigation only inside explicit
`(read-line)`.

## Hardware acceptance

The v1.8 substrate D-session booted to the native REPL, retained ordinary line
input and Delete behavior, recovered from `(>= nil 32)` to a live prompt
practically immediately, and evaluated the follow-up `(list 1 3)` as `(1 3)`.
Four performance-smoke bodies completed in at most one frame. D5 measured
113/1,506 with no optional library loaded.

The attempted Cursor Left row at the bare prompt was withdrawn from acceptance
weight and then attributed host-only. The native prompt has no boot-time or
runtime binding to the Bank-2 Lisp editor in either the sealed v1.7 ELF or this
v1.8 ELF. PETSCII `$9D` reaches stable native error code 5 before parsing or
evaluation. This is not a v1.8 regression and is explicitly outside the
release claim.

## Claim boundary

v1.8.0 claims the exact 22-role product/library set, the visible 1.8.0 banner,
retained v1.7 native behavior and a qualified but closed Capture/Hybrid
substrate. It does not claim Capture activation, lossless user input, Comfort,
delimiter matching, cursor blinking, or Cursor Left/Right editing at the bare
native `lisp65>` prompt. The fast-typing Known Issue remains open.
