# C2.0 metadata-envelope addendum

Status: **Option A owner-approved; C2.1 bytes authorized**

Date: 2026-07-19
Machine-readable proposal: `config/c2-metadata-envelope-proposal.json`

## Finding

The approved C2.0 contract fixes the 16-byte C2I entry and the eight-byte
literal descriptor, but it does not say how a decoder discovers the entry,
literal and string sections. The inherited 32-byte L65S-v4 record contains
region addresses, lengths and CRCs, but no entry or literal counts. The
contract also names an entry `flags` byte without assigning its bits, and it
does not define binary-safe string boundaries.

Hard-coding those values in the proof target would produce a green prototype
for a format that a product decoder could not independently decode. C2.1 is
therefore paused before its first emitted byte; the already approved address,
identity, reset and freight decisions remain unchanged.

## Options

1. **Local 24-byte C2I header — recommended.** Each metadata region is
   self-describing. The approved 32-byte shelf record and its identity chain
   stay unchanged.
2. **Expand the shelf record.** This puts container-internal counts in the
   catalog, couples two format layers and pays another catalog evolution.
3. **Compile-time counts in the proof target — rejected.** It would not prove
   the decoder that C2.2 needs.

## Recommended 24-byte header

| Field | Bytes |
|---|---:|
| magic `C2I\0` | 4 |
| version, header bytes, entry bytes, literal bytes | 4 |
| flags (zero) | 2 |
| entry count, literal count | 4 |
| entries offset, literals offset, strings offset | 6 |
| string-pool bytes | 2 |
| reserved (zero) | 2 |
| **Total** | **24** |

Sections are exact and contiguous:

```text
entries = 24
literals = entries + entry_count * 16
strings = literals + literal_count * 8
metadata_bytes = align2(strings + strings_bytes)
```

The L65S metadata length must equal that result. Checked arithmetic precedes
every access; the optional final alignment byte is zero.

## Strings and names

The local pool contains packed `length_u16 + raw bytes` records. Offsets point
to the length field and are relative to the local pool. This represents NUL
inside immutable strings without sentinel conventions. String descriptors
repeat the length in `argument0`; disagreement is a format error.

Export names are 1–255 canonical seven-bit ASCII bytes without NUL or reader
whitespace. The decoder does not case-fold them. The entry's u16 export-name
offset retains `$ffff` as the anonymous sentinel; every real record offset is
strictly below it.

## Flags and literal kinds

Entry bit `$01` marks a macro export; bit `$02` marks a late-bound export;
all other bits are zero. Anonymous entries carry neither bit. A late-bound
entry is named and cannot be targeted by an ordinal descriptor.

Literal kind IDs are fixed in the order already approved: NIL 0, true 1,
fixnum 2, immutable string 3, local entry ordinal 4, exported name 5 and
native primitive 6. Literal flags and the reserved byte are zero. Unused
arguments are zero. For strings/names, `argument0` is the byte length and
`argument1` is the local string-record offset; for entry/native references,
`argument0` is the ordinal/ID and `argument1` is zero.

Stored code keeps the current seven-byte header and zeroed literal-shaped
slots. Entry arity and literal count equal the header, and the complete
code-length equation must close. `PUSHLIT` consumes the mutable session
resolution table rather than those zero bytes.

## Decision — approved 2026-07-19

The owner approved the local 24-byte header and all rules above without
amendment. C2.1 must emit and decode this exact envelope. The approval changes
no product byte, spends no capacity and makes no execution claim by itself.
