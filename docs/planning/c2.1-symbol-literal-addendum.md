# C2.1 symbol-literal addendum

Status: **Option A owner-approved; C2I-v2 kind 8 authorized**

Date: 2026-07-19

Machine-readable proposal: `config/c2-symbol-literal-proposal.json`

## Finding

The recursive-list decision closes aggregate structure, but the following
semantic census found 979 existing SYMBOL nodes with 344 distinct spellings.
These are general Lisp symbol values. Some spellings name functions, while
others are quoted data, variables, compiler opcode names or future designators.
The legacy manifest records the value, not its eventual runtime use.

Consequently, spelling cannot prove a cross-container call edge. Mapping all
979 nodes to C2I-v1's `export-name` kind would turn data such as `pushi8`,
`otherwise` or `motion` into a false API claim. All current names are canonical
ASCII, 1–33 bytes, so representation width is not the problem; the missing
category is semantic.

## Option A — general-symbol kind 8 (recommended)

C2I-v2 adds `general-symbol-name-offset` as kind 8. It uses the existing
length-prefixed local string pool and resolves by interning the symbol without
asserting that a function cell exists. The descriptor remains eight bytes.

Kind 5 retains its narrower meaning: a compiler-proven cross-container callable
edge naming a declared export. Every converted legacy SYMBOL node maps to kind
8 because the old artifact carries no use provenance. New emitters may select
kind 5 only from explicit edge provenance; name equality is never sufficient.

This adds no metadata or C2D bytes. C2D remains 10,480 bytes with 40,336 bytes
of projected Bank-5 headroom. The additional decoder branch remains unpriced
until the real link.

## Rejected alternatives

Renaming kind 5 to a general symbol would erase the format-level distinction
that makes cross-container APIs auditable. Inferring callable roles from name
matches fabricates provenance and is rejected as false evidence.

## Consumer rule

Tree-shaking, `who-calls`, ide-help cross-references and every future call-graph
consumer may use only kind 5 as call evidence. Kind 8 is invisible to call
graphs. No consumer may promote it from spelling alone.

## Decision — approved 2026-07-19

The owner approved kind 8 for general symbol values while retaining kind 5 for
compiler-proven export edges. The two alternatives remain rejected. This
decision changes no product byte and spends no capacity; the new decoder branch
is priced only by the real link.
