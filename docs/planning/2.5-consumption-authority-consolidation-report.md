# Block 2.5 consumption-authority consolidation

Status: **complete — read-only, zero product bytes**.

The three formerly local cases now pass through one relationship-level gate:

| Case | Consumed property |
|---|---|
| static-plane extent | both real compiler consumers use the bound header path and its materialized extent |
| output-root / MAP tuple | every tenant's final `LOADADDR - VMA` equals the offset decoded from the emitted tuple |
| bytecode entry | both real compiler consumers use the bound stdlib header path and its materialized entry ordinal |

The gate does not replace one path literal with another.  It checks the pair
of path and value for headers and the pair of linked `LOADADDR` relation and
emitted tuple for MAP geometry.  It imports the predecessor mutation sets and
adds eight sharp relationship mutations; all fall.

The second consolidation is one prelink authority containing the seven
literal pins and six inherited candidate-dependent closures of the r7 world.
Every closure carries its live/sealed era policy.  Omitting a pin or losing a
closure's era policy falls before a link.

Permanent implementation:
`tools/host-lisp/consolidated_consumption_authority.py`, configured by
`config/consolidated-consumption-authority.json` and reachable from
`check-source`.  Historical receipts remain sealed and unchanged.

Successor rule: the compiler-consumer population is not a `seed/final` list.
It is derived from every linked `*.prg.elf` product node below the active
build-graph roots, and every such node owes one adjacent consumption receipt.
A newly added product without a receipt, or one consuming a stale path/value
pair, is mutation-red without registering its name.
