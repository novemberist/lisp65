suspects for the observed first failure: `vm_run_dir` rejects the zero length

The zero-depth abort plan itself is structurally sound.  D3 began with an

## Post-failure capture — completed 2026-08-02

The accidentally restarted state was reproduced against the exact Link-84
candidate medium before any readback: the bound editor query and the following
`(+ 4 5)` both returned `vm: undefined function #0ab`.  Only then did the
authorized eleven-read capture run.

The binary outcome is **READY zero with an intact directory view**, but the
pre-registered recovery interpretation needs one important correction.  The
abort path did not merely forget to re-arm READY: it correctly rejected an
invalid journal.  C2D header, high row 63, `lcc-run` row 171 and the resident
`c2_runtime` tuple are consistent with Link 84.  Runtime-overlay fault and
busy are zero, family/generation are Session/1, and phase owner is NONE.  The
abort witness is state 1, range 31..32, not done: journal validation was
entered and reconstruction was never reached.  The live 64-byte C2J is not
CLEAR; every byte is `$10`, so it cannot satisfy the `C2J\0` identity or CRC
and must fail closed.

The causal gap is in the autonomous medium path.  The candidate descriptor
stages and readback-verifies only the 33,840-byte canonical C2D prefix.  The
standing destructive-restage contract requires the complete 50,816-byte
Bank-5 reset image, with `[33840,50816)` zero and C2J zero before READY.  The
cold stager has no separate operation for that suffix, while product boot
changes only the header watermark and publishes READY without validating
C2J.  A restart can therefore retain stale C2J bytes under a newly staged,
otherwise valid product.  RUN/STOP is simply the first path that validates
them; it sets READY to zero, after which every entry-length lookup returns
zero and `#0ab` becomes stable.

This makes a simple READY re-arm the wrong fix: it would bypass a correct
fail-closed decision over unauthenticated rollback state.  The prepared
Class-C item is a cold reset-domain repair: bind the full 50,816-byte image in
the medium/descriptor, write and read it back before the later disjoint Boot
scratch, and prove zero C2J before handoff.  No product fix or link is made in
this attribution.  Full bytes, hashes and claim limits are bound in
`tests/bytecode/dialect-v2/evidence/architecture-blocks/c2.3-link84-post-runstop-readonly-capture-receipt.json`.
