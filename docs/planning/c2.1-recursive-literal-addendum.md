# C2.1 recursive-literal addendum

Status: **Option A owner-approved; C2I-v2 cons lowering authorized**

Date: 2026-07-19

Machine-readable proposal: `config/c2-recursive-literal-proposal.json`

## Finding

The direct six-entry C2 proof used only local entry references. The first
complete manifest census found a different live class: the IDE image contains
four recursive LIST nodes with 34, 48, 74 and 12 children. Together they carry
168 edges. C2I-v1 has descriptors for atoms, strings and callable references,
but no CONS or LIST representation.

The complete current census is:

| Existing literal kind | Nodes |
| --- | ---: |
| Fixnum | 260 |
| Symbol | 979 |
| CONS | 0 |
| LIST | 4 |
| String | 116 |
| Entry reference | 725 |
| **Total** | **2,084** |

Every child of the four current lists precedes its parent in the generated
manifest. The finding is therefore representational, not a cycle in today's
input. Emitting a partial image or retaining the L65M list materializer would
repeat the proof-diverges-from-product failure and is forbidden.

## Option A — strict C2I-v2 with cons-pair lowering (recommended)

Keep the approved 24-byte metadata header, 16-byte entry and eight-byte literal
descriptor. C2I-v2 adds one kind, `cons-pair`, whose arguments are descriptor
ordinals for CAR and CDR. Both are strict backward references; the u24 CDR
field must have a zero high byte. The emitter lowers every LIST to a canonical
backward cons chain ending in a NIL descriptor.

For the current four lists this creates 168 cons descriptors and one shared
NIL descriptor while removing four LIST descriptors: net +165 descriptors,
+1,320 immutable metadata bytes and +330 bytes in the C2D resolution table.
The approved C2D table becomes 10,480 bytes and still leaves 40,336 bytes in
the 50,816-byte Bank-5 region.

The version boundary remains strict: the product decoder accepts only C2I-v2;
the historical C2I-v1 proof stays immutable evidence and rejects v2. No product
contains both decoders.

## Option B — C2I-v2 edge-index section

Add a self-described u16 edge table and CONS/LIST span descriptors. The four
current lists need 336 edge bytes; a 24-to-32-byte header expansion across six
images adds 48 bytes, for a minimum 384-byte immutable cost and no C2D growth.
This is smaller, but introduces another section, cycle validation and more
decoder arithmetic. It is the bounded fallback if Option A is rejected.

## Rejected alternatives

Keeping the L65M recursive materializer creates a mixed decoder and violates
the substitution law. Rewriting the four IDE constants merely special-cases
today's census, changes source-level behavior/cost, and leaves future user
aggregate literals without a format.

## Decision — approved 2026-07-19

The owner approved Option A. The full-composition emitter uses strict C2I-v2,
backward-only cons-pair descriptors and canonical LIST lowering. Forward and
self references are format errors, and the resolver must be iterative or prove
its stack bound at the longest current chain. C2I-v1 remains immutable
historical evidence because no product has shipped it; making the same version
change after a product seal would require migration. Option B remains
unselected. This decision changes no product bytes and spends no capacity.

The later C2.2 repin must also replace the old capacity vocabulary with budgets
for immutable Attic code/metadata, C2D in Bank 5, the hot code window and the
remaining non-materializer runtime slices.
