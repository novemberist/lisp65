# C2.1 session-extension contract

Status: **bounded host probe complete; owner/reviewer decision required before product work**

Date: 2026-07-19
Machine-readable contract: `config/c2-session-extension-contract.json`

## One image language

Static product libraries, interactive definitions and persistent compiled
libraries use the same immutable representation: normalized code plus C2I-v2
metadata. A persistent or newly born library is wrapped as a one-record
L65S-v4-direct artifact. The outer record supplies the same split-region and
CRC identity used by the product shelf; the inner decoder is exactly the C2I
decoder already proved over the six static images.

The C2 product contains one emitter and one decoder. It rejects L65M. Source
remains portable across the cut, but a v1.1 compiled artifact must be
recompiled or converted offline. Keeping an on-device legacy reader “just for
old files” would recreate the forbidden dual-decoder product.

## Persistent envelope

The artifact is the existing self-describing L65S-v4-direct grammar narrowed
to one record:

- 32-byte header and one 32-byte split record;
- fixed `SESS` identity in record bytes 0–3; library names live only in the
  generated L65I index and are not a second record-local namespace;
- normalized code followed by C2I-v2 metadata;
- exact current product build ID;
- catalog, code, metadata and combined-image CRC32 on device, complete SHA256
  on the host;
- maximum total length 8,192 bytes, matching the M65D transaction contract.

Wrong versions, record identity, flags, build identity, CRC, section
arithmetic, trailing bytes or a record count other than one fail before
staging.

## Session Attic arena

Verified extension artifacts are copied append-only into the one-MiB session
arena beginning at `$08400000`. The copy is immutable for the rest of the
session. C2D records use source kind 1 and offsets relative to that base;
product shelf records remain source kind 0 relative to `$08100000`.

Attic survival is not session survival. The physical bytes may remain after a
reset, but a new C2D generation contains no extension record. Header, image
and entry generations must agree before any source-address calculation. A
stale record therefore cannot resurrect code merely because its bytes remain
in Attic memory.

## C2D-v3 append geometry

C2D-v3 replaces the tightly packed proof plane with capacity-separated
sections so append never moves a published record:

| Section | Capacity | Active at boot | Free |
| --- | ---: | ---: | ---: |
| Images | 64 | 6 | 58 |
| Entries | 2,048 | 583 | 1,465 |
| Resolutions | 4,096 | 2,249 | 1,847 |
| Root values | 1,536 | 284 | 1,252 |

The 48-byte header, 64 32-byte image records, 2,048 10-byte entry records,
resolution words and root values occupy 33,840 of the 50,816-byte Bank-5
session region, leaving 16,976 bytes. These are probe projections, not a
capacity authorization.

Each image record binds source kind/slot, current generation, its contiguous
directory/resolution/root ranges, code and metadata locations/lengths, and the
combined image CRC. The C2D header additionally binds the product shelf CRC
and product build identity.

There is no separately maintained committed Attic watermark. It is derived as
the maximum end of the metadata region among active source-kind-1 records (or
zero when none exist). Activating records through the C2D header counts thus
publishes reachability and the next append position from one source instead of
creating a second allocation truth.

## Roots during append

Heap-root membership remains emission-derived from C2I kinds 3 and 7; heap
objects still live only in the canonical `root_values` array. During an append
a two-byte pending-root high-water temporarily extends the collector's scan
through newly populated canonical slots. This is transaction state, not a
second value representation. Each heap value reaches its final root slot
before any subsequent allocation. Rollback zeros touched slots and clears the
high-water; ordinary collections scan only the committed root count.

## Publication

The loader verifies and readbacks the unpublished Attic artifact, checks all
four C2D capacities, resolves literals into inactive ranges and journals the
target export cells. It then writes inactive records and publishes the updated
C2D header as the directory commit marker; the active records expose the
derived Attic watermark. Exports publish last. Failure restores export cells
in reverse order, restores the old header and zeroes every touched inactive
record/root byte.

## Probe boundary

The authorized probe must use one emitter implementation for static and real
compiler-derived input, reject both format directions, inject failures at
every append phase, collect after every new heap allocation and prove stale
generation rejection. It changes no product source or artifact. Only a green
receipt may return to review and request authority for the real substitution
link.

The completed host probe is bound by
`tests/bytecode/dialect-v2/evidence/architecture-blocks/c2.1-session-extension-probe-receipt.json`.
It used the canonical C2I-v2 emitter for all six static product manifests, a
real compiler-derived session image and a root-bearing stress image. C2D-v3
closed at 8 images, 595 entries, 2,259 resolutions and 286 roots after both
appends. Forty-four negative classes cover the two format directions, every
append cutpoint, all capacity dimensions, stale generation, reset reachability
and malformed envelopes/records. These are host-contract results only: product
source and the real substitution link remain unchanged and unauthorized.
