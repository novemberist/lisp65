# C2.2 matrix addenda: cold placement

Status: owner-approved product contract, 2026-07-23.

The E5 depth-five failure is produced by the cold fronts phase, immediately
after `c2_transient_fronts` has authenticated the depth and before the phase
publishes any front value. It passes code 63 and Fixnum 5 directly to the
existing terminal detail seam before any C2D or C2J mutation. That seam enters
the one abort landing, which performs the existing C2J and transaction cleanup
before control returns to the REPL. No new resident cell or root is introduced.

On MOS the callsite is explicitly non-returning: this product path is entered
under the active REPL abort landing, so LTO may not materialize a fictitious
return continuation across the whole cold bounds phase. The host fixture keeps
its deliberate return path. This is a control-flow truth, not a second helper,
state cell, or error seam.

B3 and D3 share one event-tuple store. The physical RUN/STOP latch retains
priority, and a queued PETSCII `$03` remains data to discard rather than a
second abort authority. The common tail is a structural single-source
correction, not byte shaving.

The qualifying Whole-Program-LTO map must simultaneously retain at least 32
bytes of Bank-0 text noise reserve, the final 54-byte `$E000` floor, the 64-KiB
session-family aggregate and every other existing wall. The
`reopen_gap0`/session-emitter overlap must be zero in the linked map. Any red
stops before the successor product link.

The amended E5 form does not build a defer abstraction or a second VM-status
translation. The cold refusal calls the already existing
`lisp_abort_detail`/`lisp_abort_symbol` terminal seam with the two compile-time
constants. That seam alone owns the private `pending_code`/`pending_symbol`
cells and the abort landing. No E5 helper, latch, root, VM status, or second
status representation exists.

## Link-58 fixed-block relocation

The completed E5/B3/D3 WPLTO leaves 12 bytes of ordinary Bank-0 text against
the mandatory 32-byte LTO-noise reserve. This is resolved by one placement
change, not by instruction shaving. The first two candidates exposed the real
geometry: six inherited `.noinit` bytes follow the hot heap, and the inherited
overlay floor is `ALIGN(__noinit_end + 1, 2)`. The 30-byte
`lisp65_mod_adjust_tagged` leaf missed `$c356` by four floor bytes; the 28-byte
`rtov_read` leaf still missed it by two.

The selected tenant is therefore the intact 21-byte `rtov_fail` leaf. It has
exactly one control target, the named resident `rtov_wipe` function, resolved
from structured ELF relocation identity. It follows `kb_cursor_off` and
`c2e_cons` at `$c245`. The fixed code spans `$c218..$c259`; the unchanged
240-byte hot heap moves to `$c25a..$c349`; `.noinit` is pinned at
`$c34a..$c34f`; the aligned overlay floor is `$c352`, while the runtime-overlay
VMA remains `$c356`. The real fixed-block reserve is four bytes, while
ordinary-text room is projected to rise from 12 to 33 bytes.

The final-ELF gate binds the leaf's section, address, size, STT_FUNC identity,
sole fixed control target, and the inherited `.noinit` extent. Wrong section,
address, size, and an added control edge are negative fixtures. `$c080`,
`$c218`, `$c356`, the 54-byte E000 floor, and the 32-byte text-noise
requirement do not move.
