# C2.2 `defstruct` v1 host-first probe

Status: **probe in progress; no product seam, product link or hardware
authorized**

The accepted July-17 surface is deliberately small: a tagged list,
positional strict constructor, predicate, readers, functional `with-`
updates, shallow copier and canonical `setf` registration.  There are no
constructor, conc-name, include, default-value or representation options.

The first target preflight must distinguish the surface from its substrate.
Generated public names require the contracted `intern` primitive; replacing
them with gensyms would change the user surface.  Reader places require one
canonical registration mechanism in `stdlib-places`; a private defstruct
setter table would create a second place truth.

The July-17 design classified both capabilities as present.  The Link-68
dialect-v2 reality currently exposes neither through its executable ABI:
`intern` is named by `lib/prelude-surface.json` but has no callable
dialect-v2 primitive/function entry, while `lib/stdlib-places.lisp` has a
closed four-form dispatcher and no extension table.  The probe therefore
pins the complete expansion semantics and then runs a real P0 preflight.  A
red on either seam is a Class-C product question, not permission to add a
primitive or shadow registry.
