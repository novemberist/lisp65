# 1.4 work plan — the m65-hw parity pilot

Status: **commissioned by owner 2026-08-03** (successor-menu decision:
the parity pilot leads; tick hook rides as the paper track).
Baseline: released v1.3.0 (first advertised release, public main
`a8775d43`), revalidation bound in
`basic65-parity-revalidation-2026-07-30.md`.

## The one sentence

The graphics/VIC/SID era opens: `m65-hw` ships the **synchronous class**
— draw, sprite positioning, SID register voices — inside its revalidated
2,048-byte Bank-2, zero-resident envelope, with `q`, `wait`, `(time)`
and `read-line` as the already-delivered companions.

## Ground rules (all standing rules apply)

Host-first; receipts with execution witnesses; dependency-sharp first
red; no inherited green; resident geometry closed. Standing session
rules: cold reset + machine-checked context asserts (buffer peeks, never
the status line); quiet execution, postcondition reads only; I/O-register
captures CPU-side only (memsave reads RAM under I/O); no screenshot
polling around persistently writing forms; gates never take the code's
assumption or a simplified register model as oracle; **the owner's
physical test is a first-class acceptance instrument.**

## Phase A — Pilot contract (paper)

A1. The `m65-hw` surface from the revalidation, synchronous class only:
    register peek/poke discipline, `m65-draw` line/plot/fill primitives,
    sprite enable/position/shape, SID voice register writes (strike a
    note, set waveform — no envelopes over time, that is tick-hook era).
    Names prefixed per the module graph; no `fx`/`sfx` collision (moot
    since the `q` rename).
A2. Capacity card against the 2,048-byte envelope; EDMA surface only
    where the revalidation priced it. Error behavior and bounds named
    (coordinates, voice indices).
A3. **Ship closure rule**: `m65-hw` is tree-shaken freight like every
    base library — a shipped game carries it; the samples prove it.
→ No halt.

## Phase B — Host-first implementation

B1. Bank-2 implementation against a modeled register file (the fx/q
    gate pattern: source and artifact lanes, positive I/O witnesses,
    mutations for register addresses, bounds, and built-but-not-run).
B2. Equivalence lanes + the A2 allocation gate; **one WPLTO**, walls
    named, zero resident bytes.
B3. **Fifth ship sample: a visible toy** — sprite moving under `q`
    subpixel positions with `wait` pacing, one SID note on input via
    `read-line`/`key-event`. The smallest honest game loop the
    synchronous class allows; it ships through the real `(ship ...)`
    path.
→ No halt if the walls hold.

## Phase C — Tick-hook paper track (parallel, no product bytes)

The drafted `VM_YIELD_SAFE` scheduling contract matures into a
reviewable design: scheduler placement, callback state limits, abort
semantics, and its capacity estimate — the input for the *next* block's
decision, never implemented here.
→ Output lands at halt #1 as a menu item, not freight.

## Phase D — One bundled device session

Cold-reset rule, standing preflight asserts, rows in dependency order:

D1. Pilot smoke on hardware: draw visible, sprite visible and moved,
    SID note audible (owner confirms by ear — the physical instrument),
    bounds behavior sane.
D2. The fifth sample boots from its shipped D81 and plays.
D3. Standing trailing lines: require peek map, `q`/`(time)`/`read-line`
    smoke.
→ **Class-C halt #1**: results plus the tick-hook design on one table.

## Phase E — v1.4.0 release (after halt #1)

Standard ritual under the A1 rule; banner `WORKBENCH 1.4.0`; notes lead
with the visible toy; guide gains the m65-hw section with the honest
synchronous/continuous boundary stated (what needs the tick hook and is
not yet there).
→ **Class-C halt #2: publish go.**

No fix, no link, no hardware before an attributed mechanism.

### Attribution result — bounded First Red (Codex, 2026-08-03)

The first commissioned premise is false: the 16-byte Link-90 readback is
**not** a VM `pc/op/bank/off` capture.  The target Runtime Core was built
without `LISP65_VM_DIAGNOSTICS`, `VM_STEP_LIMIT` or `LISP65_DMA_PROF`, and its
ELF contains no `vm_dbg_*`/`vm_diag_*` symbols.  Its owned prefix ends at
`vm_status` (`$85` state, `$86–87` result, `$88` preload detail, `$89`
top-level latch, `$8A` status); bytes `$8B–$8D` are padding, not a latent
program counter.  They must not be decoded as a fault site.

The remainder of the Class-B work did narrow the boundary:

- the exact Link-90 emitted artifact runs host-green (`status=0`);
- a bound target-side predecessor witness read the shape as length 63 with
  byte 0 equal to 88 (`X`), while sprite 0 is an immediate, excluding the
  outer `m65-sprite-shape` argument guard;
- the first semantic difference between that host run and the target is now
  explicit: target `peek` reads live `$D06C–$D06E`, whereas the Ship host
  fixture models only `$FF83/$FF84` and therefore supplies zero for these
  unmodelled VIC reads; and
- Ship boot establishes no `$D06C–$D06E` ownership/readback contract.

That is a real host-gate gap, but it is **not yet the target-error
attribution**.  No exact Link-90 post-unlock pointer values or fault PC were
captured, and the lack of a visible sprite cannot distinguish the pointer
guard from a target-only failure between the accepted outer arguments and
the nested shape writer (sprite enable occurs later in both cases).

The bounded receipt and its six rejected overclaim mutations are
`c2.3-v1.4-link90-typeerror-host-elf-attribution-first-red.json`.  Per the
commission, work stops with zero product bytes, zero links and zero hardware
contacts.  The smallest honest next method is an owner decision between a
non-promotable target identity carrying the already-written minimal
`vm_dbg_pc/op/bank/off` seam, or production-order CPU witnesses after the
argument guard, after the pointer guard and after the first shape byte.


## Method decision — 2026-08-03 (reviewer): the VM-debug identity

The attribution stopped honestly at its proof boundary: Link 90 carries
no VM debug capture (the 16 bytes end at `vm_status`; `$8B–$8D` are
padding), the host replay is green, the outer argument guard is
exonerated, and the first real divergence is named — `$D06C–$D06E` read
live on the target, modeled as zero on the host, never initialized by
the ship boot. Two disjoint residues remain, and choosing between them
without a fault PC would be guessing.

**Authorized: the non-promotable VM-debug identity** (the proven
diagnostic-identity pattern): the debug capture compiled in, one
contact, reading in one pass (a) the fault PC/opcode/bank/off that names
the throwing site directly, and (b) a **CPU-side witness of
`$D06C–$D06E`** in the same stopped state — so the same contact
separates both residues *and* tests the inheritance hypothesis. Zero
bytes on the product candidate; standing session rules; the three
production-order witnesses remain the fallback only if the fault PC
alone cannot separate the residues.

If the pointer-geometry inheritance confirms, the fix direction is
already familiar: the pilot arms what it uses — and the host model stops
modeling uninitialized registers as convenient zeros (the synthetic-state
lesson, third appearance).

### VM-debug identity result — bounded First Red (Codex, 2026-08-03)

The non-promotable identity was built and consumed exactly one device
contact.  Its ordinary control Runtime ELF is byte-identical to Link 90
(`dcb415da…`), the Link-90 product image remained unchanged, and the
diagnostic ELF proves CPU reads (and no writes) at `$D06C–$D06E`.  Twelve
overclaim mutations were rejected.  The diagnostic-only LTO layout leaves
8,172 bytes beyond the required 8 KiB runtime stack, 20 bytes below the
product's 8,192-byte post-boot floor; its private link contract therefore
binds 8,160 bytes.  The product wall itself was not changed.

The contact reached `RUNTIME_VM_ERROR=$E3`/`VM_TYPEERROR`, the CPU sampler
ran, and the live VIC bytes were `$05/$06/$07`.  Those bytes fail the
source pointer guard (`D06E != 0`) and remain a strong inheritance witness,
but they do not by themselves prove that execution reached that guard.

The commissioned four-field VM seam did **not** form an atomic fault tuple
under recursive VM execution.  It read bank/off `5:$06E1`
(`m65-sprite-shape`), post-PC `$002A`, and opcode `$3D` (`OP_CALLPRIM`).
A three-byte `OP_CALLPRIM` ending at `$002A` must begin at payload `$0027`;
the bound object contains `$01` there, not `$3D`.  Thus caller identity and
callee/static-window state were mixed by the minimal seam.  The earlier
automatic `ATTRIBUTED` classification was withdrawn before commit.

The honest result is therefore the pre-authorized fallback boundary:
production-order witnesses after the argument guard, after the pointer
guard and after the first shape byte are required.  No second contact,
product fix, product link or promotion was taken under the one-contact
authorization.  The bound receipt is
`c2.3-v1.4-link90-vm-debug-identity-device-receipt.json`.


## Production-order witnesses — authorized 2026-08-03 (reviewer)

The debug-identity contact is accepted at its honest weight: the
CPU-side `$D06C–$D06E` witness (`$05/$06/$07`, latch 1) strongly
supports the inheritance hypothesis — the pointer guard would reject on
`$D06E ≠ 0` — but the VM debug tuple is non-atomic (recursive VM state
mixes caller and callee under the reload-on-return architecture), so
the mechanism stays unproven. That non-atomicity is itself booked as
instrument knowledge: **the VM debug tuple is a hint, never a witness,
whenever recursion is in play.**

**Authorized: the pre-named fallback — one contact, three CPU-side
production-order witnesses**: after the argument guard, after the
pointer guard, after the first shape byte. Each witness is a stamped
RAM write (the proven pattern), read after the stop; their order tells
exactly which stage the execution reached, separating
guard-rejection-on-inherited-geometry from a target-only fault behind
accepted guards. Zero product bytes, Link 90 unchanged, standing rules.

If the pointer guard proves the rejecting stage, the fix commission is
pre-sketched: the pilot arms the sprite-pointer geometry it uses, the
host model stops modeling uninitialized registers as zeros, and the
class closer asserts both.

### Production-order witness result — bounded First Red (Codex, 2026-08-03)
