# 1.6 work plan — the defstruct diagnosis block

Status: **commissioned and phased 2026-08-04** (owner direction choice at
the successor menu after the geometry chain parked).  The phases below make
the charter executable; they authorize diagnosis through Halt 1, not a fix.

## The one sentence

Attribute the reproducible defstruct fail-closed stop to a named
mechanism — attribution first, no fix, no surface promise, and no
relabelling of the guard as the fault (the guard is doing its job).

## The anchor (proven 2026-07-31, quiet conditions)

`(require 'defstruct)` returns `t` after 45 quiet seconds; `(defstruct
point x y)` produces no result for 180 seconds with zero monitor
traffic; the first capture afterwards shows the fail-closed frame.
Link 75's original red frame is thereby real, not a harness artifact.

## Instruments inherited, all proven this era

Sentinel/tag witness discipline (non-zero stamps, tagged values);
the dispatcher opcode-view witness (cannot be skipped by the
divergence it measures); non-promotable diagnostic identities;
buffer-peek context asserts; quiet execution with postcondition reads;
the hang-triggered one-stop runner; independent oracles only.

## Pre-registered suspects (to be proven, never inherited)

1. **The F018B refill-visibility class — now a proven product class
   with a live conviction on the pilot path.** A stale code window
   after a reported-complete refill sends the VM into old bytes; a
   guard catching the resulting illegal state would look exactly like
   this stop. If defstruct's expansion is the first form whose
   compiled body crosses a refill boundary under quiet conditions,
   membership would explain Link 75 end to end. Membership must come
   from a witness, not from the prior (the broaden-once lesson).
2. The persistent-append/C2J machinery under the long `require` load
   (the historical R-1/R-2/R-3 candidates from the Link-75 owner
   decision, still unexhausted).

## Bounds

## Phase A — reconstruct the real execution, host-first

Build one machine-readable execution inventory for the exact sequence

1. cold boot with a CLEAR journal and no Session rows;
2. `(require 'defstruct)` through the real Lisp resolver and real library
   medium;
3. `(defstruct point x y)` with the persistent appends it actually emits.

The historical Link-75 host receipt is input, not sufficient authority: it
explicitly executed an append-shaped model with zero Prim-67 calls and no real
resolver.  The new lane must execute the current Session host runner against
the bound Link-82 carrier/C2D/library artifacts and retain, form by form:

- expanded source form and emitted code object identity;
- persistent-row start/end, generation and C2J transition;
- VM instruction count and the last successful definition/append;
- every code-window identity, payload-PC range and refill crossing;
- the exact expected first opcode at each post-refill cursor.

Two controls are mandatory: `require` alone, and the same `defstruct` sequence
with a direct-memory window lane.  A mutation that omits the prior `require`,
uses the wrong library medium, suppresses one persistent append or silently
flattens the windowed lane must fail.  If the real expansion never crosses a
refill boundary, the F018B membership hypothesis is rejected here and C may
not carry an opcode-view claim merely because the pilot did.  If it does cross,
the inventory fixes the expected source bytes independently of submit-return
or refill metadata.

Exit: one bound host receipt that names the last form, all append transitions
and the complete refill schedule.  No diagnostic ELF or device is touched in
A.

## Phase B — partition every path into fail-closed

Starting from the A trace and the final Link-82 ELF, enumerate every reachable
edge from the measured sequence to the fail-closed store.  The guard remains
the terminal observer, never the blamed operation.  The inventory must cover:

- VM non-OK return and first-error-stamp paths;
- post-refill fetch/dispatch, using the proven dispatcher-side witness rather
  than an in-stream store that stale code can skip;
- persistent append prepare, publish, rollback, C2J validation and phase-owner
  handoff;
- source-less IRQ episode/latch entry after the delivered interrupt masks;
- OOM/GC only if the exact static path can reach it in the measured form.

Design one diagnostic record in ordinary RAM with non-zero per-stage
sentinels and separate tag bytes for every unconstrained value.  No clear value
may also be a legal observation.  The record retains the last two completed
refill views, not just a global “refill happened” bit: cursor, owner, window
base and fetched opcode.  Expected opcodes are derived after the stop from the
bound C2D source and A's schedule, never from completion metadata.  Alongside
that record, retain the first error, phase owner, C2J state, the **first
non-OK** append checkpoint, the tagged second source-less entry, its raw
episode latch and the interrupted return PC.  A completed ordinary append does
not create a failure checkpoint.

The decision table is fixed before C builds anything:

| Outcome | Required stopped-state evidence | Attribution |
|---|---|---|
| R — refill member | tagged dispatcher view; cursor/owner correct; fetched byte differs from bound C2D source | F018B content-visibility class, same mechanism family as the pilot |
| A — append/transaction | every observed refill byte agrees; tagged first non-OK checkpoint, owned phase or non-CLEAR C2J names one prepare/publish/rollback edge | named persistent-append/C2J edge |
| I — interrupt entry | refill and transaction evidence clean; tagged second source-less entry, raw latch exactly 1, `$D019` raster bit clear, `$D01A=1` and return PC name the edge | named interrupt/guard-input edge |
| G — other guarded VM failure | refill and transaction evidence clean; tagged first-error/PC maps to one enumerated non-OK edge | that exact VM/GC/error edge, without widening the claim |

An unset tag names “stage never reached”, not value zero.  If the static graph
admits an outcome outside these four rows, B is red and the device session is
forbidden; the partition is repaired on the desk rather than by adding another
contact later.
