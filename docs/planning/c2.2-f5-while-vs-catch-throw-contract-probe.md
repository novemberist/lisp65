# C2.2 F5 — `while` versus `catch`/`throw`

Status: owner accepted; paper decision only, implementation not authorized
Date: 2026-07-27
Product links: zero
Hardware runs: zero

## Decision

Choose `while` as the single control-flow repair. Defer `catch`/`throw` to a
separately commissioned condition-and-unwind project.

This confirms the direction already approved in the v1.2 scope memo, but on
the C2-lite implementation that now exists rather than on the architecture
that was only projected at the time. The evidence makes the choice stronger,
not weaker.

One terminology correction is binding: `while` is **not** a non-local-exit
primitive. It is structured local iteration. The older planning phrase
“one minimal non-local-exit primitive, either `while` or `catch`/`throw`”
joined two different semantic classes. The committed choice is more
accurately “one control-flow repair”.

## What C2-lite actually provides

The current unwind machinery has one deliberately destructive destination:

1. every error and RUN/STOP source enters `lisp_abort_jump`;
2. that seam calls `c2_product_abort_cleanup`;
3. C2J restores or wipes the incomplete transaction and removes active
   transient suffix records;
4. C `longjmp` returns to the sole `setjmp` at the REPL top level.

The relevant authorities are `src/interrupt.c`, `src/repl.c`,
`src/c2_product_runtime.[ch]` and
`config/c2-nested-append-unwind-contract.json`.

C2J therefore records storage recovery, not a resumable Lisp continuation.
The transient high edge records executable lifetime and directory identity,
not catch tags, value-stack depths or return PCs. The contract also requires
that no authenticated overlay transaction remain active while Lisp bytecode
executes. These properties are exactly right for fail-closed recovery, and
exactly the wrong abstraction to pretend is a user-level catch stack.

## Why `while` fits the machine

Both compilers already lower `dotimes` and `dolist` to the same two bytecode
operations needed by `while`: `JFALSEREL` for the exit edge and `JMPREL` for
the back edge. The VM already executes those operations. A strict

```lisp
(while test form*)
```

can therefore remain a compiler special form:

- evaluate `test` before every iteration;
- terminate on `nil`, continue on every non-`nil` object;
- evaluate the body left-to-right and discard each body value;
- return `nil` after normal termination.

It adds no opcode, resident dispatch arm, root, C2J field or dynamic runtime
state. The loop occupies constant VM and C stack depth. Existing rel8
overflow handling remains fail-closed; the implementation proof must include
that boundary rather than silently inventing a wide branch.

This directly repairs the documented language hole: Dialect V2 can express
only bounded iteration or recursion today, and the redesign removed `do`
while assuming `while` would cover the real uses.

## Why `catch`/`throw` does not fit the existing unwind

A real `catch`/`throw` pair would need new runtime truths:

- a dynamically scoped chain containing an evaluated tag, VM frame, logical
  PC and value-stack depth;
- GC roots for catch tags and thrown values across nested `vm_run_dir` calls;
- precise unwinding to an inner bytecode continuation;
- a distinction between a catchable throw and fatal errors or RUN/STOP;
- parity across both compilers, the evaluator bridge and the VM.

Routing `throw` through the current C2J landing would not implement catch. It
would erase the transient execution context and return to the REPL. Retaining
that context would instead require a second unwind mechanism and resident VM
state. Its capacity and failure surface are unmeasured, and the terminal
geometry makes it unsuitable as a paper-probe passenger.

The existing `error` path consequently remains a fatal top-level abort. This
decision does not advertise it as user-catchable and does not smuggle in a
condition system.

## Contract for a future `while` cut

The later product cut must prove:

1. zero iterations return `nil`;
2. multiple iterations preserve ordered side effects;
3. non-boolean truth is accepted;
4. allocation and GC in both test and body are safe;
5. a long loop has constant stack depth;
6. malformed syntax and branch-range overflow fail closed;
7. device compiler, host compiler, host VM and device VM agree;
8. language, migration and special-form inventories carry the same surface.

It must not add `break`, `continue`, `return-from`, `catch`, `throw`,
`block`, `tagbody`, `go` or condition restarts. If a future product needs
non-local transfer, it returns as a condition-and-unwind design rather than
reusing C2J by analogy.
