# v1.7 native `INIT.L65` pricing

Status: **PASS — priced host-only; implementation is not opened by this
report.**

The winning form is deliberately small: the existing `%repl-banner` object
evaluates `(load "init.l65")` before drawing the banner.  That seam already
runs after the native `setjmp`, after `lisp_toplevel_active`, and after screen
initialization, but before the first `lisp65>` prompt.  Its existing
`if (!aborted)` owner also gives the hook the required once-per-boot behavior:
an init error recovers to the native prompt without immediately retrying the
same broken file.

This keeps the block native-only.  It adds no Comfort dependency, does not
rename either prompt, introduces no named helper, and does not add a resident
state byte.

## Emitted price

The complete resolved product stdlib suite was rebuilt in a temporary host
root with only the candidate banner source substituted.  The accepted A0
world has 352 objects and 15,491 stdlib code bytes; `%repl-banner` is 145
bytes.  The candidate still has 352 objects, totals 15,501 bytes, and emits a
155-byte banner.  The exact Bank-2 price is therefore **10 bytes, zero objects,
zero symbol slots, and zero name bytes**.  The full static plane projects from
46,043 to 46,053 bytes.  Under the composed A0 map it remains disjoint, leaves
1,229 bytes before the first mapped owner, and leaves the existing 16,431-byte
largest contiguous hole unchanged.

The string `init.l65` is a bytecode literal, not a name-pool symbol.  The
post-descope capacity therefore remains **105 free slots / 1,413 free name
bytes**, against the standing 32/384 floor.

Three target micro-prototypes price the necessary resident seam conversions:

| Seam | Predecessor | Candidate |
|---|---:|---:|
| Banner VM failure | 41 B | 16 B |
| Stream stops at first VM failure | 49 B | 56 B |
| Found-but-unloadable source reports `LOAD_OPEN` | 25 B | 27 B |
| **Total** | **115 B** | **99 B** |

The isolated forecast is −16 bytes.  It is not banked as credit: the
implementation bar is final-linked resident delta **≤ 0**.  Forecasts are
floors, never pins.

## Failure and absence semantics

The delivered Lisp `load` already supplies the desired absence rule: an absent
directory name returns `NIL`, so the banner continues silently.  Three small
conversions are required for the failure half:

1. the current banner VM-error branch must enter the normal numeric
   `lisp_abort_code` path instead of returning from `repl()`;
2. `load_source_stream` must stop immediately after the first VM error, so a
   later form cannot reset and mask it;
3. a file that was found but could not be loaded must raise the existing
   `LISP65_ERR_LOAD_OPEN` (`18`) rather than becoming an indistinguishable
   `NIL`.

The executable boot model covers absent, valid, reader-error, VM-error,
load-error, and RUN/STOP outcomes.  Every error crosses the installed recovery
and ends at exactly one live native `lisp65>` prompt.  Mutations reject an
early hook, missing-as-error, return-from-REPL, post-abort retry, and a later
form masking the first failure.

## External publication boundary

The mandatory Block-3 lesson is exercised against the exact final A0 static
plane, not a synthetic empty directory.  The fixture seeds generation 1 with
6 images, 755 entries, 2,929 resolutions, 352 roots, and 46,043 code bytes;
then it appends:

```lisp
(defun %init-external-proof () (list 17 65))
```

The append publishes handle 755 and advances the real geometry to 7 images,
756 entries, 2,930 resolutions, 352 roots, and 46,059 code bytes.  Execution
returns `(17 65)` in five VM steps; the recorded tail call resolves the new
definition's `list` reference to the final static owner.  Removing the append
or removing that static owner both fail.  This is the publication/resolution
boundary the earlier Block-3 fixture did not compose.

## Card boundary

The pricing used zero WPLTOs, product links, media builds, and device contacts.
An implementation card, if reviewed open, must prove the final linked
resident delta, the one-attempt boot ordering, every failure outcome, the
candidate-owned external append fixture, the composed Bank-2 map, and a full
double-green `check-source` closure.  Hardware acceptance remains one later
owner-held contact.  Nothing in this result reopens Comfort, Block 3, or the
canonical prompt swap.
