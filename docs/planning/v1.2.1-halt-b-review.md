## What the release says

The proposed [v1.2.1 release notes](../releases/1.2.1.md) cover:

- the native `while` form, including the user-visible cost of a backward edge
  that crosses a streamed code-window boundary;
- `random` and `random-seed`, including reproducible seeding and the explicit
  “not cryptographic” boundary;
- fixed-argument direct calls, measured at zero frames in the accepted G5
  case;
- hardened ownership of Ethernet, Auto-IEC, and audio-DMA interrupts; and
- the repeated-`require` fast path.

The Known-Issues delta is written as user guidance:

- do not use an interrupt-generating cartridge while lisp65 is running;
- preserve the exact form and preceding steps if the intermittent post-GC
  out-of-memory symptom appears;
- an undefined-function error can print a shortened name even though the
  error itself is valid; and
- `defstruct` and dynamic package freight are not delivered in v1.2.1.

## Clean-build result

Two independent, fresh, detached clones of that exact candidate ran:

```text
make --no-print-directory workbench-product
```

The environments differed in hash seed, source epoch, and timezone. Both
builds produced the exact promoted 19-role product set:

`2115b955512a3b794f68d5f2a1d160708cb89184735b7a0984a7cfc61c38f63f`

No private evidence file was a build input. Both builds reported product build
ID `ee357d31` and profile build ID `1b242dd9`.

The clean-build qualification caught and closed four public-tooling gaps
before turning green:

1. machine-readable wording lost during the user-facing Known-Issues rewrite;
2. an interrupt gate that still required a private owner packet;
3. the public entry point still selecting the historical canonical-product
   path instead of the v1.2.1 single-emitter path; and
4. the `random` gate still using a private Link-76 receipt as capacity input.

All four are source/build-gate fixes. No promoted product byte changed, and no
partial result from a failed clone was inherited.
