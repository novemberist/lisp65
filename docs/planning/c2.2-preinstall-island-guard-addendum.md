# C2.2 pre-installation Island guard addendum

Status: owner-authorized bounded host/lifecycle and capacity probe; no successor product link authorized.

## Invariant

The resident Island at `$1800..$1fff` is untrusted predecessor state until the boot installer has copied the current generated image, verified its destination CRC, and published `RTOV_ISLAND_READY`. The installer may write and verify that destination as part of installation, but no Bank-0 installer path may execute Island code or consume Island-owned data before publication.

Transaction authentication therefore has one resident discriminator: an inactive transaction returns without touching the Island; an active transaction before READY fails closed; only an active transaction after READY may cross the single `rtov_transaction_context` seam. Both catalog-cache lookup and publication obey the same guard.

## Permanent proof

The host lifecycle fixture begins with the exact 1,291-byte Link-30 Island that was observed on hardware, runs the current installer, and proves zero transaction-context calls before READY plus an exact current-image result afterward. A static gate computes the Bank-0 closure reachable from `vm_runtime_overlay_install_island`, rejects every unguarded control edge or consuming data reference into the Island, and proves the guarded edges plus the sole complete-destination zero-wipe form against source and linked machine shape. Mutations cover an unguarded edge, consuming Island data, every zero-wipe tuple dimension, inactive/stale, active/not-ready, and active/ready behavior.

This is the Island analogue of the `$E000` pre-ownership rule: memory that a boot phase is still manufacturing cannot be treated as infrastructure.

## Manufacturing-write clarification (2026-07-21)

The owner authorized one narrow correction after the Handoff-reanchor WPLTO
exposed a contradiction between this invariant and its relocation gate. A
pre-READY reference is not automatically consumption: the named installer
must erase arbitrary predecessor bytes before installation and wipe the full
destination on either failure path. The sole permitted linked form is a
complete LO/HI address pair for `$1800`, addend zero, feeding a zero-valued,
2,048-byte call to `__memset` from `vm_runtime_overlay_install_island`.

Every dimension is closed: a different source, target, addend, fill byte,
length or callee; an incomplete pair; an unmatched extra reference; any read;
or any unguarded control edge remains a hard error. The current WPLTO machine
shape contains exactly three such wipes (initial erase plus two compiled
failure paths). This is a classification correction against an already
permitted manufacturing action, not a relaxation of pre-READY ownership.

The correction may be replayed only against the SHA-bound, read-only ELF
`c82b9bd0…`. It authorizes no compiler, linker, second WPLTO, product link or
hardware run.
