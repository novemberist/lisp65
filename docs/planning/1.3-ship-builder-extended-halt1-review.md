## First-card attribution and historical recommendation

The exact noinit assertion is doing useful work: a smaller compiler stack is
still a different overlay VMA derivation and cannot be accepted silently.
Padding compiler-owned `.noinit` would merely hide the changed call graph and
is not recommended.

The recommendation at that point was to authorize **one new card** that
preserves one backspace truth while forcing its small implementation to remain
inline at the two screen call sites. The card must prove the inherited six-byte
static stack, the `$C354` overlay floor, destructive DEL in both Workbench and
Ship Runtime, and all standing walls. It gets one WPLTO; failure returns to the
owner without another shape experiment.

That one correction card has now been consumed and rejected. The conservative
alternative remains to remove Workbench `read-line` from v1.3
(and therefore from the advertised common surface) while retaining Ship-only
input. That would satisfy geometry but weaken the owner-approved product
contract and the first-public-release story.

The sole authorized WPLTO is nevertheless red. The linked native leaf is 105

## Owner round after the third red — decided 2026-08-01

Three cards, three different compiler stack profiles (3/4/12 B against
the contracted 6): the class is structural, not card-solvable. The
C-driver route for DEL is abandoned — **not** the freight.

**Commissioned: `read-line` entirely in Bank-2 Lisp.** A `key-event`
loop with echo and DEL over the existing screen primitives — the
existence proof is the IDE, which has edited lines exactly this way on
hardware for months. Zero C bytes, zero WPLTO exposure, the freight
stays complete in v1.3.0 for both runtimes. Conditions: the DEL-semantics
suite (14 mutations) re-targets the Lisp implementation; the A2
allocation gate prices its per-key cells like every editor path; RUN/STOP
aborts via the standing poll discipline; one host card, and if it fails,
the automatic fallback is deferral (Codex's option 1) without a further
round. **Layering clarification (owner concern, 2026-08-01): `read-line` lives
in the base composition, not in the IDE library.** It is a small
standalone base-library unit beside `random` and the `q` family,
composed exclusively from base primitives (`key-event`, the screen
write/cursor primitives) — it imports nothing from `ide-*.lisp` and
shares no code with the editor. The IDE was the existence proof that
line editing works in Lisp on this hardware, not the home. Consequence
check: the ship tree-shaker must keep `read-line` in every shipped
image while still dropping the IDE libraries — the interactive sample
proves exactly this separation on the device.

The three-method geometry table is booked as the opening evidence
of the successor-menu stack/overlay-ownership candidate. The 105-byte
assembler leaf and its 17/17 mutation suite are retained as shelf
evidence, not shipped.


## Phase-E documentation obligations — owner-directed 2026-08-01

Documentation only; zero freight delta. Binding on the release phase:

1. **The base string library enters the public reference.** Delivered but
   undocumented today: `string-trim`, `string-left-trim`,
   `string-right-trim`, `string-upcase`, `string-downcase`,
   `char-upcase`, `char-downcase`, `string=`, `string<`, `string-equal`,
   `string-prefix-p`, `string-suffix-p`, `string-append`, `substring`,
   `string->list`, `list->string`. The surface-delivery parity binding
   grows accordingly — an advertised release must not hide working
   vocabulary.
2. **The input section carries the parse recipe**: `read-line` →
   `read-from-string` → `numberp` guard (garbage input reads as a
   symbol and is caught; syntactically broken input takes the reader
   error path — stated plainly), plus the note that `read-from-string`
   reads any Lisp form, so list-shaped commands are free.
3. **A language-forms box beside the function reference**: `let`,
   `let*`, local `setq`, parameters/`&rest`, `while`, `dotimes`,
   `dolist`, `when`, `unless`, `cond`, `case`, `lambda`/closures,
   `defun`, `defmacro` — special forms are compiler-lowered and absent
   from the bound-name list, and a newcomer must not conclude the
   language lacks `let` by reading the function table.

4. **The character model, stated plainly** (owner round 2026-08-01):
   characters are fixnum codes — there is no character type and no
   `#\` literal syntax (the reader knows `#'` only). Codes come from
   `string-ref` or plain numbers; comparison is `=`, arithmetic works
   directly; `char-upcase`/`char-downcase` are fixnum→fixnum. One short
   paragraph inside the language-forms box.
5. **Higher-order functions and strings**: `every`/`some`/`filter`/
   `mapcar`/`reduce` walk cons lists, not strings — the bridge is the
   `string->list` / `list->string` round trip (one cell per character;
   fine for input lines, mind long strings), while substring questions
   use the direct string family (`search`, prefix/suffix, `string-equal`)
   without conversion. Recipe example in the input section.

Booked to the successor menu, not this block: `capitalize` and
`string-split` (four-liners on the existing base; comfort track beside
