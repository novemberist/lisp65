# lisp65 1.2 scope memo

Status: decision memo for owner review, 2026-07-17. This document fixes the
recommended scope and ordering after the Wave 1 seal. It authorizes no product
implementation. Every accepted item still requires its own contract, probe,
capacity authorization, product link and acceptance cycle.

## Decision summary

Recommend a deliberately narrow 1.2 architecture release:

1. **C2 direct Attic execution leads and is non-deferrable.** It is the named
   cure for the dated C1 definition-to-first-call limitation. The exception
   may not roll into another release without a new owner decision.
2. **The on-device ship builder moves to 1.3.** The product promise remains;
   only the delivery version changes. C2 consumes the 1.2 architecture and
   hardware budget; the verified R6 host packer supplies reusable packaging
   evidence, although it is not itself a user application builder.
3. **Restore `while` as the one 1.2 control-flow mechanism.** The redesign
   explicitly relied on `while` when deleting `do`, but the form never reached
   the migration contract. `catch`/`throw` and general user-visible condition
   handling remain outside this release.
4. **Deliver `(show 'name)` after C2 as the first Interlisp-style metadata
   dividend.** It is display-only: location registry, scanner, drift check and
   source display; no splice-back or dual-file transaction.
5. **Revalidate the BASIC 65 parity-library design in 1.2, but do not commit a
   parity module to this release.** The `m65-hw` pilot remains first in line
   after the revalidation and the ship-builder ordering, unless the owner
   explicitly reverses the standing "users can publish before parity grows"
   product rule.

Items 2 and 3 change earlier planning assumptions and therefore require
explicit owner approval. Items 1, 4 and 5 schedule already commissioned work.

## Why C2 must lead

C1 bought 9,244 B of net resident relief by loading, committing and retiring a
9,573-B compiler tier. The remaining delay is not shelf transfer or compile
time; it is the generic L65M materialization of roughly 9.4 KiB, hundreds of
patches and more than one hundred directory entries after a definition forces
retirement. Three bounded fast-cycle alternatives were measured and rejected
on independent hard budgets:

- independent installation: fixed-overlay overlap;
- permanently resident compiler: 643 B below the EXT floor;
- identity-bound restore: commit/lifetime slice overruns and a runtime-bank
  deficit.

C2 removes the materialization step rather than optimizing it again. Shelf
code executes from Attic, while mutable session bindings remain outside the
reset-persistent image. This is the only accepted direction that attacks both
the 1.9-s cure and the long-term library-capacity architecture.

The historical C2 ceiling was 19,228 B for IDE+IDEX+M65D. That number predates
the final Wave 1 containers and must be remeasured at C2 start; it is a scale
indicator, not an authorization estimate.

## Delegated diagnostic procedure (owner-approved 2026-07-21)

The following delegation classes apply from 2026-07-21 onward. They change
the reporting cadence, not the evidence standard: SHA binding, read-only
evidence, mutation coverage, first-red handling, and claim hygiene remain in
force in every class.

### Class A — autonomous, bundled report

Gate-, proof-model-, and harness-only corrections, plus pure replays against
read-only artifacts, may proceed autonomously when they create no product
bytes, have no capacity effect, invoke neither compiler nor product linker,
and require no hardware. For this class the one-attempt rule means: correct
and replay until green, or stop as soon as a product question appears. Report
the completed chain as one result with all receipts.

### Class B — autonomous within the commissioned diagnostic budget

Non-promotable diagnostic links and diagnostic hardware runs may proceed
autonomously only inside an already commissioned diagnostic question. Every
bound floor and cap must remain untouched or improve. A commission permits at
most three autonomous diagnostic cycles; after the third cycle, return to
review regardless of outcome. Announce each hardware need to Alex before the
run, and report each hardware run in the evidence chain. Diagnostic artifacts
must remain unmistakably non-promotable.

The current commission is **E2f / hold before wipe**, for at most three Class-B
cycles. Gate and harness adjustments encountered on its path are Class A.

### Class C — review or owner decision required

Promotable product links; contract, anchor, floor, or cap changes; format
evolution; freight triage; KERNAL-window questions; promotion; acceptance
chains; and every finding that changes product semantics remain subject to
explicit review or owner approval.

### Escalation rule

If a Class-A or Class-B activity unexpectedly touches product bytes, consumes
a bound floor, challenges a cap, or raises a contract or product-semantics
question, stop immediately and return it as Class C. When classification is
uncertain, use the higher class.

### Temporary closure delegation and C1 endpoint (owner-approved 2026-07-26)

Until the acceptance chain starts, one additional standard response is
delegated: a fully attributed one-line-class product correction may be
implemented and carried into the next link without an intervening review when
its complete product delta is at most 32 bytes, every relevant gate and
negative mutation is fresh, and the resulting capacity map is green. The
cause must be unambiguous; this delegation does not cover a new contract,
architecture, format, anchor, floor, cap, feature or product-semantics
decision. The completed link and all receipts are reported together. Any
ambiguity or larger effect remains Class C.

The next C1 hardware appointment is one bundled session, not one test per
appointment. While green it runs, in order:

1. the `defun` smoke;
2. Cutpoint 3, including physical Freezer return with **F3**;
3. Cutpoint 4;
4. the already commissioned acceptance measurement rows, without scheduling
   another device appointment.

The non-promotable carrier has all applicable hold recipes and passive
Slot-39 witnesses loaded before the session. A failure may therefore be
captured during that same appointment; it does not create a separate
instrumentation appointment.

C1 also has a terminal disposition. If the bundled session encounters a new
error class and therefore cannot close C1, no further C1 pursuit is
authorized. Cutpoints 1 and 2 and the idle-Freezer result remain PROVEN;
“Freezer during an active definition” is recorded as a documented product
restriction and deferred to C2.3 under the matrix disposition method. The
matrix gate then falls with C1 documented rather than PROVEN, and the
acceptance chain starts. Thus the bundled appointment ends in exactly one of
two states: C1-PROVEN, or C1-documented/C2.3-deferred; neither state permits
another diagnostic cycle before the chain.

### Terminal CRC-convergence floor break (owner-delegated 2026-07-21)

The `$e000` floor is reduced exactly once from 115 to **63 bytes**. The
52-byte debit is purpose-bound to the one shared CRC-convergence retry driver
and its necessary contractual call seam. The measured 104-byte resident
growth must be attributed against exactly 52 bytes of window debit, 19 bytes
of ordinary-text room and the 33-byte fixed-block pocket; none of those
allocations is general capacity.

The 63-byte floor has a literal self-destruction clause: it has no third
negotiation. Any later resident or window requirement that would cross it
selects **C2-lite automatically**, without a review request, exception or
owner escalation. A qualifying WPLTO probe must carry the serial Island
00/01 split, the cold-helper move and the slice-local Boot barriers, and must
run every ownership, data-reference, facade and KERNAL-freedom gate afresh.
Link 36 remains a separate Class-C decision.

The resulting non-promotable WPLTO probe passed with the window at exactly
the 63-B floor. Its other measured headrooms are 2 B ordinary text, 129 B
ordinary BSS, 2 B in the fixed retry pocket, 267 B in the Resident Island and
21 B in the tightest runtime slice. All ownership, data-reference, facade,
CRC and KERNAL-freedom gates passed. This is placement evidence only; it
authorizes neither Link 36 nor hardware execution.

The one authorized Link-36 attempt stopped in the Resident-Island seed link:
the real `.text` grew 10 B beyond the green terminal probe and overlapped the
fixed `$b4a3` handoff by 8 B. No product closure and no hardware run occurred.
This resident demand activates the clause above, so **C2-lite is now the
automatic successor**. Link 36 has no retry, and neither the 63-B floor nor
the handoff anchor returns for negotiation.

## C2 block split and acceptance

C2 is too large for one undifferentiated implementation block. Use four
promotion boundaries:

### C2.0 — address and identity contract

- Define the extended executable-code address independently of host pointer
  layout and the current 8-bit-bank/16-bit-offset directory encoding.
- Keep immutable Attic code bytes separate from mutable literal resolutions,
  export cells and session object identities.
- Specify reset: Attic survives; every mutable resolution is rebuilt or
  invalidated. Reusing a stale object reference is impossible by construction.
- Treat physical MEGA65 addresses as an explicit non-pointer domain: 28-bit
  DMA/Attic endpoints remain `uint32_t` values or encoded DMA-list bytes and
  never pass through the target's 16-bit `uintptr_t`.
- Cover direct call, `funcall`, `apply`, closures, tail calls, entry refs,
  late-bound exports, diagnostic maps, host VM and disassembler.
- Decide format evolution and strict decoder rules before emitting anything.
- **Design law from the failed 2026-07-18 L65S-v4 probe: C2 must be
  substitutive, never additive.** The v4 device decoder failed at +84 B
  over the fixed VMA and a 3,326-B stage against the 1,792-B slice cap —
  seeded *beside* the existing machinery, as any additive attempt must be.
  The space for the C2 decoder comes from retiring the L65M materializer
  it replaces; C2.0 therefore plans a staged swap with a defined interim
  state, not a parallel path with a switchover. Inherited assets: the
  host-validated v4 layout model (five containers reconstructed
  byte-identically, strict version/mutation matrix passed, 458 KB
  four-role envelope) and the receipt-confirmed metadata split numbers
  (55.6% metadata, 27,744 B load-time literal machinery); constraint
  inherited from the metadata audit: off-catalog metadata needs an
  identity-bound reset-persistent source — D81-only side files would
  regress the one-swap media contract.

Exit: format/identity contract, negative fixtures for stale reset bindings,
and a prototype that executes one SHA-bound anonymous helper from Attic in all
four engines. No product promotion.

and added zero-length and live-session hot-restage rejection. The owner

### C2.1 — read-only execution prototype

- Execute a small shelf container directly without mutating its code image.
- Prove code-window refill/DMA behavior, GC roots, nested calls and interrupt/
  reset boundaries.
- Report Bank 0, EXT, fixed overlay, runtime-overlay bank, resident island and
  installer slice. Zero-headroom resources may not be debited by assumption.

Exit: four-engine differential, reset/restage matrix, real link and bounded
hardware smoke. If the fixed overlay remains unable to fund the address path,
C2 stops for a layout decision rather than borrowing from the 1.1-L budget.

**Commissioned input to that layout decision (owner, 2026-07-17): a
read-only KERNAL residency audit.** The old "evict KERNAL/BASIC" lever was
rejected as a RAM lever and stays rejected as one (ROM banks are
reset-restaged by HYPPO — strictly worse than Attic for data). But the
scarcity has moved to 16-bit *address space*, and unmapping the KERNAL
window (~8 KB at the top of the CPU map) is the largest single relief
available in exactly that currency. The audit must deliver: (a) the
complete list of remaining KERNAL calls **including passive dependencies —
discovered 2026-07-18: the RUN/STOP evaluation break reads the
KERNAL-IRQ-maintained STKEY flag ($91) in `lisp_poll()`; unmapping the
KERNAL silently kills the break key unless it is re-sourced from the typed
queue/keyboard matrix** (expected active core: GETIN — which L-full's
typed-event driver replaces anyway, possibly making "queue driver + KERNAL
unmap" one self-funding block that resolves the L-full overlay deadlock); (b) what an unmap frees, precisely, in the
address map; (c) the duties we would assume (IRQ/NMI vectors, the frame
source used by latency measurement); (d) touched HYPPO/Freezer contracts;
(e) boot/reset interplay (boot needs BASIC/KERNAL, eviction is post-boot,
reset restores ROM — consistent with the reset doctrine). Findings feed
C2.1's layout decision and the wave-3 feasibility note.

**Audit delivered 2026-07-19:** `c2.0-kernal-residency-audit.md` and its
machine-generated receipt bind the current product ELF: one CRT CHROUT, four
GETIN calls and passive STKEY `$91`; no product IRQ/NMI handler exists. The
exact opportunity is 8,192 bytes of 16-bit address space and zero physical RAM.
The audit recommends one inseparable candidate block — typed event queue,
RUN/STOP source, owned IRQ/NMI state and post-boot unmap — but authorizes none
of it before the C2.1 layout decision.

### C2.3 — cure and product acceptance

The dated exception retires only if:

- definition → first call is measured separately from harness/transport time;
- a numeric interactivity limit is owner-pinned before the acceptance run
  (recommended ceiling: 15 frames / 300 ms on the reference machine, with
  warm calls remaining at or below the existing 10-frame baseline);
- a repeated definition/call session shows no growth or leak;
- the value is reported as a real performance pass, not a renewed exception;

**Named restart freight inherited from 1.1 (owner decision 2026-07-18).**
`restart-repl` is a C2.3 feature, not a deferred wish-list item. C2.0 supplies

hardware session and requires a fresh banner and usable REPL after each call,
no stack/symbol/directory/shelf leak, unchanged code identity, and unchanged

architectures (platform reset, CRT re-entry/invalid Bank-7 stash, and resident

- `tests/bytecode/dialect-v2/evidence/architecture-blocks/v11-restart-repl-self-restart-probe-receipt.json`
- `tests/bytecode/dialect-v2/evidence/architecture-blocks/v11-restart-repl-attic-recovery-probe-receipt.json`

The C2 implementation must use the immutable/mutable split; it may not revive
one of those whole-session mechanisms under a new name.

If C2 cannot pass the owner-pinned cure limit, 1.2 does not silently ship with
the C1 exception. It returns for an explicit product-scope decision.

## Control-flow repair: choose `while`, not `catch`/`throw`

The two candidates are not semantically equivalent:

- `while` is a local iterative special form. It directly repairs the missing
  redesign target and permits unbounded iteration without recursive stack
  growth.
- `catch`/`throw` is non-local transfer. It helps user-level condition
  handling, but does not itself provide a constant-stack loop without an
  additional pinned-TCO/local-recursion design.

For 1.2, choose the smaller truth repair: one `while` special form with strict
syntax, ordinary lexical/body semantics and no second exit mechanism. It is
designed after the 1.1-G `error` result is known, but it does not pretend to
turn `error` into a user-catchable condition system. `catch`/`throw`,
`block`/`return-from`, `tagbody`/`go` and condition restarts remain out.

Required proof: zero-iteration, multi-iteration, side effects, GC in test/body,
non-boolean truth, malformed syntax, four-engine parity and constant stack
depth across a long loop. The migration contract and language reference are
generated/gated in both directions so this special-form loss cannot recur.

## Early Interlisp dividend: `(show 'name)`

`show` is intentionally staged before editable definitions:

1. a definition-location registry records symbol → file + top-level-form
   position for user source and shelf metadata;
2. the 1.1-H S-expression scanner revalidates that the position still holds
   the named definition, rescanning or failing closed on drift;
3. `(show 'name)` displays the bounded source form without modifying it.

This is useful on its own, exercises the metadata/scanner seam, and moves the
normal 8-bit workflow toward named definitions rather than whole-file editing.
It also de-risks later `(edit 'name)`, `remove-def`, `copy-def` and `move-def`
without committing those write paths to 1.2.

Dependencies: the 1.1-G metadata index and 1.1-H scanner must be sealed first.
`show` follows C2 product stabilization so it cannot dilute the cure schedule.
It is a shelf/IDE feature: no new resident metadata and no fixed-overlay debit.

## BASIC 65 parity revalidation

The 2026-07-06 design remains valuable but its assumptions are obsolete in
five places. The 1.2 revalidation must replace them with measured facts:

| Old assumption | Revalidation input |
| --- | --- |
| resident or disk-loaded libraries | Attic shelf plus C2 direct execution |
| no first-class byte carrier | 1.1-E buffer |
| bit/word helpers deferred | C2.2 carries `logand`/`logior`/`logxor`/`ash`; re-evaluate `peekw`/`pokew` after that delivery |
| timer hook deferred | C2 scheduler boundary; no 1.1 prompt-only substitute |
| GETIN-centric input | final L-lite/L-full split and typed-event availability |

Deliver one English revalidation document containing a revised module graph,
capability matrix, capacity model, fidelity tags and pilot contract. Preserve
`m65-hw` as P1 and reprice its register/EDMA surface; do not inherit stale
28-bit-flat-access or Bank-4 assumptions from the old draft.

No parity module is promised for the 1.2 binary by this memo. That keeps the
standing product order honest: a redistributable on-device ship path precedes
ecosystem breadth. The revalidation may run in parallel after C2.1 because it
is read-only; its pilot waits for the ship-builder version decision.

## Ship builder: defer implementation, preserve the promise

The ship builder remains a required product capability:

```lisp
(ship "program" :entry 'main)
```

It will eventually create a standalone bootable D81 containing the stager,
redistributable runtime core, tree-shaken closure libraries and user FASL.
Nothing in this memo weakens that promise.

Recommend moving implementation to **1.3** because:

- C2 is release-blocking by dated contract; the ship builder is not;
- C2 changes code addresses, relocation and the shelf model that the builder
  would otherwise have to encode twice;
- 1.1-G metadata and C2's immutable/mutable split improve tree shaking and
  eliminate a throwaway pack format;
- the existing R6 host packer already proves deterministic product D81 and
  manifest mechanics that the future builder can reuse; it is not presented
  as a user application builder;
- no current user program is known to be blocked from distribution by the
  absence of the on-device front end.
