# C2.2 transient-handle contract probe

Status: **owner-authorized bounded contract/design probe; no product work authorized**

Date: 2026-07-20
Machine-readable contract: `config/c2-transient-handle-contract.json`

## Why the first placement was red

The first nested-append placement probe kept physical C2D high-tail ordinals
as callable handles.  The hot entry path therefore needed a second locator to
decide whether an ordinal belonged to the persistent prefix or one of up to
four active transient image intervals.  Even the smallest transported split
grew the closed `$e000` window by 126 bytes.

The two C2D allocation fronts already contain a cheaper handle contract.  A
persistent entry grows from physical and logical index zero.  A transient
entry grows from physical index 2047 but receives its 12-bit BCODE index from
4095 downward.  The domains are disjoint, and the translation for every
transient handle is the constant `logical - 2048`.

## C2D-v5 visibility marker

C2D-v4 has not shipped.  C2D-v5 therefore replaces the header's
`transient_depth_u16` with `transient_handle_watermark_u16` without changing
the 48-byte header or any record width.  The inactive value is 4096.  An
active value lies in 2048…4095 and makes exactly that value through 4095
callable as transient handles.

Depth is not a second counter.  Cold publication, removal, GC and unwind code
derive it from the contiguous source-kind-2 image records descending from
slot 63, with a hard maximum of four.  The physical high entry front is
`watermark - 2048`; the active transient count is `4096 - watermark`.

Publication writes and verifies bytes, image records, entry records, reverse
edges and generation first, then publishes the watermark last inside the
existing non-GC-interruptible publication seam.  Removal raises the watermark
first and wipes afterwards.  Restage writes 4096 before changing generation.
Thus an old handle dies before its old bytes do.

The format version advance is free only because no C2D-v4 product has shipped.
After a seal, the same change would require migration.

## One hot path

`BCODE_IDX` is the type boundary and proves that the incoming value is in the
12-bit range.  The normalizer performs one low/high comparison:

- below 2048, require the persistent count and leave the ordinal unchanged;
- at or above 2048, require the transient watermark and subtract 2048;
- reject the hole between both live fronts.

The result enters the existing `c2_entry_records` path.  There is no tail
scan, transported locator or second materialization path.  Immutable
directory/image topology is validated at stage/publication and cannot reach
the hot path in malformed form; the hot path does not repeatedly re-prove
that invariant.

The meet rule is exact: `persistent_count + transient_count <= 2048`.
Equality is legal.  One further entry is rejected before the unwind journal
or any target byte changes.

## Proof and capacity boundary

The bounded probe must cover nested allocation, pop, abort, restage, holes,
malformed watermarks, source-record contiguity and both sides of the exact
collision edge.  In particular, an inner handle becomes invalid immediately
when its watermark is raised, while an outer handle remains valid.

The target-shaped size comparison is a projection, not a product link.  It
must show:

- `$e000` delta at most zero; the window remains closed to new tenants;
- the normalizer and the already-priced abort facade fit the 109-byte Island
  headroom;
- no Bank-0 BSS debit and no new runtime lookup slice;
- every existing frozen budget explicitly.

The GC high-edge fallback still projects 96 instead of 18 32-byte reads per
collection.  That is capacity-neutral but not performance-accepted.  The
next hardware presmoke must measure GC separately.

Even a green result authorizes no implementation or link.  Directly after
this probe, before any successor link, the commissioned cross-invariant matrix
gets its B2, E1, C2, B5 and D1 quick pass against this stable contract.
