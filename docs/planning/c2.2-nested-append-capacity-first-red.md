# C2.2 nested-append capacity and placement first red

Status: **first red at the closed `$e000` window; product unchanged**

Date: 2026-07-20
Receipt: `tests/bytecode/dialect-v2/evidence/architecture-blocks/c2.2-nested-append-capacity-placement-first-red-receipt.json`

The owner-authorized product-shaped sizing probe compiled one isolated
llvm-mos target object and performed no Resident-Island seed link, product
closure link or hardware execution. Link 32 remains the bound product
baseline (`189548ea…`).

The persistent directory path can keep its two existing DMA reads. A
transported Tail locator nevertheless needs a 126-byte resident range branch
and call context; the locator itself is 480 bytes and fits a new Session
slice. The direct all-resident form would cost 290 bytes. Both violate the
explicit `$e000` rule: delta must be exactly zero and the remaining 386 bytes
are closed contingency, not tenant space. The probe therefore stopped before
implementation.

The other three named costs have viable projected homes:

- rewriting the install lifetime from execute-inside-transaction to serial
  publish/run/remove is 9 target bytes smaller than the same-toolchain
  baseline;
- longjmp restoration is a 709-byte Session slice plus a 13-byte Island
  facade and a projected three-byte Bank-0 call site;
- the fixed unwind journal consumes 64 bytes at its contracted Bank-5
  location and no ordinary C BSS;
- the zero-new-walker GC variant reuses the existing 32-byte B2 block loop.
  While a transient is active it spans all 1,536 root slots: 96 block reads
  instead of 18 for Link 32, plus 1,253 zero-or-live mark inputs. This is a
  transport-count result, not a latency acceptance. The exact-interval walker
  costs 784 bytes and has no legal always-available residence today.

With two new Session slices, projected runtime-bank use is 50,373 bytes
(15,163 bytes free). Bank-0 text projects to 16 bytes free, ordinary BSS stays
at 19 bytes, and the Island projects to 96 bytes free. None of these green
projections overrides the first red.

Review must choose a structural answer before any implementation: reclaim at
least 126 bytes inside the existing `$e000` entry-record closure, change the
transient-handle contract so no resident branch is needed, or explicitly
reopen the closed contingency. The last option is currently forbidden by the
authorization that commissioned this probe.
