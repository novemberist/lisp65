# C2.0 address, identity and reset contract

Status: **owner-approved; separate C2.1 proof target authorized**

Date: 2026-07-19
Machine-readable contract: `config/c2-address-identity-contract.json`

This document turns the C2 design dossier into an implementable boundary. All
five review decisions, including the 3/3/3 freight order, were owner-approved
on 2026-07-19. It authorizes the separate internal C2.1 proof target, not a
product change, product claim or capacity debit.

The exact local metadata envelope in
`c2.0-metadata-envelope-addendum.md` was owner-approved on 2026-07-19 before
the first C2.1 image. C2.1 must use that envelope; no proof-only substitute is
permitted.

## Outcome first

C2 keeps the existing Lisp-level `BCODE` immediate as a small session-local
callable. It stops treating that value as an indirect spelling of a physical
bank/offset. The directory maps it to an identity-bound entry in an immutable
Attic image, and the VM refills its hot code window from that entry by DMA.

Executable bytes are never patched. Literal values, local entry resolutions,
exports and late-bound function cells are rebuilt in a separate mutable plane
for each session. Reset or restage invalidates that entire plane before a new
callable can be published.

The product transition is substitutive:

```text
v1.1 product                 C2.0/C2.1 proof                C2.2 product cut
L65S-v3 + L65M materializer  separate v4 direct target     v4 direct decoder
          |                          |                              |
          +--- no shared product ---+--- no dual decoder ----------+
```

C2.1 therefore proves the path in an internal target. C2.2 converts the whole
shipped closure and removes the old materializer in the same product identity.
Rollback restores the complete prior artifact set; it never creates a mixed
format product.

## 1. Three address domains

### 1.1 Lisp callable: `BCODE`

The current raw object range `$c000..$dffe` remains a 12-bit directory index
(0–4095). It is a logical, session-local handle. It is not a bank number, a
pointer or an Attic address.

This preserves `eq`, closures and the public function-designator behavior. It
also means stale callables are rejected structurally: a restage is a new
session, and heap, directory and resolution tables are cleared before the new
directory is published. No Lisp object from the prior generation survives.

### 1.2 Persisted source address: `C2SourceAddress`

An address inside the staged shelf is encoded as:

```text
region-id:u8 | offset:u24 little-endian
```

The offset is relative to the staged shelf base `$08100000`; the current
contract admits offsets through `$6fffff` (7,340,031), matching the inherited
v4 envelope. A physical endpoint is computed only at the DMA seam as a
`uint32_t`, checked for 28-bit overflow, then written bytewise into the DMA
list.

It is forbidden to pass this value through the target's 16-bit `uintptr_t`, to
store it in an `obj`, or to publish it without shelf identity and session
generation.

### 1.3 Runtime directory address

The runtime directory maps a `BCODE` index to:

- image slot and entry ordinal;
- code length;
- base of the session literal-resolution table;
- current session generation.

The directory does not carry a raw physical address. The image slot selects a
verified catalog record whose 28-bit base is computed only for a checked
refill.

## 2. L65S-v4-direct and C2I-v1

The shelf reuses the host-proven v4 envelope: 32-byte header, 32-byte records,
u24 region offsets and separate immutable-code/load-time-metadata regions.
The pure catalog-widening variant is not a C2 product format because it still
requires L65M reconstruction.

The strict decoder rules are deliberately asymmetric:

- v1.1 accepts only L65S-v3;
- C2 accepts only `L65S-v4-direct` and known flags;
- C2 rejects v3, widening-only v4 and unknown versions;
- no shipped candidate carries both decoders.

Each split container has a `C2I-v1` metadata region. Its 16-byte entry record
contains:

| Field | Encoding |
|---|---|
| code offset | u24, relative to the container code region |
| code length | u16, legal range 1…65,535 |
| first literal resolution | u16 |
| literal count | u8 |
| export name | u16 offset, or `$ffff` for anonymous |
| arity | u8 |
| flags | u8 |
| diagnostic ordinal | u16 |
| reserved | u16, must be zero |

Every legal name offset is strictly below `$ffff`; the sentinel can never
become reachable through a future pool rebalance.

Literal descriptors are eight bytes:

```text
kind:u8 | flags:u8 | argument0:u16 | argument1:u24 | reserved:u8=0
```

The initial kinds cover NIL, true, signed fixnums, immutable strings,
container-local entry ordinals, exported names and native primitive IDs.
For `fixnum-i16`, the `argument0:u16` bits are interpreted as a two's-complement
i16. The decoder accepts only the dialect range −16384…16383; other bit
patterns are format errors rather than wrapped literals.
Local edges use ordinals. Cross-container edges use exports only. A late-bound
edge is always a name descriptor; converting it to an ordinal is a format
error.

Stored code objects retain zeroed literal-table-shaped bytes so code and PC
layout remain deterministic, but `PUSHLIT` reads the session resolution table.
Those zero bytes are immutable and ignored as values.

## 3. Identity and publication

The host binds the product set, complete shelf, each region and diagnostic map
with SHA-256. The device binds product build identity, catalog CRC32 and
per-region CRC32. This distinction is intentional: the device does not claim
to compute SHA-256 when it only verifies the product-bound CRC chain.

Every stage/restage allocates a nonzero u16 session generation. Wrapping the
generation is fail-closed and requires a cold boot. Publication order is:

1. verify complete catalog and region identity;
2. reserve unpublished directory and resolution ranges;
3. resolve immutable descriptors into session `obj` values;
4. validate exports, anonymous entries and late-bound constraints;
5. journal the prior bound state and value of every target export cell;
6. publish the directory range;
7. publish export function cells last.

Any error restores changed function cells from the journal in reverse order
before restoring all watermarks. No callable or export from a partial commit
survives. Late binding changes only mutable function cells; immutable code and
descriptors remain unchanged.

## 4. Code-window contract

The VM retains one hot code window. A refill is keyed by product identity,
shelf identity, session generation, image slot, entry ordinal and PC. Before
DMA it proves that:

- entry and PC stay inside the immutable code region;
- base plus offset cannot overflow the 28-bit domain;
- the refill does not cross the entry length;
- generation and shelf identity still match.

C2.0 deliberately does not pick a window or refill quantum by intuition.
C2.1 measures the geometry, nested-call reloads and the owner-pinned latency
limit in a real link. A zero-headroom budget cannot be spent by assumption.

## 5. Reset and restart

A platform reset is not a Lisp restart; it returns to firmware. A cold boot
restages and verifies the complete Attic cache, then creates a new mutable
session plane.

The C2.3 `restart-repl` operation keeps only verified immutable Attic tenants.
It increments the generation, clears heap/directory/resolutions/exports,
rebuilds the mutable plane and starts a fresh REPL. Hot-restaging a different
shelf into a live session is forbidden.

This is the missing invariant exposed by all three rejected 1.1 restart
designs: pristine code remains stable, while session state is disposable.

## 6. Proof and negative matrix

C2.0 exits only after one SHA-bound anonymous helper runs through direct,
`funcall`, `apply`, closure and tail-call coverage in all four engines. This is
internal proof evidence, not a product promotion.

The permanent negative matrix includes:

- strict v3/v4 rejection in both directions and unknown flags;
- u24 and 28-bit overflow;
- `$ffff` used as a legal name offset;
- a zero-length entry;
- a fixnum descriptor outside −16384…16383;
- cross-container ordinal and late-bound ordinal edges;
- region CRC and product/shelf identity mismatch;
- stale generation after restage;
- a hot-restage request in a live session;
- failure before and during export publication;
- refill beyond an entry boundary.

## 7. Freight order for approval

The machine-readable triage is `config/c2-freight-triage.json`.

| Rank | Freight |
|---|---|
| MUST | catalog/direct format; all product library and compiler conversion; 1.9-second cure |
| SHOULD | bitops; `gc`/`room`/`error`; `restart-repl` |
| COULD | H/I/J substrate and metadata shelf; color-scroll rider; tick hook and `(time)` |

The 1.1 performance exception never renews automatically. Missing the cure
returns to the owner even if lower-ranked freight has already shed. `while`,
`show`, parity revalidation and the ship builder are post-C2 work, not freight
inside this cut.

## Review decisions — approved 2026-07-19

The owner/reviewer approved:

1. the logical `BCODE` → directory → image/ordinal address chain;
2. the C2I-v1 entry and literal-descriptor encodings;
3. the no-dual-decoder staged swap;
4. the reset/generation and publication rules;
5. the MUST/SHOULD/COULD freight order.

The approval incorporates the review hardening: code length is u16 without
growing the 16-byte entry, zero length is invalid, and hot restage has its own
negative fixture. C2.1 remains an internal proof target until its own gates
and capacity review pass.
