# C2.1 dynamic-code prelink addendum

Status: **Option A owner-approved; bounded contract/emitter probe authorized**

Date: 2026-07-19
Machine-readable proposal: `config/c2-dynamic-code-gap-proposal.json`

## Finding

The owner-approved C2D-v2 decoder and its GC-root protocol now close the six
immutable product images: 583 entries, 2,249 resolutions, 284 canonical heap
roots and all current hot-literal windows. The first real product-integration
audit found a different address class before the substitution link changed a
product byte: **code created after the session directory has been published**.

The current product has two live publishers into the legacy directory:

- `lcc_install_overlay.c` installs `lcc-run`/`eval` definitions;
- `l65m_commit_overlay.c` installs libraries loaded from disk or the Attic
  shelf, including the result of `compile-string`.

The independent compile-REPL engine uses a third publisher in
`compile_repl.c`; it is not linked into the Workbench product, but the eventual
four-engine C2 parity closure must convert or deliberately classify it.

The shipped developer loop is explicitly tested as
`compile-string -> load-lib -> call`. Its producer still emits an L65M
container, and the public product contract lists compilation and library load
as resident workflows.

C2D-v2 cannot encode that work. Its image record points at an immutable shelf
record. Its entry record contains an image slot and immutable entry ordinal;
the flags are required to be zero. Its heap-root membership is derived from
the immutable C2I descriptor stream, and its final header is a one-time
session publication marker. There is no source kind, extension identity,
append capacity, append journal or persistent C2 compiler output.

The arithmetic `608 - 583 = 25` is not a hidden solution. It is neither a
declared append capacity nor sufficient for the compiler's existing
64-entry FASL limit, and it supplies none of the missing identity, descriptor,
root or rollback rules.

Therefore a nominal substitution link has only two possible outcomes today:
it retains the old directory/L65M materializer beside C2 and violates the
no-dual-decoder contract, or it removes public compiler behavior. Neither is a
valid product probe. The link stops before either false result exists.

## Option A — C2 session-extension images (recommended)

Define one session-extension image format shared by interactive and persistent
compilation:

1. the compiler emits normalized immutable code and C2I-v2 metadata rather
   than L65M patches;
2. the loader stages an unpublished, identity-checked extension tenant in
   Attic memory;
3. it appends image, entry, resolution and root ranges to the mutable C2D
   plane under the existing export journal;
4. the updated C2D header is published last;
5. `compile-string` persists the same format through M65D COW, and `load-lib`
   accepts it through the sole C2 decoder.

The contract must pin the extension identity/source-address domain, hard
capacities, rollback and reset behavior, disk version boundary and the policy
for v1.1 L65M files. No exact record reuse is assumed: in particular, a
mutable C2D flag is not identity by itself.

This route preserves the core substitution law. Static and generated code use
one descriptor/root model; the old 28 L65M slices and fixed directory can
actually disappear.

## Option B — mutable session-code lane

Add a C2D source class for directly resolved mutable Bank-5 code. This might
avoid an Attic tenant for every definition, but it creates a second address,
literal and GC-root domain inside C2. Persistent output still needs an on-disk
translation. It is a measured fallback candidate only after an explicit
address/root amendment and performance probe.

## Rejected alternatives

Keeping L65M only for user code is a mixed-decoder product. It retains the 28
slices and the legacy directory, so it is not the authorized substitution.
Removing compilation instead would break `lcc-run`, `eval`, `eval-buffer`,
`compile-string` and arbitrary `load-lib`, contradicting both the public
product contract and the C2.2 exit criteria.

## Decision — approved 2026-07-19

The owner approved **Option A** as one bounded contract/emitter probe, with
hard generation binding, a single product emitter, the established
publish-last/rollback patterns and no product bytes before review. The probe must
produce an exact self-describing extension envelope, capacity arithmetic and
append/rollback/GC negative matrix before the real substitution link resumes.
No product capacity is spent by this stop, and the green immutable-image
C2D-v2 proof remains valid within its stated domain.
