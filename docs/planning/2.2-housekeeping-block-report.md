# 2.2 Post-v1.5 Housekeeping Block — report

Status: **owner touchpoint; the hard bar is not met, and the reason is the
block's most important finding**

Ran: 2026-08-18, autonomous, host-only, zero device contacts.

## Outcome first

The block repaired a recurring structural defect, consolidated the era's rule
set, sealed its plans, groomed the registers and consolidated the repository.
It did **not** reach the hard bar of a fully green `check-source` with an
empty exception list, and it should not have forced it: what stands between
here and green is not housekeeping.

**The finding that matters more than any individual repair: `check-source`
has not been running to completion, so the tail of its gate list has been
unverified for some time.** Every run stopped at the first red, and each
repair only revealed the next one. Running it with `make -k` for the first
time showed the whole picture at once: eleven failures, of which this block
repaired one (an uninventoried assembler source). The remaining **ten are
pre-existing v1.5-era drift**, not damage from this block: gates that bind
`src/mem.c`, `src/c2_platform_dma.c`, `src/c2_product_runtime.c` and the
linker driver still name the bytes those files had before the CPU-transport
work changed them on 2026-08-14 and 2026-08-16.

## The structural repair: sealed evidence read in its own era

Four gates asked today's working tree to reproduce a closed record, so every
later edit drifted a receipt that had not changed. The project had already
paid for this twice with rebind receipts (2026-08-14, 2026-08-16) — and the
second rebind then drifted in turn. The treadmill has no last step.

Provenance is now read at the commit that sealed each record, through one
shared helper (`tools/host-lisp/evidence_era.py`); live content checks are
untouched. Repaired: the VMA-golden review, the CRC carve-out closure and its
liveness sibling, the far-payload closure, and the post-link schema receipt.

Two corollaries were bought in the same pass:

- **A historical gate never polices living documentation.** The v1.1.2
  split-media gate required the user guide to state that tracing is not
  delivered. True of the v1.4.0 world — but v1.5.0 shipped `trace`/`untrace`,
  so the gate was demanding that today's documentation deny a shipped
  feature.
- **A sealed snapshot is not a content authority.** The post-link schema
  receipt gates schema conformance, not file bytes. Identity and every
  consumed and produced key still compare exactly; the digest of a file that
  is revalidated on every run no longer has to match the snapshot.

## Other repairs

- **The ElfTruth migration gate said more than it detected.** It reported
  "parses ELF columns by hand" on any source that merely *named* `llvm-nm`.
  The two tools blocking the full run never execute llvm; they hand the path
  to `resident_island.py`, the pinned parser. The gate now distinguishes
  running a column tool from delegating to an accountable one, and stays
  fail-closed. Population: 60 mentions, 56 hand parsers (all pinned), 4
  delegating.
- **The parity contract had a delivery authority that ages.** Library
  manifests under `build/` describe whichever era last produced them, so the
  v1.1.2 manifests still described the v1.1.2 world while v1.5.0 shipped
  `defstruct`, `trace` and `untrace` — read as three documented names with no
  delivery. The release contract the D-session accepted now counts as a
  delivery authority; three mutations prove it bites.
- **An assembler source was never inventoried.** The mapped-far facade
  padding member, added with the MAP-CPU root fix, is now classified as a
  non-mirror source.
- **The v1.5 public product driver** joined the medium-builder enumeration,
  which minted its v4 record rather than rewriting v3.

## What stands between here and green

All remaining failures share one root: **the bound product authorities
predate the library and C sources that shipped in v1.5.0.** The emitter was
proven deterministic — two consecutive emissions agree byte for byte — so
this is genuine staleness of the bindings, not nondeterminism.

The documented resolution is a product link cycle that rebinds those
authorities. That is a product act, not housekeeping, so it belongs to a
product card with owner visibility. Two things must be known before that card
is written:

1. **`make workbench-product` cannot run at all right now.** The target
   routes through the frozen v1.5 public driver: with the selected manifest
   absent it chooses `build`, and `build` refuses because its one-shot guard
   tests a directory that the tool's own `ide-check` preflight already
   created. A sibling action of the same tool wedges the everyday product
   target.
2. **`check-source` is not idempotent.** An early gate verifies bound
   artifacts that a later target in the same run re-emits, so a green run
   leaves the tree in a state where the next run is red. This is separable
   from the staleness and can be fixed on its own.

Both are registered in `docs/reference/parked-items-register.md`.

## Gate runtime, measured

A full `make -k check-source` on this machine takes **15 min 30 s** and emits
about 2,000 lines. That is long enough to discourage running it per commit
and is part of why the tail went unverified, but it is not yet long enough to
justify splitting the aggregator into tiers: the target is reached far more
often by the release ladder than by hand. Measured, not guessed, and worth
re-measuring after the authority-rebind card, because a green run is the only
run whose full cost is known.

## Housekeeping completed

- **Rulebook consolidated.** The permanent clauses of the 2.0/2.1 era moved
  out of work-plan appendices into `docs/reference/gate-and-tool-register.md`,
  each with its owning gate and the mutation that proves it bites.
- **Plans sealed.** The 2.0, 2.1 and post-v1.4.0 plans carry closing entries
  and are reclassified as historical. The 2.1 plan alone had grown past 3,500
  lines.
- **Registers groomed.** The `trace`/`untrace` row is closed as delivered in
  v1.5.0; the editor key-56 row records that its documentation action landed
  and keeps only its reopen condition.
- **Docs aligned.** The architecture overview catches up with CPU transport,
  the WYSIWYG input contract, the headroom contract and boot liveness; it had
  still described release 1.2.0.
- **Repository consolidated.** `main` is fast-forwarded to the release line
  and is now the repository default (it pointed at the stale
  `codex/ship-v4-remediation`). Seven side branches were retired. Four of them
  were **not** safe to delete as found: they carried unmerged 2026-07-09
  studies, including a disk-save note that the archived collaboration handoff
  already referenced although the file had never been merged. All four were
  landed on the main line first, then deleted.
- **Evidence hygiene: nothing to do.** The 3.1 GB under
  `tests/bytecode/dialect-v2/evidence/promotions` is the deliberate
  materialization the July block left for `r6-g6-registered-seal-check`.
- **Public repo.** The v1.5.0 release already carried the documentation
  refresh: the public README names 1.5.0, `trace`/`untrace`, `defstruct` and
  the boot phases, and the About text is current. One gap remains — the
  WYSIWYG input contract is not mentioned — and it is left as an owner
  decision because it means a public commit after a released tag.

## Recommendation

Do not open v1.6 on this tree. Write one product card that rebinds the
product authorities to the v1.5 sources, and unwedge `workbench-product`
first — it is the prerequisite for the card. The `check-source` idempotence
defect can be fixed alongside or separately. When that card is green, this
block's bar is reachable in a single run.
