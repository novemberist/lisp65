## Outcome

The accepted W1/W2 design is executable as a strict host model without a
second reader or a second index truth.  The probe uses
`bytecode_p0_compiler.parse_one` to read exactly one unevaluated L65P-v1 data
form.  It generates one deterministic library index, validates every artifact
binding, resolves dependencies to one identity set, and writes one resolution
lock before modeling any append.

The positive graph contains two libraries.  Requiring the leaf loads the
dependency first and returns `t`; repeating the same request in generation 7
leaves the complete session snapshot byte-identical.  A fresh generation 8
loads both identities again.  A failure at any of six append states leaves the
failing library absent.  When the dependency was already committed, it
remains valid while the requested library rolls back.  This is the accepted
per-library atomicity rule, not accidental whole-graph atomicity.

The generated probe load closes at:

| currency | Link-67 baseline | probe delta | modeled total | hard cap |
|---|---:|---:|---:|---:|
| Bank-2 code | 34,990 B | 288 B | 35,278 B | 65,536 B |
| images | 6 | 2 | 8 | 64 |
| entries | 602 | 5 | 607 | 2,048 |
| resolutions | 2,299 | 7 | 2,306 | 4,096 |
| roots | 283 | 3 | 286 | 1,536 |
| append scratch | 0 B booked | 40 B | 40 B | 14,544 B |

These are fixture measurements for the host transaction model, not reserved
product capacity.  The implementation impact is exactly zero resident bytes,
zero product bytes, zero links and zero hardware runs.

The negative matrix rejects 38 cases: manifest shape and path errors, index
and artifact identity drift, ambiguous/missing/cyclic dependencies, stale
loaded identity, generation drift, every independent W1 capacity overflow,
runtime-Attic execution and publication-order reversal.  Twelve injected
cutpoints cover all six transaction states for both a failing dependency and
a failing requested library.

## First Red

Run 1 stopped in the host oracle: `(sources)` reached the generic
`field-shape` rejection instead of the specific `empty-sources` contract.
The structural layer now admits a named zero-arity row and leaves legality to
the field-specific arity/nonempty rule.  No format meaning changed.  Run 2
passed the complete unchanged matrix.  The separate First-Red receipt records
two host runs and zero claimed artifacts before replay.

## Target cut proposed for the next Class-C decision

The existing product already owns the expensive semantics:

1. the disk path stages one strict one-record L65S-v4/C2I-v2 artifact;
2. `c2_product_append_staged` performs capacity checks, Bank-2 destination
   verification, C2D publication, export publication and rollback; and
3. every published Session image already carries generation plus the
   combined-image CRC32 in its canonical 32-byte C2D image record.

The target `require` cut should therefore add orchestration, not another
loader:

- the media builder emits one strict generated index from the same
  artifact/emitter receipts that build the library files;
- the device resolver is cold and consumes that index, never a handwritten
  Lisp table;
- a resolved row supplies the artifact locator, dependencies, exported names,
  exact capacity deltas and the canonical L65S combined-image CRC32;
- the combined-image CRC32 is the target-visible library identity.  Loaded
  state is derived from the existing generation-bound C2D image records, not
  from `*loaded-libs*` or a new resident registry;
- each missing row is staged through the existing disk/stage seam and
  committed by `c2_product_append_staged`; and
- `require` publishes no separate loaded bit.  The C2D header is still the
  one reachability commit, and exports remain publish-last.

This removes the old Lisp `*loaded-libs*` list from the new surface without
changing traditional `load-lib`.  It also gives the identity rule a canonical
target witness that already exists.  The host SHA-256 remains a build and
receipt binding; the device uses the CRC-bound L65S/C2D identity it can
actually prove.

The product-shaped probe must answer three placement questions with WPLTO
rather than assumption:

1. Can index parsing, dependency traversal and aggregate preflight live
   entirely in cold library/Session overlays with **zero resident debit**?
2. Does the index fit an existing media role and staging scratch without a
   new Session slice record?
3. Can `load-project` reuse the canonical source reader/load path while
   keeping project parsing and resolution-lock construction off the hot path?

Any resident byte, new Session record, index-format widening or C2D record
change returns as a separate Class-C question.  A green probe may then request
one successor product link and a bundled hardware session containing:
dependency load, idempotent repeat, fresh-generation reload, stale-identity
rejection, dependency-failure partial commit, callable export, Freezer
identity and exact post-load W1 counters.

## Freight order after the target seam

The accepted first library is `defstruct`.  `random` follows on the existing
ring-buffer substrate, with lagged Fibonacci as the portable baseline and a
separately measured xorshift option using F2 bitops.  Neither library is
implemented or capacity-claimed by this receipt.
