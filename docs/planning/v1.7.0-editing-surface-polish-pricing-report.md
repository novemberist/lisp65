## Outcome

Block 3 has a host-priced winner: one shared lexical matcher scheduled in
bounded idle chunks, plus a software cursor blink driven by the product's
existing frame counter. Both forms live in Bank 2. They add no resident byte,
primitive, input owner or timer owner.

The important capacity correction is favorable. The parked Comfort world at
32 free symbols is not the delivery baseline. The delivered, Comfort-free
v1.6 D5 world starts at **105 symbol slots / 1,413 name bytes**. The complete
conservative Block-3 name inventory spends 11 slots and 124 bytes, leaving
**94 / 1,289**, or **62 slots / 905 bytes above the release floor**. This is a
device-measured baseline, so no projection bias is applied.

The selected forms require review acceptance before freight. This report
authorizes no library edit, WPLTO, product link, medium or device contact.

## Matcher: idle-chunked, never synchronous

The executable semantic prototype is one scanner over both real surface
representations:

- the Bank-2 line editor supplies its existing sentinel-chain code list;
- the IDE supplies its already materialized packed string through
  `string-ref`;
- parked Comfort can later consume the list seam, but is not a delivery or
  acceptance claim in this block.

The matcher recognizes parentheses and quotes, ignores parentheses in strings
and after line comments, and treats an escaped quote as string content. The
line and IDE adapters allocate no cells. Ordinary non-delimiter input bypasses
the matcher entirely; the measured IDE bypass costs 18 VM steps.

The compiled seven-function semantic core is 805 Bank-2 bytes. Its largest
object is 235 bytes, below the 255-byte object limit:

| Object | Bytes |
|---|---:|
| `%sexp-code` | 22 |
| `%sexp-rest` | 18 |
| `%sexp-step` | 145 |
| `%sexp-scan` | 79 |
| `%sexp-open` | 155 |
| `%sexp-close` | 151 |
| `%sexp-match` | 235 |

A full unmatched 250-code scan takes 27,726 VM steps, equivalent to **93.669
ordinary line-editor key deltas**. The synchronous delimiter-dispatch form is
therefore rejected.

The winner advances at most three code units between input polls. This bound
was measured separately across scan/open/close and list/string forms; the
worst is the string closing pass at **351 VM steps**, or 0.482625 frame under
the historical conversion, below the 0.5-frame scheduling ceiling. One pass
over 250 codes needs 84 chunks and a worst two-pass match 168; the 79-column
IDE equivalents are 27 and 54. Every pass must carry resumable state—no later
implementation may make only the prefix scan incremental while hiding a
synchronous partner-search pass.

The 0.482625 figure is a scheduling projection from the already accepted
historical cycles-per-VM-step constant, not a current device-timing claim.
The exact authorities remain the host instruction counts.

## Paint ownership and Bank-2 envelope

The scanner returns only a partner index. Each surface owns the actual paint
and two cells of highlight state, and clears an old highlight when the cursor
moves or input becomes unmatched. Cursor paint and delimiter paint are proved
as one composed framebuffer; separate renderer fixtures are not sufficient.

The emitted matcher core (805 bytes) and blink kernel (114 bytes) establish
919 bytes of executable Bank-2 body. The remaining three anticipated private
integration objects—`%sexp-paint`, `%rl-idle`, `%ide-idle`—are deliberately
not represented as final freight in a price-only card. Their conservative
object-limit envelope is 3 × 255 bytes, making the admitted Block-3 ceiling
**1,684 Bank-2 bytes** with no name outside the eleven-entry inventory. The
implementation cards must replace that ceiling with exact emitted sizes and
must keep every object below 255 bytes; exceeding the name inventory triggers
a new price round.

## Blink: software idle phase wins

The MEGA65 core implements colour-attribute blink, but that capability is not
delivered as a usable product contract:

- the selected product does not explicitly enable the required VIC attribute
  mode;
- `src/screen.c` preserves only the low colour nibble, not blink bit 4;
- the safe 1,024-byte colour window does not reach the line editor's last-row
  cursor at offset 1,920.

Hardware blink is therefore rejected. A core capability is not a product
feature until the delivered profile, writer and full surface reach all prove
it.

The selected software kernel reads the existing `C2K_FRAME_LO` at `$FF83`,
toggles every 32 frames and forces the cursor visible before dispatching a
key. It compiles to **114 Bank-2 bytes**. Its measured branches cost 42 steps
without a toggle, 61 for a line-editor toggle, 60 for IDE wrap-toggle and 52
for the dispatch handoff. The one allocation shown by each isolated fixture
is creation of the single mutable `(last-frame . visible-phase)` state pair;
an idle tick itself allocates zero cells.

The line editor changes its blocking wait into a nonblocking idle loop while
retaining the same public input owner. The IDE reuses `poll-key`, already its
burst-drain source. There is no second queue reader, timer or resident state.

## Surface baselines and claim boundary

The actual line-editor suite measures 3,954 steps for an empty line and 4,842
for three ordinary characters: **296 incremental steps per ordinary key**.
The current resolved IDE suite measures 80 keys at mean 1,476.9, median 1,412
and maximum 6,569 VM steps/key, with mean 38.275 allocations/key. Native
screen I/O is excluded from the IDE projection, so Block 3 claims only bounded
additional visual work; the IDE throughput redesign remains Block 4.

The current claim covers the Bank-2 line editor and IDE. It does not claim a
matcher in the native C fallback, does not revive or accept Comfort, and does
not turn historical timing conversion into device evidence.

## Permanent gates and recommended split

The implementation should run as three cards: shared scanner/paint ownership,
line-editor idle blink, then IDE idle blink. The following gates travel with
them:

1. lexical parity covers strings, comments and escaped quotes;
2. ordinary keys never invoke the scanner;
3. every scan/open/close pass yields after at most three code units;
4. unmatched or moved-away input clears stale highlight;
5. cursor and partner paint are checked in one composed framebuffer;
6. blink runs only while idle and forces visible state before dispatch;
7. each surface retains one input owner and the existing frame counter remains
   the sole timer owner;
8. hardware blink cannot be claimed from core capability without delivered
   ATTR enable, bit-4 preservation and all-row reach;
9. D5 measures the final loaded Block-3 configuration.

## Recommendation

Accept the selected Bank-2-only forms and open the three implementation cards.
No owner capacity exception is required: the result leaves 62 symbol slots
and 905 name bytes above the release floor, with zero resident cost. Review
acceptance is the only remaining touchpoint.
