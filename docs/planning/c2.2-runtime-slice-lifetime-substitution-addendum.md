# C2.2 runtime-slice lifetime-substitution addendum

Status: **Option A attempted; first-red, not promoted**

Date: 2026-07-19
Machine-readable contract:

## Finding

The completed C2 reslice fits all 43 C2 operation slices below the fixed
1,792-byte execution-window ceiling and reduces named resident C2 text from
18,172 to 4,657 bytes.  The combined product nevertheless misses the two
remaining placement gates: Bank 0 requires 3,049 bytes of relief and the
single L65R-v1 store exceeds its 64-KiB u16 domain by 256 bytes.

The same real link proves that decoder phases 0, 1, 2a, 2b and 3 are used only
before the product directory is published.  They occupy 6,605 raw bytes and
7,168 bytes after the store's 256-byte packing quantum.  Every session append
starts at phase 4.  The measured boot-exclusive storage is therefore larger
than the complete 3,305-byte combined deficit.

This is a lifetime-placement failure, not a request to enlarge a ceiling.

## Option A — two exclusive L65R families

C2 uses two fixed, product-bound L65R-v1 tenants and one execution window:

| Family | Physical base | Callable contents | Lifetime |
|---|---:|---|---|
| `boot-validation` | `$08200000` | catalog/record verifiers, phases 0–3, resident-island installer | generation invalidated through completion of phase 3 |
| `session-runtime` | `$08000000` | catalog/record verifiers, phases 4–13, emitter, append path and runtime services | phase-3 handoff through the end of the session |

The slot namespace is deliberately reused.  Slot 2 means phase 0 in the boot
family and phase 4 in the session family.  No caller may therefore select a
slot without naming its expected family.  The resident transport rejects a
family mismatch before reading a catalog record or loading executable bytes.

This is not a general multibank slice store.  It is one fixed boot tenant and
one fixed session tenant, selected exactly once at the already-proven phase-3
cursor boundary.  Each tenant independently remains an L65R-v1 u16 store.

## State and generation protocol

The only legal state sequence is:

```text
inactive
  -> invalidate C2 session generation
  -> boot-validation
  -> phase 0 / 1 / 2a / 2b / 3
  -> verify nonzero new generation
  -> session-runtime
  -> phase 4 ... publication ... session appends
```

`c2_product_prepare_boot()` owns the first two transitions as one product
operation.  It clears reachability and the active generation before enabling
the boot family.  Phase 3 owns the sole boot-to-session handoff.  Re-entering
the boot family from a live session is impossible through the runtime API;
restage must first invoke the generation-invalidating prepare operation.

The family state, selected physical base and generation state are resident.
The immutable family images may both be staged in Attic memory, but only the
active family is executable.  A failed switch latches the transport and
publishes no C2 directory or export.

## Structural gates

The permanent negative matrix rejects:

- a boot-family phase after the phase-3 handoff;
- a session-family phase before the handoff;
- a restage attempt that enters the boot family before generation
  invalidation;
- a session handoff with generation zero;
- a family/catalog identity or physical-base mismatch;
- a second boot-to-session handoff;
- an attempted family switch while a slice is active;
- any model in which boot and session phases are simultaneously executable.

The product closure must contain exactly the two generated family manifests.
Both bind the same product/profile build identity.  Their dense slot maps,
verifier tuples, base addresses, image sizes and CRCs are generated inputs;
the C source does not reproduce them by hand.

## Capacity and future boundary

The authorized link prices the resident family flag, generation state,
expected-family check and DMA-base switch from the real linked product.  The
7,168-byte observation is not itself a capacity authorization.

This addendum does **not** widen L65R-v1.  Each family still has a 64-KiB u16
file-offset ceiling and at most 64 dense slots.  A future general
multibank/Attic native store is the recorded C3-class growth path when the
session tenant itself reaches that wall; it is not a fallback in this round.

## Decision — approved 2026-07-19

The owner approved Option A as one addendum/receipt pass followed by exactly
one real substitution link.  No slice ceiling may move, interactive
compilation and the single C2 emitter/decoder remain mandatory, and every
first red returns for review.  There is no automatic fourth layout attempt.

## First real link — red, 2026-07-19

The family model closes the old store failure arithmetically on the linked
sections: the boot image projects to 12,129 bytes and the session image to
58,275 bytes, both under the unchanged 65,536-byte limit.  The real seed link
stops earlier at the resident boundary, however.  The family selector,
generation latch, second verifier tuple and expected-family checks add 591
resident bytes relative to the preceding reslice candidate.  Its BSS end is
`$d18d` against the fixed `$c356` overlay VMA, so 3,639 bytes of resident
relief are still required.

The approved premise was therefore incomplete: temporal separation frees the
runtime-store namespace, but it does not by itself move the remaining
resident C2 facade into that namespace.  No family image, runnable smoke or
product artifact was emitted.  The one-link authorization is consumed and
the result returns to architecture review; no additional facade split or
packing round is implied by this addendum.
