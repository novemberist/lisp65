# C2.1 mutable-resolution GC-root addendum

Status: **product-substitution stop; owner decision required**

Date: 2026-07-19  
Machine-readable proposal: `config/c2-gc-root-proposal.json`

## Finding

The complete streaming decoder passes and fits the runtime slices, but its host
witness uses synthetic values. The first product-substitution audit exposed a
missing lifetime rule: C2D resides in Bank 5, while the current collector scans
only the Bank-0 shadow-root stack and the symbol table. A string or cons stored
only in C2D is therefore not a GC root.

This matters during construction, not just after publication. Resolving a
later string, symbol or pair may allocate and collect. Without a C2-aware root
source, an earlier resolution can be reclaimed before the final header is
published. A link could be green while the first GC corrupts the session.

The complete composition has 2,249 resolution slots:

| Kind | Values | Needs an additional GC root? |
|---|---:|---|
| NIL / fixnum / local entry | 986 | no (immediate) |
| immutable string (kind 3) | 116 | yes |
| symbol (kind 8) | 979 | no (canonical symbol table already roots it) |
| cons pair (kind 7) | 168 | yes |
| **additional roots** | **284** | **568 bytes as `obj` values** |

Kind 5 is absent from the legacy conversion and, when present, resolves through
the same rooted symbol table. The consumer rule remains unchanged: only kind 5
is call evidence; kind 8 is invisible to graph consumers.

## Option A — scan the complete resolution table

Keep C2D-v1 unchanged. Once resolution begins, the collector DMA-reads all
2,249 slots and marks every pointer-shaped value. Zeroed unresolved slots are
safe during construction.

This costs no additional C2D byte, but every collection reads 4,498 bytes. At
the streaming proof's 32-byte transfer quantum that is 141 reads even though
only 284 values need this root source. The project has already found and fixed
GC latency caused by repeated extended-memory scans; accepting this option
without hardware timing would repeat that risk.

## Option B — C2D-v2 contiguous root vector (recommended)

Append a compact root vector after the resolution table. Its entries mirror
only kind-3 strings and kind-7 pairs, in descriptor order. The existing 32-byte
header remains the same size: the former reserved `u16` becomes
`root_count_u16`, and `roots_offset` is derived as
`resolutions_offset + resolution_count*2`. The format version becomes 2.

For the current composition:

```text
C2D-v1: 10,480 bytes
roots:      284 * 2 = 568 bytes
C2D-v2: 11,048 bytes
Bank-5 session headroom: 50,816 - 11,048 = 39,768 bytes
```

Before the first allocating resolution, both the resolution and root sections
are zero. After `str_from_bytes` or `cons` returns, the new value is written to
its resolution slot and immediately to the next root slot with no allocation
between those writes. The collector scans all `root_count` slots during both
construction and the published session. On failure, the export journal rolls
back first and the unpublished C2D header remains non-authoritative.

The current 36-byte streaming context can carry `root_count` and `root_cursor`
by replacing two diagnostic/cursor fields that the decoder does not use; this
does not pre-authorize the resident GC seam or any capacity delta. With the
same 32-byte transfer quantum, the root scan is 568 bytes / 18 reads.

No C2 format has shipped. As with the pre-seal L65S and C2I changes, C2D-v1
remains historical proof evidence and C2D-v2 becomes the sole product decoder.
The same change after a product seal would require migration.

## Option C — a `%lit-keep`-style keeper list

Keep C2D-v1 and link each heap-valued resolution into a symbol-rooted list.
That adds 284 bookkeeping cons cells (2,272 extended-heap bytes at eight bytes
per cell) and makes GC traverse a second mutable representation of the root
set. It preserves the old materializer's workaround instead of making the new
mutable plane authoritative. This is retained only as a measured fallback.

## Recommendation and decision gate

Choose **Option B**. It makes the C2D plane explicitly GC-visible, reduces the
per-GC cold read volume by 87.4% versus Option A, preserves construction safety,
and costs only 568 of the measured 40,336 Bank-5 headroom bytes.

Approval authorizes the C2D-v2 contract/emitter/streaming-decoder update and a
real product-layout link that measures the GC seam. It does not authorize a
capacity debit, product promotion or device claim. The product link remains
blocked until one option is owner-approved.

Required negative fixtures after approval:

- root count disagrees with the descriptor census;
- C2D total omits or overlaps the root section;
- nonzero root slot before resolution begins;
- a kind other than 3 or 7 attempts to append a root;
- root cursor underflow/overflow or final count mismatch;
- GC during every allocating descriptor kind preserves all earlier values;
- rollback clears the active scan binding before the prior plane is restored;
- C2D-v1/v2 are rejected in both wrong decoder directions.
