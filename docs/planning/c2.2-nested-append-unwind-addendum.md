# C2.2 nested append and non-local unwind addendum

Status: **owner-authorized bounded contract probe; no product work authorized**

Date: 2026-07-20
Machine-readable contract: `config/c2-nested-append-unwind-contract.json`

## The Link-32 first red

Link 32 boots and directly executes a newly defined function, but public
`eval` inside the top-level compiled wrapper fails with `VM_BADOPCODE`. The
outer transient installation holds one authenticated overlay transaction open
while its bytecode runs. The inner installation therefore sees `BUSY`.
`vm_check_status` then reaches the top-level `longjmp` before the outer C2D
suffix rollback. Two failed calls left two valid, CRC-matching transient images
published in C2D.

The immutable diagnosis is
`tests/bytecode/dialect-v2/evidence/architecture-blocks/c2.2-product-link32-nested-eval-hardware-first-red-diagnosis.json`.
It blocks promotion and every latency claim but does not invalidate Link 32's
structural receipt.

## Transactions are serial; Lisp evaluation may nest

The preferred correction is stronger than nested overlay transactions:
**no overlay transaction remains active while Lisp bytecode executes**.
Staging, publication and cleanup each complete their own authenticated serial
transaction. `BUSY` remains a real anomaly.

Serializing alone is insufficient. The current transient wrapper is an
ordinary low-end C2D suffix. If code running from that wrapper publishes a
persistent definition, rolling the wrapper back to its older checkpoint also
deletes the newer definition. Skipping the rollback preserves the definition
only by leaking one wrapper per occurrence. The bounded probe must reject both
outcomes.

## C2D-v4 disjoint transient lane

C2D-v4 keeps persistent images, entries, resolutions, roots and Session-Attic
bytes growing from their existing low end. Dynamically scoped evaluation
records grow from the high end:

- image slots descend from 63;
- entry, resolution and root intervals descend from their existing capacity
  ceilings;
- transient Session-Attic bytes descend from the one-MiB arena end;
- `transient_depth_u16` replaces the previously zero v3 flags word and is the
  publish-last commit marker, bounded to four.

The two allocation fronts must never overlap. Their positions are derived
from active records rather than independently maintained watermarks. A
persistent append can therefore commit below active transient records. Normal
return or abort removes only the high-end dynamic extent and cannot cross the
persistent publication.

C2D-v3 has not shipped. The pre-release v3-to-v4 correction is therefore
format maintenance without compatibility debt; the same change after a seal
would require migration.

## Roots and execution handles

The directory accepts the committed low prefix plus exactly the high-tail
entry intervals named by active transient records. Holes and inactive tail
handles are format errors. The collector scans the committed low root prefix
and every active transient root interval, all in the same canonical root-value
plane. The transient lane creates no second bytecode, literal or GC-root
representation.

## Longjmp-safe restoration

Publish-last protects visibility, but a non-local abort can bypass a C stack
checkpoint. A fixed 64-byte `C2J` unwind record at Bank-5 session offset 50,752
therefore binds the complete pending mutation before its first target write:
old persistent counts and transient depth, exact target ranges, Attic span,
generation, export-journal count and CRC32.

The central abort landing validates this record and restores it without using
a dead C pointer. It then unpublishes transient depth before wiping all active
high-tail records. Persistent descendants committed before the error survive,
as ordinary Lisp side effects do. An invalid nonzero journal makes the session
plane unusable and requires disk reboot; cleanup never guesses.

## Probe and claim boundary

The one authorized host probe must first demonstrate why the two cheaper
serial variants fail, then exercise the disjoint lane over nested transient,
persistent-descendant, every-cutpoint, abort, generation, collision, directory
and GC-root cases. `eval`, `eval-string`, `load` and `load-lib` are direct
cases; `compile-string` is classified as a C2I-v2 media producer whose later
`load-lib` enters the persistent path.

The probe changes no product source or artifact. Even a green result only
returns the contract to review. With 10 bytes of Bank-0 text, 19 bytes of BSS,
109 bytes of Island and 11 bytes of smallest-slice headroom, every product
implementation begins with a separately authorized capacity/placement probe.
