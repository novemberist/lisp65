# 1.2.3 work plan — landed freight to the user, one device session

Status: **commissioned by owner 2026-07-30**
Baseline: released v1.2.2 (public `43a7ba63…`), head `7224e080…`,
housekeeping block closed, `while`/`random` disposition closed.

## Why this plan has this shape

Three features are finished on the host side and hardware-untouched or
hardware-unfinished: `random` (host-green, gated, never smoked on the
device), `while` (hardware-green for the loop itself; its bundled session
died at the unrelated GC row), and the `require` fast path (−97.96% steps,
host-green, phase markers 17–20 never read on the device). The users have
none of them. Everything this plan does serves one sentence: **ship the
landed freight as v1.2.3, through exactly one device session.**

The plan is ordered so that Codex works without interruption: Phases A–C
are autonomous (Class A or normal implementation work with existing
authority), Phase D is the one device session, and only then come the two
owner halts — results review and publish go. No mid-phase approvals.

## Ground rules (unchanged)

Host-first; receipts with execution witnesses; dependency-sharp first red;
no inherited green; substitutive-never-additive; the resident geometry is
closed. The stuck-debugging rule stands: a contradiction is a reading task,
not another capture — and on grinding debugging, align with the reviewer
before searching further. Class A autonomous; Class B ≤ 3 cycles; Class C
prepared, never decided.

New and binding since 2026-07-30: the release plan's Phase E inherits the
`check-source` rule — green, or a named exception list at the halt.

## Phase B — The product link cycle (autonomous; this is the ide-drift fix)

One regular WPLTO + product link on the current head. This is not new
scope — it is the cycle that was always coming, and it repays two debts at
once:

B1. The link rebinds the profile authority
    (`config/c2-l-full-product-profile.json`) to the fresh product, which
    resolves the one named `check-source` red
    (`product-bound manifest hash drift: ide.manifest.json`).
B2. Exit criterion, and the first time this has ever been true:
    **`make -k check-source` fully green on the built tree** — no
    exception list needed. On a fresh clone the parity gate reports its
    explicit `NOT CLAIMED`; both are green states now.
B3. **Banner subtitle** (owner request 2026-07-30, the one product-byte
    addition of this plan): `lib/repl-banner.lisp` line 33 currently prints
    `WORKBENCH - DIALECT V2`; replace the dialect tag with the release
    version (`WORKBENCH 1.2.3`), adjusting the hard-coded length and the
    centering column. There is no on-device version constant today, so the
    honest form is a **drift guard, not just a string**: a small permanent
    source gate that compares the banner string against the single
    authoritative release version (today `config/v12-known-issues.json`
    `.release`; give it one canonical home if that is cleaner) and goes red
    when a release bumps the version without the banner following. Without
    the guard this becomes the next quiet lie; with it, E1's version bump
    forces the banner by construction.
B4. Walls are known (243/54/2/137/50/113 B at text/E000/fixed/BSS/island/
    session). If any wall breaks, that is a stop-and-align, not a
    negotiation — the terminal geometry stands.
→ No halt if the walls hold.

## Phase C — Session assembly (autonomous, host only)

Consolidate the **one** bundled device session. Everything is prepared;
this phase makes it executable without improvisation:

C1. **Session script and preloaded instruments** for, in dependency order:
    - boot + the standard smoke prefix;
    - **GC two-number discriminator**: cells marked vs. cells returned to
      the freelist from the failing collection of the 600-iteration
      reproducer (authority: the prepared `alloc_oom` discriminator and
      `c2.2-link77-gc-ext-dma-host-lane-receipt.json`). This is the single
      highest-information row of the session — it either attributes the
      intermittent post-GC OOM or moves its parked entry forward;
    - **`random` smoke**: seeding variance, `(random n)` bounds, and the
      `(random-seed k)` reproducibility pair;
    - **`require` fast-path markers 17–20** on a repeat `require`;
    - **IRQ-mask readback**: `$D6E1`, `$D697`, `$D713` enable fields masked
      after boot (closes the Phase-I hardware line);
    - **RUN/STOP** interrupt line;
    - **math-unit probe** (owner decision 2026-07-30, de-risks the 1.2.4
      `fx` core): one passive peek/poke line against `$D770+` — write two
      operands, read the 32-bit product registers, confirm which result
      bytes carry the fraction bits for a signed ~8.7 format. Zero product
      bytes, feature-disjoint, passive; it must never block a feature row;
    - **post-`symname` DIRMISS hold** as the trailing line (K2).
C2. **Dependency map for first red**, written before the session: which
    rows stop on which failure. The GC discriminator row must be placed so
    that an OOM there does not poison the feature rows — feature rows run
    first, the reproducer runs late.
C3. Dry-run the full script against the host session runner.
→ No halt. The session enters with everything preloaded; blind polling is
   forbidden.

## Phase D — The device session (one hardware contact)

Execute C's script in one physical session, dependency-scoped first red as
always: a failing row stops itself and its dependents; independent rows
continue if the device stays live and defined. A red fail-closed frame,
crash or undefined state is terminal for the whole session.

→ **Class-C halt #1: everything on one table.** Session results, Phase A/B
   reports, and — if the discriminator fired — the OOM attribution with a
   prepared (not decided) follow-up. One review, one set of decisions.

### Halt #1 continuation — reviewed 2026-07-30 (attribution round)

The Class-B host attribution is accepted: H0 is refuted cleanly (Link-80

**Commissioned (reviewer Class-C decision): one bounded device

1. `(require 'place)` — expected `nil` (reproduction);
2. immediately read the **first-error stamp**: `lisp65_c2_phase_scratch`
   byte 302 plus trace flags (the first-error-stamp-wins contract exists
   for exactly this question). Non-OK terminator (boundary 2) stamps;
   a clean stamp with `nil` eliminates it;
3. read back the **`place` C2D row** (generation and CRC bytes 28..31 at
   the row address the attribution already computed): an absent/empty row

4. trailing: a second `(require 'place)` and the stamp again.

Address map (phase-scratch and row addresses from the Link-80 ELF via

### Discriminator session: tool-terminal, re-dispositioned 2026-07-30

Both contacts died in `exact-media-put-get-mount` — Link 80 never booted,
`require` never ran, zero peeks. Boundaries 1–3 stay undecided; the red
screen is the FTP helper's normal transfer display that never progressed,
not a product frame.

**Reading before retry (the stuck rule, applied to ourselves):** the FTP
command sequence is byte-for-byte the one the green bundled session used.
The one structural difference is the device state it ran against: the
bundled session started against a freshly defined device; the discriminator
contacts hit a device still running Link 80 — with KERNAL unmapped and the
Phase-I interrupt ownership active that the same session had proven as
masks `(0 0 0)`. The serial FTP helper has to take over the running
system; against BASIC that works, against our hardened product it
evidently wedges. Recorded as a read finding, not a proven mechanism.

**New disposition (reviewer Class C): one additional contact, hardened
procedure.** Before any FTP byte:

0. **Cold reset first** (JTAG reset via `m65`, or the physical switch),
   then a screenshot gate that must show the fresh startup state before
   the transport step may begin — the transport precondition becomes an
   asserted state, not an assumption;
1. a progress guard on the FTP step: no forward progress in
   `media-upload.log` within 120 s aborts the contact cleanly instead of
   burning the budget on a wedged transfer;
2. then the unchanged discriminator script (same peeks, same budget
   discipline: this is contact 3 of now 3).

Standing rule from this incident, for every future session script:
**device sessions begin with a cold reset and an asserted fresh state.**
The bundled session got this for free by running first; scripts must not
inherit that luck silently.

## Explicitly out of scope

`defstruct` and dynamic library freight (parked; R-1/R-2/R-3 restart
package unchanged), the `gc`/`room`/`error` trio (parked on capacity — but
note the standing freight-order rule: if Phase D's discriminator makes GC

the ship builder, and any resident-capacity renegotiation.

`fx`/`long` status changed by owner decision 2026-07-30: **`fx` is the
named core of the block after 1.2.3** (it is still not in this plan's
scope — only the passive `$D770` probe rides Phase D). Its preparatory
decisions are already fixed: signed ~8.7 format (fixnum-width-bounded, per
the `peekw` design stop; screen coordinates with subpixels are the real
8-bit games use case), hardware math unit route, and the legacy software
`lib/stdlib-fixed.lisp` is superseded and never returns to the product.
`long` stays coupled to the `defstruct/packed` restart: stage 0 (scaled
units) already covers the economy-game case, and stage 1 only becomes
first-class with packed 4-byte fields. Every other extension-library
candidate remains demand-gated, owner-activated only.

## Interruption profile (the point of this ordering)

Codex works A → B → C → D without an approval stop. The owner is needed
exactly twice: halt #1 (session results, one combined review) and halt #2
(publish go). If nothing in the session goes red, the total owner cost of
v1.2.3 is two conversations.
