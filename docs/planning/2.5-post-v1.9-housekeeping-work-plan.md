# 2.5 Post-v1.9 housekeeping and tool-layer refactoring — work plan

**Commissioned:** 2026-08-28 (owner: "Ja, das passt für mich", extended
2026-08-28 with the domain audit and the naming audit).
**Position:** runs after the v1.9.0 publication and **before** new product
freight. The v1.9 cycle spent nine link rounds, two descopes, one lifted
descope and a dozen new gates; the accumulated tool and document debt is
now large enough that the next cycle would pay for it in link budget.
**Form:** host-only. **Zero device contacts, zero product bytes.** Owner
touchpoints: the evidence-retention decision (item 5) and the closing
report; everything else is reviewer-decided under the standing
delegation.

## The guard rail

Refactoring in this block means the **checker and tool layer only**. No
product source changes, no renames of public names, no domain repairs.
The v1.9 lessons — LTO folding the wrapper, text prices measured at the
final link, not the fragment — make unmeasured product rework explicitly
out of scope. Every consolidated checker keeps its mutation proof in the
sharp direction: a world that truly lacks the property must still fall.

## Order of work

Two items may run in parallel with separate touchpoints (standing cut
rule). The suggested pairing is noted per item.

### Item 1 — `check-source` runtime measurement (first, gates the rest)

The historical archive revalidator killed a full run during Block R, and
the honest "not claimed green" that followed is exactly the pressure
under which discipline erodes. Measure per-target wall time across one
full run, publish the ranked list, then decide between tiering (a fast
inner loop plus a slower complete gate) and incremental revalidation.

**Bar:** a named, measured ranking; a decision recorded with its
reasoning; no target silently dropped. If tiering is chosen, the complete
tier still runs at every closing commit — the inner loop is a
convenience, never the certification.

### Item 2 — plan-document hygiene (pairs with item 1)

`v1.7.0-pre-plan.md` is 2,101 lines with 35 decision sections and carries
v1.8 and v1.9 decisions that belong in their own documents; the v1.6
freight plan is 10,145 lines. Seal v1.6 and v1.7 as historical, relocate
the foreign decisions to their own cycle documents with provenance
preserved (no rewriting of sealed text — move and reference), and sweep
the 197 planning documents for correct classification.

**Bar:** document index green; every relocated decision reachable from
its own cycle document; no sealed evidence altered.

### Item 3 — gate consolidation (the refactoring half)

`tools/host-lisp/` holds 1,671 tools. Two consolidations are earned by
this cycle, both replacing repeated single cases with one authority:

1. **One force-include header gate** proving bound = consumed for every
   such header, replacing the three separate cases (static-plane extent,
   output root / MAP tuple, bytecode entry).
2. **One prelink pin authority** enumerating the pins in a single place —
   the r7 world's 7 literal pins plus 6 inherited candidate-dependent
   closures — so a card never again pays a WPLTO for a pin nobody
   enumerated.

**Bar:** each consolidation subsumes its predecessors' mutation sets;
the sharp-direction mutations still fall; zero product bytes.

### Item 4 — evidence-era and receipt sweep (pairs with item 3)

Re-prove idempotence (two consecutive full runs, second changing
nothing), refresh the document index and the gate-and-tool register with
the v1.7-v1.9 rule additions: composed Bank-2 owner map, MAP
$100-congruence at placement time, tuple = LOADADDR, consumption-not-just
-arming for delivered instruments, text prices measured at the final
link, and one positioning model per surface.

**Bar:** the register contains every rule this cycle earned, each with
its sealed evidence pointer.

### Item 5 — evidence retention (owner decision)

3.2 GB of untracked evidence sits on disk (largest tarball 1.39 GB)
against a 59 MB `.git`. Propose a retention policy: sealed receipts and
attributions are permanent; superseded acceptance tarballs of worlds that
later shipped are candidates for pruning. **The owner decides what may be
deleted** — bound evidence is immutable by house rule, so this item
produces a proposal, not an action, until that word.

### Item 6 — public surface refresh (last)

The public repository's docs and description have not been touched since
the 2.3 block; v1.7, v1.8 and v1.9 changed the state substantially
(INIT.L65, A0 recovery, lossless input, the editor at the native prompt).
Refresh the public README/description and the user guide's state of the
world, including the two retired Known Issues and the ones that remain.

**Bar:** the public text claims exactly what the releases claim — the
same claim-boundary discipline the release cards use.

### Item 7 — public-surface domain audit (parallel, read-only)

Build the mechanical matrix from the register's domain-discipline row:
every public function (the 139-record public metadata index is the
population authority) against representative out-of-domain arguments
(number, string, symbol, `nil`, list, function), each observed outcome
classified as *error raised* / *documented-permissive* / *silently
wrong*. It runs **profile-faithful** — against the product primitive
table, never the host VM's independent implementations.

**Bar:** the classified matrix becomes a permanent contract table under
enforce-what-you-record: no later change flips a cell silently, and every
new public symbol ships its domain row. **Repairs stay outside this
block** — they are priced freight afterwards, tiered as the register
records (library sequence walks need no breaking-change word; `car`/`cdr`
need measurement and the owner's).

### Item 8 — naming audit (parallel, read-only)

Classify the user-facing names: library designators users type
(`v16core` is the flagship — a version-bearing name a user must type,
still shipping in the current build authority), public function and
error vocabulary, medium and file names (`V17B3P.D81`), and the terms the
user guide teaches. Criterion per name: does it name a capability or an
era/implementation detail?

**Bar:** a classified list with proposed speaking names and a migration
sketch (old designator as an alias for one cycle, then removed).
**Renames stay outside this block**: public names are owner-bound surface
and a breaking change for users advertised since v1.3.

## Out of scope

Any product byte; renames; domain repairs; the Comfort return; the
Block-3 return and `$22` escalation; the #670 reproducer; G1 `room`;
device contacts of any kind. A finding that wants product work becomes a
register row with its evidence, as always.

## Exit

Owner touchpoint: the block report, carrying the measured `check-source`
ranking and its decision, the consolidated gates with their subsumed
mutation sets, two consecutive green full runs with a byte-identical
tree, the refreshed public surface, and the two audit tables as durable
authorities. Owner release of that report opens the next product cycle,
whose candidate order is then decided with the audits in hand.
