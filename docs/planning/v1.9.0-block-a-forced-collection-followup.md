# v1.9.0 Block A — forced-collection follow-up binding

Date: 2026-08-30

Status: **ready for one owner contact**

Block B is already hardware-accepted. This contact opens only the missing
Block-A hardware qualifier: lossless physical input while an actual
collection occurs during one armed `read-line` lifetime. It reuses the
byte-identical r7 product medium; there is no product build or media change.

## Corrected allocation authority

The review sketch inherited the historical public-`key-event` cost of four
heap cells per printable. That is not the delivered r7 world. The final-ELF
consumer uses the scalar Capture route and allocates **one** heap cell per
printable. Six ten-character lines would therefore not force a collection.

The bound replacement keeps one `read-line` and one atomic counter origin
alive. Six passes each insert a visible 32-character token and delete it in
four counted groups of eight. The final seven-character string makes
**199 printable insertions**. Since the nursery holds 192 cells, `199 × 1 >
192` proves at least one collection for every incoming nursery phase. The
maximum visible test payload is only 32 characters, so no scrolling count is
needed.

## Owner steps

Boot the existing `V19R7P.D81` product medium without optional libraries. At
the live `lisp65>` prompt enter exactly:

```lisp
(progn (setq s (read-line)) (print (string-length s)) (wait 16383))
```

On the blank nested input row, perform six passes with this exact token:

```text
01234567012345670123456701234567
```

For passes 1–2 type normally; for passes 3–6 type quickly. Before deleting,
verify the four visible groups are `01234567` each. Then press
Delete/Backspace exactly 32 times as four counted groups of eight — do not
hold the key — and require the row to become blank exactly at the last press.

After pass six, type `abcdefg` and Return. The machine must print `7`. The
long `wait` deliberately prevents the next native prompt from re-zeroing the
counters. Leave the keyboard untouched and tell Codex that `7` is visible;
Codex then stops the CPU once and reads `$BCFC..$BCFF` without resume.

The exact event count inside the nested origin is:

```text
199 printable + 192 Delete + 1 Return = 392 events
392 mod 256 = 136 = $88
```

Green is therefore `7` plus raw/seen/stored/taken all equal to 136 (`88 88
88 88`). Any visible token mismatch, deletion-count mismatch or counter-arc
inequality is red. Equal counters with a different value invalidate the
choreography rather than exonerating or condemning the product.

Green closes Block A and pensions the v1.5 fast-typing Known Issue. The claim
ends at typing inside the delivered armed `read-line`; type-ahead during
evaluation remains outside it.
