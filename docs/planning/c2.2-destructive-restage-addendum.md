# C2.2 destructive-restage addendum

Status: **contract first; Link-57 hardware negative not yet run**

Date: 2026-07-23

Machine-readable contract:
`config/c2-destructive-restage-contract.json`

Cross-invariant row: **C4 — cold reset × partially published C2D**

## Scope

A platform reset is not a warm Lisp restart.  On the measured MEGA65 it
restages ROM over Chip Banks 2 and 3, while Bank 5 and Attic RAM survive.
Therefore a subsequent C2 cold stage must assume that every surviving byte in
Bank 5 and the Session-Attic arena belongs to an arbitrary predecessor.  A
power cycle has no survival claim and is outside this negative.

The contract separates two obligations which must not be blurred:

1. A torn predecessor presented to the product is rejected before `READY`.
   The product may not infer or guess a repair from a mixed-generation header
   or journal.
2. A cold stager which chooses the repair path replaces the complete mutable
   Bank-5 reset domain and then lets the unchanged product reconstruct both
   disposable Chip planes.  Only this complete replacement may lead to
   publication.

The two branches run under the same Link-57 product SHA.  They change no
product byte and make no promotion claim.

## Exact destruction

The destructive predecessor begins with the canonical 33,840-byte C2D-v6
plane, then represents a reset at the publication boundary:

- header generation byte 1 is replaced by 2 while the six immutable image
  records and 590 entry records still carry generation 1;
- the inactive Bank-5 suffix is allowed to contain stale nonzero bytes;
- the 64-byte C2J at Bank-5 offset 50,752 contains a syntactically valid,
  CRC-valid, ACTIVE journal for generation 1, representing a reset after the
  journal commit and before cleanup;
- a sentinel remains in the Session-Attic arena;
- the pre-reset volatile tuple is represented as `READY=1`, Session family,
  generation 1 and Island READY.

The header mutation is deliberately generation-only.  Image counts and shelf
identity remain otherwise plausible, so the negative proves the generation
cross-binding rather than merely rejecting a broken magic byte.

## Detection branch

The destructive plane is read back before the unchanged Link-57 PRG starts.
The required result is:

- `c2_ready == 0`;
- no callable Session-family binding;
- stable error code `LISP65_ERR_STDLIB_PROFILED_PRELOAD` (`0x25`), rendered
  as `E25` because this rejection occurs before the Bank-3 L65E text slice is
  available;
- no stale export, entry or handle becomes callable.

The old C2J is evidence, not recovery input.  Because the header already
proves a mixed generation, cleanup must not be guessed from that journal.
The first red ends this branch.

## Repair branch

The cold reset image is exactly 50,816 bytes:

```text
[0, 33840)       canonical C2D-v6 prefix
[33840, 50816)   zero
```

The zero suffix includes the complete C2J interval `[50752,50816)`.  Uploading
only the 33,840-byte prefix is insufficient for C4: Bank 5 survives reset, so
that shorter write can leave an ACTIVE predecessor journal behind.  The C4
fixture and every later acceptance cold-stage artifact must use the complete
reset image.

There is one authenticated, temporary occupant of that suffix.  After the
complete reset image has been written and read back, the SHA-bound Boot
overlay is staged at physical `$058500`, Bank-5 offset 34,048, for 3,285
bytes.  Its interval `[34048,37333)` is disjoint from both the canonical C2D
prefix and C2J.  The proof therefore has two ordered identities rather than
one impossible simultaneous image:

1. the complete 50,816-byte reset image is byte-identical before any later
   Bank-5 preload;
2. after the Boot-overlay preload, the canonical prefix, the authenticated
   overlay scratch and the still-zero C2J are each byte-identical to their
   separate authorities.

This is not an exception to cold repair.  The stager first overwrites every
surviving predecessor byte, including C2J; only then does a verified current
boot artifact occupy a bounded pre-READY scratch interval.  No product record
may publish that scratch as Session state.

Old Session-Attic bytes need not be wiped.  Their invalidation is structural:
the reset C2D contains no Session image record, and no new active record may
refer to them.  This distinguishes cache invalidation from expensive,
truth-free wiping.

After the complete Bank-5 readback and the separately verified Boot-overlay
scratch preload:

1. CRT and `c2_product_prepare_boot` force `READY=0` and a non-callable family
   state;
2. Bank 2 is completely restaged and target-CRC verified;
3. Bank 3 is completely restaged and target-CRC verified;
4. the C2D header, exports and exact Session family/generation publish last;
5. C2J is still zero before the first append;
6. one fresh persistent definition may commit and call, and C2J is zero again
   after that transaction.

The surviving Attic sentinel is captured after boot.  Its continued physical
presence plus the absence of an active Session record is the stale-handle
negative: survival of bytes does not imply survival of reachability.

## Hardware protocol

One operator-assisted hardware run contains both branches:

1. reset/hold and preload Link 57 with the destructive Bank-5 plane;
2. read back all inputs, run, and capture the fail-closed state;
3. reset/hold the same product identity;
4. preload the complete repair plane and the same immutable inputs;
5. read back, run, and capture Bank 2, Bank 3, Bank 5, volatile publication
   state and the unchanged Attic sentinel;
6. at the REPL, confirm the stale name is undefined, then define and call the
   fresh fixture function;
7. capture the final header and cleared C2J.

The bound runner is
`scripts/c2-link57-destructive-restage-hw.sh`.  Its ordered actions are
`prepare`, `negative`, `confirm-negative`, `repair`, and `final`.
`confirm-negative` is deliberately separate: the memory capture cannot claim
the rendered `E25` line until the operator has actually seen it.  Likewise,
`final` is invoked only after the three printed REPL
observations have been reported.

Any READY publication in the destructive branch, any nonzero byte in C2J
before the fresh append, any Chip-plane identity mismatch, or any stale
callability is first red.  C4 closes only when the host preparation receipt
and the same-identity hardware receipt are both green.
