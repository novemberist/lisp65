# C2.2 runtime-overlay DMA completion contract

Status: contract and implementation proof complete, 2026-07-21. Strict
L65R-v3 host and terminal-floor WPLTO gates passed. The one authorized Link 36
stopped before its Resident-Island seed could be published; no product closure
or hardware run exists, and the terminal rule selected C2-lite automatically.

## Source finding and hardware truth

The pinned MEGA65 Chipset Reference says that the processor stops executing
instructions until a DMA job completes. Enhanced DMA at `$d705` selects
per-job options while retaining the F018/F018B execution model. The current
official User Guide source says the same, and the inspected `mega65-core`
development source exposes no documented software-readable busy bit for an
ordinary DMAgic job.

Hardware has now disproved two local completion assumptions:

1. Link 34 resumed with two different wrong CRCs over one 1,156-byte
   Attic-to-Bank-0 target.
2. Link 35 waited for a chained `$a5` fill marker, then still failed the first
   target CRC. Class-B cycle 2 replaced only the two-byte operand of that
   failure jump with a same-size self-loop. Read-only JTAG captures showed:

   | Capture after launch command | CRC | Bytes differing from payload |
   | ---: | ---: | ---: |
   | 1 ms | `$e8d8` | 1,133 / 1,156 |
   | 691 ms | `$e856` | 0 |
   | 2,381 ms | `$e856` | 0 |

   The source remained byte-identical, the marker was `$a5`, and execution
   remained at Boot/INSTALLING with the exact 1,156-byte length live and no
   wipe or verifier call. The destination therefore converged after the marker
   and after the product's first failed CRC.

The marker is an **acceptance witness**, not a completion boundary. It may
remain as a diagnostic ordering signal, but no product consumer may treat it
as proof that destination bytes are ready. The result strengthens upstream
candidate L10; it is still not a claim against current `mega65-core` HEAD. The
tested device's exact core identity was not captured. A core ID/version is a
mandatory field of the next reduced hardware reproduction and of any upstream
submission.

## Product rule: content, not signal

`rtov_read` submits a transport and returns **untrusted destination bytes**.
Neither the documented CPU stall nor the chained marker authenticates their
contents. A consumer may inspect, parse, execute, copy onward or publish those
bytes only after the content proof assigned to that seam has converged.

The general convergence rule is:

1. record the product-owned frame count after the transport marker returns;
2. compute the seam's authoritative CRC over the complete logical object;
3. if it matches, the object is complete and may be consumed immediately;
4. otherwise repeat while the unsigned frame delta is below
   `LISP65_RTOV_COMPLETION_TIMEOUT_FRAMES`;
5. if the CRC still does not match at the boundary, fail closed with
   `VM_RUNTIME_OVERLAY_ERR_COMPLETION_TIMEOUT`.

The content check precedes the timeout check. A matching CRC on the exact
64-frame edge succeeds; a mismatch on that edge times out. Frame subtraction
is modulo 16 bits. The timeout uses the already-owned frame source exposed by
`c2_kernal_frame_count`; no guessed delay loop or new time source is allowed.
The convergence loop begins only after the completion leaf restores the
caller's interrupt state. Every target caller must therefore enter with the
owned frame source active; a caller that cannot supply advancing frames is a
contract violation, not an infinite wait.

### Bound timeout

`LISP65_RTOV_COMPLETION_TIMEOUT_FRAMES = 64` at the product's pinned 50-Hz
frame rate, nominally 1,280 ms. The observed upper bound is 691 ms, or 35
frames after upward quantization. The contract therefore adds 29 full frames
(580 ms) beyond the quantized observation, and 589 ms beyond the raw capture
time. This is a fail-closed ceiling, not a latency acceptance target.

The timeout status is appended to the existing status enum; no existing value
is renumbered. The first, innermost status wins. Outer Island installation may
attach context but must not replace completion timeout with generic `E2f` or
`ERR_ISLAND`.

## Complete seam inventory and disposition

The current source has nine `rtov_read -> consumer` seams. Every seam receives
an expected-content barrier. The original record-capture disposition was
withdrawn after its preflight proved incompatible with the trusted
transaction fast path; L65R-v3 gives each record its own emissions-bound CRC:

| Seam | Completion proof | Disposition |
| --- | --- | --- |
| Catalog header | embedded header CRC | repeat the whole 32-byte header read until its self-CRC authenticates or timeout |
| Catalog directory chunks | header-bound directory CRC | repeat the complete directory CRC pass until it matches; partial-pass success is impossible |
| Requested record entry | L65R-v3 embedded record CRC | repeat the one 32-byte read until its nonzero self-CRC matches or timeout |
| Catalog-verifier payload | verifier-tuple CRC | poll the complete target CRC before verifier entry |
| Record-verifier payload | verifier-tuple CRC | poll the complete target CRC before verifier entry |
| Executable application slice | authenticated record payload CRC | poll the complete target CRC before execution or batch publication |
| Island carrier record | L65R-v3 embedded record CRC | repeat the one carrier-record read until its nonzero self-CRC matches or timeout |
| Island source-CRC chunks | carrier-record payload CRC | repeat the complete streamed source-CRC pass until it matches |
| Final Island carrier transfer | authenticated final carrier-record payload CRC | carry record length/CRC across the serial phase handoff and poll the complete destination CRC before READY publication; prerequisite seed identity is not a runtime comparison |

The two record reads remain standalone but are no longer trust exemptions.
Each is consumed only after its L65R-v3 embedded CRC converges in the existing
32-byte verifier scratch. The aggregate directory pass remains once per append
transaction/generation; it is not repeated for later slices. The contract
introduces no second record buffer or metadata representation.

Host builds retain synchronous `vm_code_load`, but exercise the same
content-proof state machine with injected CRC sequences and frame counts.
There remains one target transport implementation and one timeout constant.

## Proof and mutation boundary

The contract probe pins these model cases before implementation:

- immediate match;
- observed convergence at 35 frames;
- mismatch at 63 frames followed by success at frame 64;
- mismatch at frame 64 producing the specific completion-timeout status;
- 16-bit frame-counter wrap;
- a marker with still-wrong content;
- wrong, zero, stale or nonconvergent L65R-v3 record CRC rejected;
- a v2 record rejected by the strict v3 decoder;
- every one of the nine seams absent in turn;
- timeout/status/50-Hz-source drift;
- an outer layer replacing completion timeout with `ERR_ISLAND`.

The permanent source gate inventories all nine seams, requires both standalone
record reads to be dominated by strict v3 record-CRC convergence, rejects a
second target transport, and rejects any consumer path not dominated by its
assigned content proof. Removing the marker is not a success criterion: it
remains an ordering/diagnostic witness, merely not the completion claim.

## Cost and next gates

CRC polling is paid per logical transport or aggregate pass. The contract
makes no claim that the measured 691-ms convergence is representative of all
Attic traffic. A Whole-Program capacity/placement probe must price:

- the common frame-bounded convergence driver;
- the appended timeout status and truthful display path;
- L65R-v3 record self-CRC convergence;
- all repeated full-object CRC work; and
- the removal of obsolete one-shot CRC/error branches.

Any red bound or structural gate returns to Class C. Only after a green
capacity probe may a promotable product fix be authorized. Its hardware
presmoke reports each seam's observed convergence frames, Boot-to-REPL,
definition first/warm calls, GC block reads, Freezer identity and nested eval.
The values are measurements, not pre-authorized latency exceptions.
