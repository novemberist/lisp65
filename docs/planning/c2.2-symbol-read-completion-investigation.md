# C2.2 symbol-read completion investigation

Status: **closed 2026-07-29: physical DMA row stable; `symname` and its read
seam exonerated; L65E renderer overwrites the correct llvm-mos pointer return
with incidental A/X; two-store deletion parked for v1.2.2**

## Final attribution

The investigation is closed.  The post-`symname` hardware hold captured the
complete expected name in `sym_name_scratch` three times at `$C472`; the
subsequent single/paired/mixed DMA row completed three batches of 256
iterations with no failed Prim-67 read, cell read or record roundtrip.  The
symbol-read seam did not reproduce a completion fault and is not changed.

The v1.2.1 acceptance ELF supplies the missing static link:

- `sym_name_scratch` is `$C1F6`;
- `symname` writes `$F6` and `$C1` to `__rc2/__rc3` immediately before it
  returns, which is the llvm-mos pointer-result ABI;
- `lisp65_error_overlay_entry` calls `symname` at `$C46F`, then executes
  `sta __rc2` / `stx __rc3` at `$C472/$C474`;
- the post-return hold captured incidental `A=$D1`, `X=$8F`, so those stores
  replace the correct pointer `$C1F6` with `$8FD1`.

The damaged DIRMISS text is therefore a renderer-consumption bug, not a
symbol-store, `symname`, or DMA-completion bug.  The convicted correction is
the deletion of those two stores.  It is intentionally not applied to the
already sealed v1.2.1 acceptance candidate; v1.2.1 documents the issue and
v1.2.2 is the first eligible fix release.  No further hardware or DMA
diagnosis is required for this finding.

The permanent attribution gate and receipt are
`tools/host-lisp/c2_v121_dirmiss_renderer_attribution.py` and
`c2.2-v1.2.1-dirmiss-renderer-attribution-receipt.json`.

## Reader inventory retained conditionally

The linked inventory separates four temperatures:

| Seam | Temperature | Runtime use |
| --- | --- | --- |
| `symfn_get` via `sym_function` | hot-critical | `dir_find` reads once for every VM `CALL`/`TAILCALL`; native/tree dispatch and GC add consumers |
| `symval_get` via `sym_value` | warm runtime | global lookup in VM/tree evaluation and one read per symbol during GC |
| `nameoff_get` + `sympool_read` in `intern` | cold but bursty | one pair for every length-filtered candidate, repeated for Reader/compiler/service interning |
| `symname` | cold | printer, diagnostic renderer, session emitter and metadata |

A CRC or frame-bounded retry on every function-cell read is therefore not an
acceptable default fix.

## What source and ELF prove

All four physical readers issue one call to `c2_facade_c2_dma`.  The final
facade owns one 12-byte `c2_dma_list`, fills all fields, triggers normal F018B
at `$D700`, and returns on the next instruction.  Its inline assembly has the
required compiler `memory` clobber.

The bound DMA-completion contract records two additional facts:

- documented normal-DMA semantics stop CPU instruction execution until the
  job completes;
- no software-readable busy register is documented for an ordinary DMAgic
  job.

Consequently a descriptor race is not statically established.  No linked
IRQ/NMI product owner writes `c2_dma_list`, and documented CPU-stall semantics
would prevent C from rebuilding it while the job is active.  Conversely, the
Link-75 capture observed neither the post-`symname` scratch nor either of the
two post-trigger destinations.  The first missing observation is cheaper and
can make the second unnecessary.

## Stage 1: DMA row before require retry

After the Stage-0 capture, regardless of its result, the diagnostic session
submits:

```lisp
(symbol-read-completion-probe)
```

The deliberately missing function enters the diagnostic error overlay.  The
overlay first reads the same two bytes from the successor's Bank-5 name-offset
region through the real `c2_dma_list`/`$D700` seam:

1. **Single lane:** poison A, submit once, save A immediately, leave the
   descriptor untouched, then save A after a bounded settle interval.
2. **Paired lane:** poison disjoint A/B, submit A, immediately rebuild the
   same descriptor and submit the same source to B, then save both.
3. **Mixed lane:** execute the real workload-shaped boundary sequence below.
4. Repeat all lanes 256 times in each of three identically initialized
   batches.  Publish the four homogeneous counters, one 256-bit failure bitmap
   per mixed substep and batch, the first failing substep/sample, and a hash of
   every ordered observation in diagnostic-only scratch, then hold.
5. The harness captures every read-only Bank-5 oracle before and after the
   row.  The diagnostic session identity is then discarded.

### Mixed lane: real-shape bank and direction changes

The mixed lane is permitted only with `C2J=CLEAR` and no append/emitter owner
of phase scratch.  Its only Chip-RAM write target is 64 bytes starting at the
live published C2D end inside the uncommitted append-scratch span.  For Link 75
that is `$8430…$846f`, strictly below the `$BD00` Region-1 floor.  A successor
must rederive both addresses and prove the same exact meet; `$8430` is evidence,
not inherited authority.

Each iteration performs these operations without an intervening Lisp form:

1. one **actual** `(%c2d-byte 0 0)` / Prim-67 read, Bank 5 → Bank 0,
   checked against C2D magic `$43`;
2. one 64-byte record-shaped seed, Bank 0 → Bank 5 append scratch.  Its bytes
   are a deterministic function of iteration and byte index.  Every batch
   therefore replays the identical stimulus, while adjacent iterations differ
   so a stale result cannot compare equal accidentally;
3. after the seed submission returns, poison and lifetime-reuse that
   probe-owned Bank-0 buffer, then read back Bank 5 → Bank 0 and check it
   byte-for-byte.  The reuse is intentional: a write job that returned before
   consuming its source is exposed at this exact boundary;
4. one real two-byte value-cell read for canonical `lisp_t`, Bank 5 → Bank 0,
   checked against the live `lisp_t` word.

Thus the sequence crosses the same shared descriptor through a one-byte read,
a record-sized write/read boundary and a two-byte cell read, alternating
Bank-5/Bank-0 direction without changing a published C2D byte, code byte,
symbol cell, Service record or persistent counter.

The three batches are part of the evidence, not repetition for confidence:

- all mixed bitmaps zero: **stable**;
- a nonzero bitmap, first failing substep and samples byteidentical in all
  three batches: **deterministic**;
- any nonzero failure with differing signatures: **intermittent**.

The receipt retains the bitmaps and observation hashes, not merely totals.
Determinism points first toward boundary/descriptor ordering; intermittence
points first toward content-defined completion.  Neither label authorizes a
fix without the failing substep attribution.

The outcomes are deliberately asymmetric:

- A changes toward the source without another submission: genuine
  destination nonconvergence;
- the single lane is stable but the paired lane is not: shared-descriptor or
  back-to-back submission lifetime;
- both homogeneous lanes and the mixed lane are stable: no reproduction and
  no fix;
- the single lane remains wrong without convergence: the read seam is
  confirmed, but this discriminator cannot choose a fix.

Both diagnostic variants are discarded after capture.  No canonical
`require`/`defstruct` retry runs before Stage 1 has classified the physical
small-read seam (or an attributed fix has been qualified).
