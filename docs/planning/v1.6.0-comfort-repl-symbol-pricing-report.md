## 2. Why zero new symbols remains impossible

The native REPL owns a static C `read_line()` and calls it directly. Redefining
the public Lisp `read-line` function cannot replace the native loop or enter a
shelf-library loop. A valid Comfort REPL therefore needs a callable shelf
entry.

The standing design names two distinct canonical symbols:

- `repl-comfort`, the shelf designator used by the default init;
- `repl`, the callable entry described as `(repl)`.

Neither exists in the current product/library union. They cost two slots and
18 NUL-inclusive name bytes. With no reclamation the projection is 30/544,
or 29/540 after calibration, and fails.

## 3. The third reclaim

The predecessor pricing found two cursor helpers with one literal call site:
`%rl-dispatch` and `%rl-put`. Together they reclaim two slots and 21 name bytes,
but their 32/565 result calibrates to **31/561** and is release-red.

The complete emitted candidate call graph contains a third low-risk private
wrapper:

- `%take`, six NUL-inclusive name bytes;
- exactly one caller and call site: `butlast`;
- non-public and non-recursive;
- body: one call to the existing `%take-into` worker.

The gate does not accept this from source shape alone. It marks `%take`
private-inline in the real resolved Workbench suite, runs the real compiler and
all **247 cases**, and requires the `%take` runtime entry to be absent while
`butlast` remains present. The probe is green and reduces the resolved runtime
function inventory by exactly one.

The selected arithmetic is now:
