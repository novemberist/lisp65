# v1.2.4 `fx` — host-first contract and target boundary

Status: **implementation candidate; target semantics wait for Phase M**

`fx` is a Q8.7 convention over the existing signed fixnum.  A raw value of
`192` denotes `1.5`; all 32,768 fixnum bit patterns are valid fixed-point
values, from `-128.0` through `127.9921875`.  This is deliberately not a new
numeric type and creates no tag, root, resident state or dynamic library
dependency.

The public surface is `fx`, `int->fx`, `fx->int`, `fx+`, `fx-`, `fx*`,
`fx/` and `fx->string`.  `fx` keeps the useful part of the historical
constructor: its optional second argument is a signed count of raw 1/128
units.  The old recursive implementation and its `integer->fx`,
`fx->integer`, variadic arithmetic and `fx<` surface remain superseded.

Addition and subtraction either produce an in-range raw fixnum or take the
existing arithmetic error path.  Multiplication and division round to nearest,
with exact half ties away from zero.  Conversion to an integer truncates toward
zero.  Overflow never saturates or wraps, and division by zero uses the same
existing arithmetic error path; this slice adds no status code or error text.
`fx->string` emits the exact terminating decimal and always includes a
fractional digit.

## Why the implementation lives in Lisp

The resident geometry is closed, while Bank 2 has roughly 24 KB of headroom.
The existing strict-byte `peek` and `poke` primitives already expose the
MEGA65 math registers.  Therefore orchestration stays in the base composition:
no primitive, dispatcher case, overlay or resident byte is justified.

The implementation writes unsigned 32-bit magnitudes to `$D770-$D777`.
Multiplication consumes the 64-bit product at `$D778-$D77F`.  Division writes
the magnitude of the dividend shifted left seven bits, consumes the quotient
at `$D76C-$D76F`, and uses bit 7 of `$D76B` as the half-unit rounding bit.
Phase M must confirm the high product and fraction layout before a product
link is allowed.

There is one non-obvious ownership rule.  Ordinary `*`, `/` and `mod` already
use this same hardware unit through the compiler runtime.  Consequently every
input byte is computed before the first register write.  Between that write
and the final result read, only byte I/O, busy-bit tests and control flow are
legal.  An arithmetic helper in that interval would overwrite the transaction
being observed.  The permanent gate treats this as a structural rule, not a
comment.

## Proof boundary

An independent integer oracle supplies the Q8.7 answers.  The real Lisp source
then runs twice: once from source-compiled P0 objects and once from the emitted
artifact, both against a modeled register file with positive execution
witnesses.  Mutations cover the scale, tie rule, result-byte selection,
transaction ownership, packaging and a built-but-not-run lane.

The one authorized WPLTO measures Bank-2 and every closed resident wall.  It is
not a product link.  Until M1 and M3 run on the target, the honest claim is
only that the source, artifact and documented register model agree.
