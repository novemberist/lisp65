# C2.0 KERNAL residency audit

Status: **read-only audit complete; no unmap authorized**

Date: 2026-07-19
Receipt: `tests/bytecode/dialect-v2/evidence/architecture-blocks/c2-kernal-residency-audit-receipt.json`

## Result

Unmapping the KERNAL can free exactly **8,192 bytes of 16-bit CPU address
space** at `$e000..$ffff`. It frees zero Bank-0, EXT or Attic bytes. It is a
credible way to fund a C2 runtime slice only after the product owns keyboard
input and interrupt state.

The current Workbench is not ready to do that:

| Dependency | Current product evidence |
|---|---|
| CRT output | one `JSR $ffd2` (`CHROUT`) before `main` |
| keyboard input | four `JSR $ffe4` (`GETIN`): REPL and three VM paths |
| RUN/STOP | `lisp_poll()` reads STKEY `$91`, maintained by the KERNAL IRQ |
| IRQ/NMI | no product handler is installed; platform handlers remain authoritative |

Screen output after startup already uses the native driver. MEGA65 disk I/O
uses F011/HyperTrap rather than the C64-only KERNAL file branch. The C1 timing
probe reads `$D7FA` directly, not a KERNAL jiffy variable; its hardware meaning
continues to be bound by the existing latency-probe evidence, not by this
audit.

## Official memory facts

The audit binds the repository's 2026-04-08 MEGA65 Chipset Reference snapshot
(SHA-256 `107610ae…ed220`):

- MAP selects eight 8 KiB slabs in the 16-bit address space and overrides the
  legacy banking mechanisms (pp. 9–10);
- the KERNAL window is `$e000..$ffff`, backed by the C65 KERNAL at
  `$3e000..$3ffff` (pp. 9–11, 53);
- Attic is an independent 8 MiB physical domain at
  `$08000000..$087fffff` in the 28-bit address space (pp. 5–6);
- `$D60A`, `$D610`, `$D613/$D614` and `$D619` expose the typed event queue,
  modifiers and matrix access needed to replace GETIN/STKEY (pp. 102–104).

## Duties acquired by an unmap

The C2 block that unmaps KERNAL must deliver all of these together:

1. replace every GETIN path with the typed `$D60A/$D619` event queue;
2. source RUN/STOP from that event path or the hardware matrix;
3. install IRQ and NMI vectors that remain reachable while ROM is absent;
4. retain a KERNAL-independent frame/timing source;
5. prove Freezer return either restores the C2 map or fails closed and
   re-establishes it before product code resumes;
6. keep cold boot and platform reset on the existing firmware path;
7. show in one real link that the 8 KiB window actually funds the intended
   C2 code rather than becoming unallocated optimism.

The clean architectural cut is therefore a single reviewed block:

```text
typed event queue + RUN/STOP source + owned IRQ/NMI + post-boot KERNAL unmap
```

Splitting those duties would create a state where the product appears to have
more address space but silently loses input or abort safety. C2.1 may compare
this block against a layout that keeps KERNAL resident; neither path is
authorized by the audit itself.
