## W1 — the capacity truth

The sealed v1.2 product set `37998ce7…941d` used 34,542 bytes of Bank-2
static code.  Link 67 adds F1 and F2 and uses 34,990 bytes.  The resulting
30,546-byte gross gap is real, but it is not a one-sided library purse:
persistent code grows upward while transient evaluation grows downward.
Every booking must prove their exact meet.

The current C2D-v6 counts and hard limits are:

| currency | used | cap | raw headroom |
|---|---:|---:|---:|
| images | 6 | 64 | 58 |
| entries | 602 | 2,048 | 1,446 |
| resolutions | 2,299 | 4,096 | 1,797 |
| roots | 283 | 1,536 | 1,253 |
| Bank-2 code | 34,990 B | 65,536 B | 30,546 B |
| C2D append scratch | 33,840…48,384 | 14,544 B span | 1,818 eight-byte rows |

These numbers are independent limits, not currencies that can repay one
another.  In particular, the entry headroom is shared with active transient
entries through the exact-meet rule, and the C2D scratch floor at `$BD00`
protects the Bank-5 Region-1 store.

The Session overlay family remains 64,926/65,536 bytes in Region 0 and
1,956/2,032 in Region 1, leaving 610 and 76 bytes respectively.  Those are
runtime-implementation currencies, not library payload credit.  A new carrier
still pays a 256-byte pack quantum, catalogue entry and the 1,792-byte slice
cap in its own product-shaped map.  F3 is the concrete warning: its 2,552-byte
single carrier was parked for a semantic split, not charged against another
wall.

The first library probe therefore starts with a zero-byte resident budget and
zero new Session records.  It reports exact Bank-2, C2D count and scratch
deltas and rejects before `C2J ACTIVE` if any one fails.  The seal contains no
honest free-byte claim for heap or symbol-name storage, so both are explicitly
OPEN measurements rather than inherited 1.1 estimates.  This is a deliberate
null-credit line: avoided resident machinery is not library capacity.

## W2 — `require` and L65P-v1

`(require 'seq)` is an explicit, idempotent cold load.  It returns `t` both
after a successful load and when that exact library identity is already loaded
in the current generation.  Undefined-function diagnostics may suggest the
form but never auto-load it.  A same-name/different-identity request is an
error, not a hot replacement.

There is one generated work-medium library index.  Its rows bind canonical
name, u32 identity, artifact length, device CRC, host SHA-256, dependencies,
exports and exact C2 capacity deltas.  `require` never carries a second
handwritten table.  It resolves a unique row, validates the dependency graph
and all capacity currencies, stages and authenticates the immutable artifact,
then uses the existing persistent C2-lite append transaction.  Code executes
from Bank 2; no post-publication Attic read is legal.

The project manifest is one unevaluated Lisp data form:

```lisp
(l65-project-v1
  (name "asteroids")
  (requires seq random)
  (sources "src/macros.l65" "src/game.l65")
  (default-target "src/game.l65"))
```

Unknown/duplicate fields and trailing forms are format errors.  Source order is
semantics and is never normalized.  Paths are relative media paths; device
prefixes, absolute paths and `..` are rejected.  The default target must be one
of the sources and grants write-target authority only—it performs no implicit
write.

Before mutation, `load-project` resolves the complete name-to-identity set and
records a resolution lock.  This preserves the friendly source manifest while
giving later ship tooling a reproducible identity set.  Dependencies are
loaded in declared order, then sources in declared order.  Each individual
library append is atomic.  If a later dependency or source fails, already
committed libraries remain valid; nothing pretends that the whole dependency
graph was one C2J transaction.

The existing file workflow and plain `(load)` remain first-class.  Unload,
automatic undefined-symbol loading and ship packaging are outside v1.
`restart-repl` remains the C2.3 composition switch: until it exists, a fresh
generation requires explicit `require`/`load-project` execution.  Manifest v1
freezes the read-only composition meaning now; later packaging may consume it
but may not reinterpret it.

## Halt #3 decisions

1. Accept the W1 hard budgets as nonfungible, including zero resident bytes
   and zero new Session records for the first probe?
2. Accept L65P-v1 as one unevaluated data form, resolved by one generated
   identity-bound library index and captured in a generated resolution lock?
3. Open the library era with a host-first index/`require`/capacity-preflight
   probe, while `restart-repl`, unload and ship packaging remain out of scope?

The accompanying gate checks every number against the sealed/current
authorities and runs the complete positive model plus the listed mutations.
Its green result is a review gate only, not implementation authority.

## Halt #3 disposition

The owner accepted all three decisions without amendment.  W1 is the active
budget authority; L65P-v1, the single generated index and the resolution lock
are the accepted contract direction; and the host-first `require` probe may
proceed.  This authorizes host models, fixtures, generated index artifacts and
receipts only.  A target implementation, product byte or product link still
requires its own freight review.

The first recommended library freight is `defstruct`.  The second is
`random` on the ring-buffer substrate: lagged Fibonacci as the portable
baseline, with the now-available bitops permitting a measured xorshift option.
