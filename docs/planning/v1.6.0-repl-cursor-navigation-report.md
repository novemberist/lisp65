## 1. Shipped semantics

The editor uses a mutable forward sentinel chain. Its cursor identity is the
cell immediately before point, so inserting in the middle is a constant-size
link operation rather than a reconstruction of the line prefix. A fixed
eight-cell state records head, point, tail, logical position, length, viewport
start, screen width, and row.

The in-scope bindings are:

| Action | Keys |
| --- | --- |
| Move left | Cursor Left, `C-b` |
| Move right | Cursor Right, `C-f` |
| Start/end of line | `C-a`, `C-e` |
| Delete backward | Delete, legacy code 127 |
| Delete forward | `C-d` |
| Accept | Return |

Left/backward-delete at the start and right/forward-delete at the end are
no-ops. RUN/STOP remains fail-closed. Word motion and `C-k` remain outside this
card, exactly as commissioned.

The editor owns one screen row and renders a cursor-following viewport. Point
is shown with attribute 129; end-of-line is a visible blank cursor cell. Moving
across either viewport edge repaints from the new window start. Return removes
the cursor attribute before handing the completed line to the existing reader.

## 2. One keymap, two consumers

`config/v11-l-lite-keymap.json` now carries the REPL-line projection alongside
the existing IDE bindings. `tools/host-lisp/v11_l_lite_keymap.py` validates that
projection and generates the marked binding block in
`lib/stdlib-read-line.lisp`. The editor therefore does not own a second manual
table.

The end-to-end keymap gate remains green across all 41 canonical bindings. The
new cursor gate rejects both source drift and an executable mutation that
changes Cursor Left in the generated table, proving that parity reaches the
real source and emitted-artifact behavior rather than stopping at schema
validation.

## 3. Executable proof and allocation

The real P0 suite runs in two lanes: source and emitted artifact. Ten navigation
cases per lane cover Cursor Left insertion, `C-b`/`C-f`, `C-a`/`C-e`, backward
and forward deletion, both boundary classes, legacy Delete 127, Return, and
RUN/STOP. Three additional generated limit cases cover exactly 250 characters,
rejection of the 251st character, cursor-following viewport motion, and the
one-column left-scroll edge that distinguishes narrow repaint from a full
window repaint.

The allocation model covers 15 cases, 561 input events, and every possible
incoming nursery phase:

- nine cells are allocated once before the first key (sentinel plus state);
- at most four cells are allocated after any input boundary;
- navigation and deletion use at most the three cells belonging to
  `key-event`, with no editor allocation for `C-a` or `C-e`;
- no key can trigger more than one collection in the 192-cell nursery model.

Twelve source mutations and one real executable mutation are rejected. The
card receipt is
`tests/bytecode/dialect-v2/evidence/architecture-blocks/c2.3-v1.6-repl-cursor-navigation-host-first-receipt.json`.
