# C2.2 hot-refill Link-29-seams amendment

Status: **one amended Resident-Island capacity/placement seed authorized**

Date: 2026-07-20
Machine-readable contract: `config/c2-hot-refill-link29-seams-amendment.json`

## Reason for the amendment

The first Resident-Island attempt proved the semantic boundary but changed the
already proven child resolver and entry-record seams. Those changes consumed
171 bytes in the closed `$E000` window: +73 bytes in the child resolver,
+123 bytes in `c2_entry_records`, and a 25-byte credit in
`c2_product_entry_length`. The attempt stopped at that first red gate without
creating a product link.

This amendment moves only the genuinely new entry materializer. The Link-29
child resolver, entry-record algorithm and entry-length seam remain unchanged
and keep their Link-29 placement. External linkage of `c2_entry_records` is the
only permitted source-level visibility change, solely so the Island resident
can call the existing seam.

## Hard placement rule

`$E000` delta is a pass/fail condition, not an observation. Total occupied
bytes and every named section in the owned window must be identical to Link 29.
Any nonzero delta stops the attempt before all later structural gates and before
any product link.

The sole new resident is `c2_stream_product_materialize_entry` in the Resident
Island. Both the VM refill path and the retained phase-13 entry call it. There
is no second record walker, descriptor interpreter, or materializer.

## Evidence and claim limit

The full 588-entry/1,931-value parity suite, nested-rematerialization case, four
pre-publication content mutations, and two post-publication transport failures
run freshly. The source gate binds the retained Link-29 seams rather than
inheriting their result from the failed attempt.

Exactly one product-shaped seed link is authorized after those host gates pass.
It exists only to measure placement, capacity and structural closure. It makes
no boot, hardware, latency, promotion or performance claim and authorizes no
product link. Link 29 remains untouched until a separately authorized successor
has passed every required gate.
