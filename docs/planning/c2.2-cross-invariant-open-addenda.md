## B3 — RUN/STOP during DMA

The transport seam owns its descriptor, convergence scratch and mapping from
submission until the complete object has passed its content proof and the seam
has restored its exit invariants.  No `lisp_poll`, `lisp_abort`, `longjmp` or
C2J abort landing is legal inside that interval.

RUN/STOP is not lost.  Its source may set one idempotent pending bit while a
transport is in flight.  The bit is consumed exactly once at the first safe
evaluator boundary, before another Lisp evaluator step.  Thus interruption is
deferred, not disabled:

1. before submit: latch, then return normally to the boundary;
2. submitted but unproved: latch only;
3. content proved but seam state not restored: retain the latch;
4. first safe evaluator boundary: enter the one C2J-aware abort landing.

Every linked product DMA seam must run the same five cutpoints: before submit,
after submit, after at least one convergence mismatch, after content match and
at the first safe boundary.  The no-break state and the pre-rollback state must
be exact.  After delivery, the normal abort contract must restore C2D, C2J,
exports and both Chip planes exactly.

This rule composes with D3: D3 defines the gapless physical source; B3 defines
when its pending edge may become a non-local exit.

## C3 — Freezer and the handoff

The old wording blurred two mechanisms.  On the pinned core, double-RESTORE
enters hypervisor trap `$42` at an instruction-fetch boundary.  It does not
enter the guest NMI vector.  A guest NMI is a separate event and, unlike an
IRQ, is not masked by `SEI`.  Both obligations therefore receive explicit
owners.

| Cutpoint | Mapping | vectors/NMI | published state | only legal continuation |
|---|---|---|---|---|
| H0: before `SEI` | firmware | firmware | firmware-owned | exact frozen firmware instruction; later ownership starts from its first check |
| H1: after `SEI`, before MAP | firmware | firmware | replacement-armed | exact handoff instruction; no product/evaluator edge; remaining checks run |
| H2: after MAP, before publication | C2 | C2 | handoff-closed | handoff closure only; validate mapping, vectors, abort and frame sources before publication |
| H3: steady state | C2 | C2 | product-owned | identity-specific Freezer verifier must accept E000, vectors, map generation and both Chip planes before the fixture releases ordinary evaluator work |

No state is allowed to “recover” by guessing a later state.  A cutpoint may
resume only in its own closure and take the next normal, checked transition.
At H0–H2 there is no edge to Lisp.  At H2, any owner or identity mismatch
fails closed.  The owned NMI handler acknowledges only its source, preserves
the complete context, allocates nothing and calls no Lisp; it cannot
manufacture `product-owned`.

The host fixture covers all H0–H3 tuples and keeps Freezer trap and guest NMI
separate.  A non-promotable hardware carrier then stops at H1, H2 and H3.
After thaw it enters a verifier, never the evaluator.  The verifier records the
exact owner tuple or fails closed.  If the pinned platform cannot make a
cutpoint deterministic, that cutpoint remains explicitly OPEN; it is not
waived.

This is also why C1 hardware waits for this review: the open-transaction
Freezer fixture must consume one unambiguous handoff/return model.

## D3 — queue-full RUN/STOP

The pinned MEGA65 core answers the choice left open by the matrix:

- the typed queue holds one presented head and four buffered events;
- a sixth event is not enqueued while those five are occupied;
- the combined physical matrix remains independently readable;
- RUN/STOP is matrix ordinal 63, segment 7, active-low bit 7, and maps to
  normal code `$03`.

The product therefore uses the physical matrix **edge** as the sole
authoritative abort source:

1. `$D614` is fixed to segment 7 before the owned raster IRQ starts;
2. the IRQ samples `$D613 & $80`;
3. release arms; the first pressed sample latches pending and disarms; holding
   cannot repeat; release rearms;
4. a typed queue head whose PETSCII code is `$03` is dequeued but discarded as
   an abort source;
5. B3 consumes the matrix pending bit once at its safe evaluator boundary.

This is not a second handwritten keymap.  The segment, bit and `$03` identity
are generated by a source-identity gate from pinned core ordinal 63.  No
product table maps keys a second time.

The hardware fixture fills all five queue positions with distinguishable
ordinary `(code, modifiers)` tuples, presses and releases physical RUN/STOP,
then resumes consumption.  It requires one abort and the same five ordinary
tuples in the same order.  A queued `$03` must not produce a duplicate.

## E5 — fifth nested evaluation

Depth four remains the contract maximum.  Requesting depth five is not bad
bytecode and is not an LCC installation error.  It receives the next
append-only stable identity:

```text
code        63 ($3f)
C name      LISP65_ERR_C2_NESTING_DEPTH
text        eval: nesting depth exceeded
fallback    E3f
detail      Fixnum 5
```

`LISP65_ERROR_CODE_LIMIT` rises from 63 to 64; codes 0 through 62 do not
move.  The detail is the refused depth, while the configured maximum remains
four.

The check occurs before journal publication, Attic or record writes,
watermark changes, export writes or READY changes.  The normal error surface
must render the stable error and Fixnum detail, and the ordinary Lisp error
boundary must be able to catch it.

The end-to-end fixture enters nested `eval` through the real public surface.
Depths one through four must run and restore exact state.  Depth five must
render the new error, preserve C2D, C2J, active Session-Attic, both Chip
planes, exports, READY, family and generation byte-identically, and leave a
REPL which subsequently evaluates `t`.
