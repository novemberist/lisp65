# C2.0 design inputs — consolidated dossier (2026-07-18)

Purpose: everything the C2.0 address/identity contract must honor, collected
from receipts, memos and decisions scattered across two weeks. Reviewer
compilation (Claude); authoritative sources linked per item. Index this file
on the next docs commit.

## Binding design laws

1. **Substitutive, never additive** (failed L65S-v4 probe): the decoder's
   space comes from retiring the L65M materializer; plan a staged swap with
   a defined interim state. Evidence: v4 device link failed +84 B VMA /
   3,326 B vs 1,792 B slice while host model passed.
2. **Physical addresses are a non-pointer domain**: 28-bit DMA/Attic
   endpoints as `uint32_t` or DMA-list bytes, never through 16-bit
   `uintptr_t` (restart-repl attic probe; llvm-mos warns but truncates).
3. **Session/pristine separation is the core deliverable** — three
   independent demonstrations that it is missing today: C1 retirement cost
   (definition→call 1.9 s), the restart-repl failures (bank 5 is
   session-mutated; recovery needed pristine restore), and reset-stale
   literal bindings (v4 metadata audit: no metadata pointer survives in the
   published ABI, but committed code contains resolved objects).
4. **Attic tenants follow the cache rule**: SHA/generation-verified,
   reconstructible, never the only copy of user data.
5. **Fail-fast process applies**: pre-smoke new behavioral surfaces before
   any chain; emulator dry-variants where Xemu models the mechanism
   (typed queue precedent).

## Inherited assets (start capital)

- **Host-validated v4 layout model**: both variants at 65,367 B, five
  containers reconstructed byte-identically, strict version/mutation matrix
  passed, 458,793 B four-role envelope
  (`v11-l65s-v4-layout-model-receipt.json`, one-attempt outcome receipt).
- **Receipt-confirmed metadata anatomy**: 36,260 B metadata = 55.6% of
  shelf payload; load-time literal machinery 27,744 B (nodes 17,370,
  patches 6,900, index 3,474) + string pool 5,350 B
  (`v11-shelf-metadata-audit-receipt.json`). Off-catalog metadata needs an
  identity-bound reset-persistent source (D81-only side files would regress
  the one-swap media contract).
- **34 unresolved metadata entries** (native/macro arities) recorded in the
  function-metadata contract — ide-help needs them resolved in the C2 era.
- **KERNAL residency audit commission** (1.2 memo): active calls (GETIN)
  plus passive dependencies — **RUN/STOP break reads KERNAL-IRQ-maintained
  STKEY $91 in `lisp_poll()`**; unmap kills the break unless re-sourced
  from the typed queue/matrix. Potential self-funding block: typed-queue
  driver + KERNAL unmap (~8 KB address-space relief at the top of the map).
- **Three restart-repl failure receipts** as the C2.3 restart design base
  (platform reset exits product; _start alone insufficient; attic-restore
  decoder cost 1,291 B resident — all pointing at pristine/mutable split).

## Budget reality the contract must fit (wave-2-seal state)

Fixed overlay 0 B; runtime-overlay bank ~64 B; resident island 120 B;
installer slice 22 B; shelf catalog 65,368/65,535 (167 B → 367 B after the
name harvest); Bank 0 ~1,907 B reserve (371 B over target); EXT ~8.6 KB
over floor; symbols 320; name pool 4,897 B. Zero-headroom resources may not
be debited by assumption (C2.1 rule); pack quantum 256 B; slice cap
1,792 B; per-slice VMA 0xC356.

## C2 freight list (what lands on the new foundation)

C2.2: product libraries + compiler tier conversion; catalog/format
evolution (u16 retirement); **bitops** (opcode cut passed ABI gate, blocked
only by catalog); **gc/room/error trio** (semantics pinned and host-green;
shared carrier category; no resurrected resident dispatcher); H/I/J
substrate + metadata shelf delivery. C2.3: cure acceptance (owner-pinned
ceiling 15 frames typical / 16 stability, band defined at pin time; warm
≤10 frames; no exception renewal), **restart-repl** (double-call case),
retirement of the dated 1.9-s exception. Post-C2 1.2 items: `while`
(constant-stack proof), `show` (registry + scanner + drift rule). Workbench
group (1.2/1.3 per memo): definition algebra, file management
(delete/rename/copy — copy via chain duplication), **chunked save** (lift
the 8,192-B M65D write limit toward the 38,400-B load parity), manifest as
write-target authority.

## Open questions C2.0 must answer

1. Extended code address format (width, encoding, directory record shape)
   and its resident decode cost — the v4 lesson says budget it from
   materializer retirement, not from headroom.
2. Literal/mutable resolution model: indirection table vs. per-reset
   relocation; how exports/entry-refs bind late without patching code bytes.
3. Reset/restage contract: what is rebuilt, what is invalidated, and the
   negative fixtures proving stale bindings are unreachable.
4. Code-window geometry and refill discipline (C2.1 measures the cost; the
   contract defines the mechanism; the cure ceiling bounds the answer).
5. Interim state of the staged swap: which loader coexists with which
   format at each promotion boundary, and the strict decoder rules per
   stage.
6. Where the KERNAL audit lands: does address-space relief fund the
   decoder, and does the typed-queue driver ride the same block (L-full)?

## Draft disposition — 2026-07-19

The open questions above now have a concrete review draft in
[`c2.0-address-identity-contract.md`](c2.0-address-identity-contract.md), with
machine-readable contracts in `config/c2-address-identity-contract.json` and
`config/c2-freight-triage.json`. The draft chooses:

- the existing 12-bit BCODE directory index as a session-local logical handle;
- u8-region + u24-offset persisted addresses, with physical endpoints confined
  to the `uint32_t`/DMA-list seam;
- immutable normalized code plus eight-byte literal descriptors and a mutable
  per-session resolution plane;
- a proof-only C2.1 target followed by one atomic C2.2 product cut, never a
  dual-decoder product;
- the requested 3/3/3 MUST/SHOULD/COULD freight order.

The KERNAL question is separately answered by
[`c2.0-kernal-residency-audit.md`](c2.0-kernal-residency-audit.md): 8,192 bytes
of address-space relief are real, but the current product still depends on one
CRT CHROUT, four GETIN calls and IRQ-maintained STKEY. Unmapping therefore
requires typed input plus owned IRQ/NMI state in the same reviewed block.

Both artifacts remain non-authorizing until owner/reviewer approval.
