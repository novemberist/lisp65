# C2.2 Phase F — Halt #2

Status: Class-C owner approved
Date: 2026-07-27
Baseline: promoted v1.2.0 seal `c2-lite-r6-g6-hardware-acceptance-19aa835`

## Owner decision

Approved as one disposition:

1. build one successor product link containing F1 and F2;
2. keep F3 parked with no active product bytes;
3. accept the F5 paper decision (`while`; `catch`/`throw` deferred);
4. after the link passes its full fresh gates, run the prepared F4 plan in
   one hardware session.

The approval authorizes exactly one F1+F2 successor link and one subsequent
S1 hardware session. Neither had occurred when this review package was
accepted.

## F1 — n-ary published value calls: green, mandatory

Calls to a published bytecode function bypass compile/append when every
argument is already a value (Fixnum, String, `nil`, `t`, or exact unary
`quote`). Variables, nested or effectful forms, primitives, macros and
undefined operators retain the full ceremony fallback. Arity remains the
CodeObject/VM truth; no Lisp-side arity registry was added.

- 18 executable direct/fallback/equivalence fixtures;
- 10 source mutations rejected;
- Bank 2: 34,542 → 34,748 bytes, **+206**;
- entries 590 → 596; resolutions 2,273 → 2,283; roots unchanged at 283;
- no new resident state, transaction byte or root;
- hardware latency remains unclaimed until S1.

## F2 — bitops: green, proposed for the same link

`logand`, `logior`, `logxor` and `ash` occupy the four ABI IDs already
reserved for Dialect V2. The first three share the existing tagged binary
dispatch; `ash` is a 112-byte non-LTO leaf and is covered automatically by
the ELF-derived assembler-ABI gate.

- 28 positive cases over direct and funcall routes;
- 8 type, arity and range negatives;
- 16 source mutations rejected;
- combined F1+F2 Bank 2: **34,990 bytes** (+242 over F1, +448 over v1.2.0);
- entries 602; resolutions 2,299; roots 283;
- current WPLTO walls: text 90, E000 151, fixed block 2, BSS 137,
  island 69, Session aggregate 610 bytes of headroom.

All walls are positive. No hardware behavior is claimed yet.

## F3 — `gc`/`room`/`error`: parked at First Red

The required shared-carrier semantics passed host validation (19 mutations,
9 routes, 6 negatives), but its actual cold Buffer-read slice measured
2,552 bytes against the immutable 1,792-byte cap: **760 bytes over**. The
growth attribution was 951 bytes `buffer_room`, 1,444 bytes carrier entry
and 157 other bytes.

Per the work plan, there was no resident negotiation and no second
placement attempt. The candidate surface was removed; F1/F2 remain
unaffected. F3 contributes no active product byte and is omitted from S1.

## F4 — one-session S1 harness: green, not run

The prepared 12-row session contains:

- boot watch;
- F1 definition, cold n-ary ≤16 frames and warm n-ary ≤10;
- nullary definition/cold/warm regressions;
- bitops positive vector and a type-negative followed by REPL recovery;
- idle Freezer roundtrip with **F3** return and a post-Freezer expression.

All forms parse, all rows are First Red, ten harness mutations are rejected,
and F3 exclusion is itself gated. Product/ELF/core/tool identities bind only
after the approved link.

## F5 — control-flow paper probe: choose `while`

The C2-lite evidence confirms the earlier scope direction. C2J is a
transaction recovery journal whose sole abort landing wipes/restores state
and returns to the REPL top level. It is not a resumable Lisp catch stack.
A real `catch`/`throw` would require dynamic catch frames, GC roots and an
inner VM continuation.

`while`, by contrast, lowers through the existing `JFALSEREL`/`JMPREL` ABI
already used by `dotimes` and `dolist` in both compilers. It needs no opcode
or runtime state.

The terminology is binding even where the approval message uses the older
phrase: `while` is local structured iteration, not a non-local-exit primitive.
The selected scope is “one control-flow repair”.
The paper gate rejects ten drift mutations. F5 has zero product bytes and is
not part of the successor link.

## Review boundary

Approval authorizes exactly one F1+F2 successor link and, only after its
fresh gate closure, the one F4 hardware session. It does not revive F3,
implement `while`, add `catch`/`throw`, or make a hardware/performance claim
in advance.
