# C2.3 v1.4 tick-hook scheduler design

Status: **Phase-C review design; paper only, no product bytes**

Date: 2026-08-03

Baseline: released v1.3.0 / Link 88, with the synchronous `m65-hw`
pilot priced separately for v1.4. This document refines the scheduling section
of `basic65-parity-revalidation-2026-07-30.md`; it does not authorize a hook,
an opcode, a native record, a product link, or a device run.

## Decision in one sentence

A Lisp tick callback is legal only after a resumable compiled-VM continuation
has returned `VM_YIELD_SAFE` all the way to a top-level scheduler. The current
recursive C interpreter has no such continuation representation, and the
minimum mutable continuation state already exceeds every closed resident
state allowance. The next block must therefore begin with **continuation-state
ownership**, not with a public hook API.

## Scheduler placement

The raster IRQ remains unchanged. It acknowledges the owned source, advances
the product frame counter, samples physical abort, and returns. It never
looks up or invokes Lisp.

`lisp_poll()` remains an abort poll, not a scheduler. It executes inside the
VM, evaluator, blocking input, and long-running primitives. It may observe
that a scheduling quantum expired, but it may not call Lisp or mutate hook
delivery state whose consistency depends on the live C frame.

The compiled VM receives a bounded instruction budget. At a legal bytecode
boundary it must serialize the complete continuation, keep every live Lisp
value rooted, set `vm_status = VM_YIELD_SAFE`, and unwind every `vm_run` C
frame. Only the outer scheduler may then:

1. verify that no forbidden owner is live;
2. atomically read `$FF83/$FF84`;
3. coalesce elapsed periods;
4. invoke at most one hook callback;
5. resume the exact suspended continuation.

A tail call may replace the current logical frame. An ordinary call must add
an explicit continuation frame; it may no longer rely on the host C stack as
the only record of `bank`, object offset, object length, resume PC, root-stack
base, value-stack base, and closure/upvalue owner.

## Forbidden callback owners

Every callback entry is forbidden while any of these is true:

- IRQ or NMI context;
- a nested evaluator or primitive C frame is live;
- GC mark, sweep, root scan, or retry is active;
- C2J prepare, append, publication, rollback, or finalization owns state;
- compiler, package resolver, Session service, disk mutation, or abort cleanup
  owns a lifetime;
- the runtime overlay window is occupied;
- the input path is between queue observation and dequeue.

An elapsed tick inside a forbidden owner is deferred. No owner is interrupted
and no second callback queue is created.

## Hook state and delivery

The public design is one hook, not a callback registry. Its designator and
period live in canonical symbol values, so the existing global-symbol root
truth owns them. `nil` disables the hook. The last-delivered frame and the
coalesced count are scheduler state, not IRQ state.

At most one callback runs per scheduler turn. Multiple elapsed periods become
one positive Fixnum count. The count saturates at the Fixnum maximum instead
of wrapping. A period of zero or a non-callable designator is rejected before
installation. Changing or clearing a hook becomes visible only at the next
top-level scheduler boundary.

Normal callback return resumes the exact continuation. A callback error or
RUN/STOP disables the hook, discards the suspended user continuation through
the existing top-level abort cleanup, and returns to a usable REPL. RUN/STOP
during ordinary user code follows the same landing. No callback is retried
after an error.

## Capacity estimate and present disposition

This is a lower-bound estimate, not an admission card.

The current VM uses recursive C calls and file-scope reload state. A resumable
ordinary-call frame must retain at least:

| Field | Bytes |
| --- | ---: |
| code bank, object offset, object length | 5 |
| logical resume PC | 2 |
| root-stack base and value-stack base | 4 |
| flags/closure owner or equivalent aligned tag | at least 5 |
| **minimum aligned record** | **16** |

The editor path has already demonstrated about 24 nested `vm_run` levels.
Twenty-four 16-byte records therefore require **at least 384 mutable bytes**,
before scheduler counters, status, or any guard bytes. This is greater than
the complete 137-byte ordinary Bank-0 BSS headroom and cannot borrow from the
fixed hot block, resident island, `$E000` floor, immutable Bank-2 code plane,
or the 113-byte Session-family remainder. One additional 512-byte Session
record also exceeds that remainder.

The hook design therefore has no honest placement in the current closed
geometry. The next implementation block must first choose and prove one of:

- a bounded continuation plane in extended memory with explicit ownership and
  completion semantics;
- a VM/stack ownership refactor that gives the existing root-stack allocation
  an explicit metadata format without reducing its proved safety margin;
- a separately commissioned overlay/session geometry change.

The Bank-2 public wrapper is expected to be small, but its size is irrelevant
until the mutable continuation and native yield/resume path have an owner.

## Proof plan for the next block

The permanent host model must execute, not merely construct, these cases:

- yield and resume through ordinary calls, tail calls, closures, and a
  streamed code-window refill;
- zero callback entries in every forbidden owner above;
- frame-counter wrap, delayed delivery, coalescing, and saturation;
- RUN/STOP before yield, in a callback, and immediately after resume;
- callback error disables the hook and leaves a live REPL;
- repeated callbacks leave roots, Directory, symbols, C2D watermarks,
  journals, and overlay records unchanged;
- mutation witnesses for a callback from IRQ, `lisp_poll`, GC, transaction,
  or occupied-overlay context;
- target cadence and emulator cadence reported separately.

Only after the continuation plane passes that model may one WPLTO price its
code placement. A crossed resident wall returns to the owner; it cannot be
relabelled as scheduler freight.

## Halt-#1 menu statement

The synchronous v1.4 pilot does not need this machinery: explicit `draw →
wait → draw` and complete SID snapshots are honest today. Continuous sprite
motion, background PLAY/SOUND sequencing, and timer callbacks remain blocked
on a separately commissioned continuation-state/stack-ownership block. The
paper design is review-ready, but implementation is **not presently
admissible** under Link-88 geometry.
