# C2.2 F2 bitops contract

Status: candidate contract for Halt #2 review. No product link or hardware
claim is made by this note.

F2 activates the four opcode identities that the dialect-v2 ABI reserved for
this freight:

| Opcode | Public function | Contract |
| ---: | --- | --- |
| 20 | `logand` | strict binary signed-15-bit fixnums |
| 21 | `logior` | strict binary signed-15-bit fixnums |
| 22 | `logxor` | strict binary signed-15-bit fixnums |
| 23 | `ash` | strict binary fixnums, shift count -14 through +14 |

Dialect-v1 continues to classify all four bytes as reserved. No Prim-ID is
allocated. The frozen v1 LCC remains unchanged; the v2 profile is the only
source compiler that names or emits these opcodes.

The logical operations use the low 15-bit two-complement representation and
interpret bit 14 as the result sign. `ash` shifts right arithmetically.
Left shifts are checked one bit at a time and fail with `VM_TYPEERROR` before
the signed-15-bit result could overflow. Counts outside -14 through +14 and
non-fixnum operands fail with the same type status. All four public
designators have exact arity two and preserve the ordinary `VM_ARITY`
failure.

The implementation is deliberately asymmetric by temperature. Four small
public CodeObjects live in the Bank-2 static plane. The resident VM receives
four new members of the existing fixnum-binop dispatch group. The three
logical operations extend its shared `noinline` body; `ASH` crosses one
explicit C-to-assembler seam into the named, sized, 112-byte non-LTO
`lisp65_ash_tagged` leaf in the resident island. The linked ELF derives and
checks that callsite and its llvm-mos register ABI automatically. No state,
root, dispatcher table, or public native identity is added. Direct,
`funcall`, and `apply` all reach the same public CodeObjects.

Acceptance requires parity across the live ABI document, ledger, C decoder,
Python decoder/compiler/VM, v2 LCC, and emitted public wrappers. The original
negative classes are replayed in full, including v1 reserved-byte rejection,
wrong arity/type, both count limits, both overflow signs, and negative
bitwise operands. Capacity is judged only by the combined F1+F2 WPLTO map.
# Post-promotion publish-last geometry

The F2 product-shaped WPLTO adds the resident bit-operation dispatch and its
non-LTO `ASH` leaf.  The final 40-byte runtime-family verifier table therefore
moves deterministically from the sealed v1.2.0 address `$B972` to the
post-promotion candidate address `$B98A`.  `$B972` remains immutable release
history; the F2 candidate, its WPLTO gates, and any successor product link
consume `$B98A`.  No table byte or publish-last ordering changes.
