# 2.2 Post-v1.5 Housekeeping Block — Work Plan

**Commissioned:** 2026-08-18 (owner: "Ja, bitte")
**Position:** runs between the v1.5.0 publication and the v1.6
commission. Nothing from the v1.6 agenda (cursor navigation, comfort
REPL, Attic write boundary, boot snapshot fallout, require bundling)
starts before this block closes green.
**Form:** autonomous host-only block, zero device contacts, one owner
touchpoint at the end. The previous block of this kind ran 2026-07-29/30;
three weeks of the project's highest cadence have accumulated since.

## Success criterion (hard)

`make check-source` runs **fully green with an empty exception list** —
the same bar the July housekeeping set. Everything below serves that
bar or the durability of the record.

## Work items

1. **ElfTruth stragglers.** The two legacy tools that still parse ELF
   columns manually — the standing full-`check-source` stoppers — are
   converted to the ElfTruth layer or retired with receipts. No
   manual ELF parsing remains anywhere in the tree.
2. **Rulebook consolidation.** The permanent clauses of the 2.0/2.1
   era live where they were born — as appendices in the living plans.
   Each is harvested into the gate-and-tool register as one row:
   rule, owning gate, mutation that proves the gate bites. Candidate
   corpus (not exhaustive; the harvest enumerates): born-derived,
   additive provenance, real-consumer selftests, process isolation
   for one-shot state, output closure incl. siblings, media-pair
   identity (same world, not same bytes), raw-first evidence,
   completion-is-a-reader, one-name-one-owner-one-body, WYSIWYG
   input boundary, readability-proofs-cover-probed-banks,
   opcode-semantic-equivalence, capacity-with-named-domain.
3. **Plan sealing.** Living plans that carried the era's dispositions
   (2.1 at 3,000+ lines foremost) are sealed: a closing entry with
   final commit, then archived state; successors start lean. The
   living-document semantic-inventory audit (Link-109 pattern) runs
   over every doc that still binds behavior.
4. **Register grooming.** Parked-items register: close the delivered
   rows with receipts (trace/untrace shipped in v1.5; editor key-56
   physically refuted; superseded defstruct rows merged). Every
   remaining row gets a verified pointer to its current evidence.
5. **Evidence and media hygiene.** Evidence index (5,600+ entries)
   re-verified; first-red artifacts of closed sagas moved to archive
   tier; SD card cleared to the released set plus the active
   candidate, short fresh names.
6. **Docs alignment.** architecture-overview and language-reference
   catch up with the shipped reality: CPU transport (MAP readers,
   structural-absence gate), WYSIWYG input contract, multi-form REPL
   sentence (if not already landed in the v1.5 doc task), liveness
   ordinals.
7. **Branch consolidation (owner request 2026-08-18).** The GitHub
   repo's `main` last moved 2026-07-10 and sits 1,666 commits behind
   the working branch (0 ahead — a pure fast-forward). After the
   v1.5.0 publication: fast-forward `main` to the release point; set
   the repo's default branch to `main` (it currently points at the
   stale `codex/ship-v4-remediation`); inventory the remaining side
   branches (`claude/*` audit branches, `codex/p04-mos-size-rescue`,
   the `ship-v4-*` pair) and delete each with a receipt naming where
   its content lives on `main`. Standing rule going forward: every
   release lands on `main`; side branches are working surfaces, not
   storage.
8. **Public-repo refresh (owner request 2026-08-18).** The private
   proof repo (`lisp65-proof`) gets the branch consolidation above;
   the **public** repo (`github.com/novemberist/lisp65`) additionally
   gets its presentation brought current after the v1.5.0
   publication: README highlights and roadmap updated to the shipped
   v1.5 reality (trace/untrace, guarded defstruct, WYSIWYG input
   contract, liveness ordinals, the documented 36 s boot with its
   grounds), the About description checked, the v1.5.0 release
   published there with tarball + SHA verification in the same form
   as v1.4.0, and the known-limitations section synced with
   docs/known-issues.md. Publishing steps run owner-visible, as with
   every release.
9. **Gate runtime pricing.** The full `check-source` runtime is
   measured and, if it has ballooned, tiered (fast tier per-commit,
   full tier per-session) — priced, not guessed.

## Out of scope

New product behavior of any kind. A housekeeping finding that wants a
product change becomes a parked row for v1.6, not a fix in this block.

## Exit

One owner touchpoint: the block report (green `check-source` receipt,
consolidated rulebook diff, groomed registers, sealed plans). Owner
release of the report opens the v1.6 commission.
