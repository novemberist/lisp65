# C2.2 overlay transaction authentication — Island follow-up

Status: one owner-authorized product-shaped capacity and placement probe;
no product link or hardware execution authorized (2026-07-20).

## Why this follow-up exists

The first transaction-authentication attempt proved its semantics and both
required fail-closed mutations, then stopped at the first real link. Its seven
bytes of direct state were not the dominant cost: LTO expanded the generic
transport and duplicated transaction-bearing product paths, adding 678 bytes
of resident text in a corridor with 198 bytes free.

This follow-up changes residence and duplication only. It does not relax a
validation rule. Transaction begin, end, and catalog-cache mediation are
non-inline resident-Island functions. The two product entrypoints are kept as
single non-inline copies. The five authenticated catalog bytes and their
discriminator reuse the existing runtime-batch tuple under a proved
lifetime-exclusion rule, so ordinary Bank-0 BSS receives no new state.

## Lifetime rule

Batch execution and append transactions cannot overlap. Transaction begin
rejects a live batch. Batch entry rejects an active transaction. Batch return,
transaction end, transport failure, abort, and reset release the shared
discriminator. The host mutation fixture proves both legal handovers and the
overlap rejection.

This reuse is legal because the tuple has only one owner at a time. It is not a
second representation: during an append transaction the tuple is the sole
home of the authenticated payload offset, image limit, and catalog count.
