## Hardware fact

Boot and library loading completed and the native `lisp65>` prompt appeared.
The owner typed `(list 1 3)` without submitting it.  The first Left key made
the surface stop accepting input with the cursor still after the text.

The stopped CPU was not in the matcher.  It was at `$B28F` in `__memset`,
called by `rtov_wipe` during the synchronous abort path.  The active hardware
stack decodes exactly as:

`repl -> c2_product_abort_recover -> abort facade -> c2_abort_driver ->`
`runtime-overlay exec -> rtov_wipe -> __memset`.

`rtov_busy=1` and `rtov_loaded_len=$059A` show ordinary overlay retirement in
progress.  The REPL buffer at `$BC89` still contains `(list 1 3)\0`; the ring,
input bytes and framebuffer are not the stopped subsystem.  The apparent
matcher hang is therefore the already-known long synchronous recovery service
time after an error, not a non-yielding matcher pass.

## Primary error

Zero-page `pending_code` is `$22`, decimal 34,
`LISP65_ERR_TOO_MANY_SYMBOLS`.  In the selected product source this error is
raised only by `new_symbol()`.  Its three failure predicates are an overlong
or unterminated name, an exhausted symbol table, or an exhausted name pool.

The stopped world contains 659 of 752 symbols and 8,889 of 10,208 name bytes.
There are therefore 93 symbol slots and 1,319 name bytes still free.  Capacity
exhaustion is mechanically excluded; the live call to `intern()` received a
name longer than the 33-byte contract or without a terminator inside that
contract.

The disk-library payload itself is canonical: nine entries, 1,719 code bytes,
all entry names at most 19 bytes, and no overlong metadata name.  The candidate
static manifests likewise describe the relevant resident functions normally.
The failing seam is the first newly exercised mixed-world edge:

`external %read-line-loop -> resident %rl-poll -> resident matcher/clear path`.

The green Block-3 host fixture places all functions in one host heap and one
directory.  It exercises Left and the matcher semantics, but it never appends
the external library over the already published final static plane.  It thus
does not exercise the publication/resolution boundary that the device crossed.

## Claim boundary

The exact producer of the bad C name is not recoverable from this stopped
state.  `longjmp` discarded the failing VM operand/call chain; abort cleanup
retired the dynamic runtime view; and the shared `sym_name_scratch` now holds a
later `%c2-compile-form` value, not a first-fault witness.  Treating that later
value as the bad name would violate the raw-first and claim-hygiene rules.

Naming the remaining writer would require either a first-fault latch at
`new_symbol()` or a new host executor that composes the final static C2D plane
with the real disk-library append.  Either is a new diagnostic round, followed
by a second product repair if it finds a fix.  Neither is authorized by the
Block-3 decision table.

## Disposition

editor aborts and then presents as a long recovery stall.  Block 3 already
spent its one admitted repair round on the candidate-banner ordinal defect.
The pre-bound rule says `at most one fix round, else feature descope`.

from v1.7 as one unit: shared matcher and both blinking-cursor surfaces.  The
candidate pair, hardware capture and mixed-publication attribution remain
