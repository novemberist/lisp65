# C2.2 defstruct media product-identity rebind

Status: product-shaped host/media correction; no product byte changes.

## First Red

The Link-71 pre-rollback hold reached persistent append slot 23 with the
mounted `PLACE` artifact's exact 1,925-byte length.  The append envelope
rejected the artifact before copying its record.  The mounted artifact carries
`build_id_u32 = 0xc2020001`, while the linked product consumes the canonical
Link-71 identity `0xf5fe97c0`.

The former host path was a two-witness model: `build_extension` overwrote the
header with private `PROBE_BUILD_ID`, and `decode_extension` compared against
the same private constant.  Their agreement did not prove compatibility with
the linked consumer.

## Contract correction

Product media emission consumes `product_build_id` from
`config/c2-l-full-product-profile.json`.  The generic session-extension probe
may retain an explicitly scoped probe identity, but product-shaped callers
must pass their canonical build identity to both emission and decoding.

The L65S-v4 width and layout do not change.  Only header bytes 22..25 are
rebound.  Code, C2I metadata, the 32-byte record, its CRCs, combined identity,
the L65I rows and all capacity values remain byte-identical.

## Permanent gate

For every product-shaped L65P artifact:

1. header bytes 22..25 equal the canonical product profile identity;
2. the same identity is bound by the WPLTO/static-plane authority consumed by
   the linked product;
3. the product decoder accepts the canonical artifact and rejects the former
   private probe identity;
4. the generic probe decoder rejects the product artifact unless its expected
   identity is passed explicitly;
5. the only bytes changed from the prior media artifact are 22..25.

The correction is artifact-side.  Link 71 and all product sources remain
unchanged; a hardware replay uses a newly named D81 identity.
