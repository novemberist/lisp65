# Block 2.5 public naming audit

Status: **complete — read-only; no rename is authorized**.

## Correction to the work-plan premise

`v16core` is not a designator in the v1.9 product authority.  The resident
editor needs no core-library load, the guide teaches one product medium, and
the current external library manifests are `buffer`, `ide`, `idex` and `m65d`.
`v16core` survives only in historical evidence and plans.  It remains the
clearest era-bearing example, but its migration is removal of stale wording,
not a runtime compatibility alias.

The work plan also proposed one-cycle aliases.  The newer, owner-bound v2 plan
states that there is no known user base and explicitly withdraws that premise.
Accordingly this audit recommends direct v2 renames, with a release migration
table as a courtesy.  Every actual rename still requires the owner's word.

For typed library designators the matching proposals are `editor`,
`editor-tools` and `disk-tools`.  Current release media
`lisp65-product.d81`, `lisp65-work.d81`, `AUTOBOOT.C65` and the public
`INIT.L65` convention already name capabilities and should stay.
`V17B3P.D81` is correctly historical but would be
`diagnostic-block3-product.d81` in a speaking diagnostic world.

The 64 `LISP65_ERR_*` names are internal identities, not recommended user
phrasing.  A later error-surface card should preserve those identities while
making visible text follow `operation: problem`; it must not expose short
phase codes as the primary vocabulary.

## Permanent inventory

`config/public-naming-audit.json` records every classified name and the newer
migration policy.  `tools/host-lisp/public_naming_audit.py` rejects population,
classification and alias-policy drift through `check-source`.  This freezes
the proposal as an input to v2; it changes no public name, medium or product
byte.
