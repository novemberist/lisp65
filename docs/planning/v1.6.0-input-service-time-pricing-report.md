# v1.6 input service-time pricing

Status: **priced; implementation card requires review** (2026-08-19).

This is a host-only study. It changes no product source, emits no product
link, authorizes no card, and authorizes no device contact. Its authority is
the merged First Red at `952bafc0` and its machine-readable result is
`c2.3-v1.6-input-service-time-pricing-receipt.json`.

## Result first

The scalar ring dequeue is not the fix. It removes only **49 VM steps per
character**. The current ring path costs 1,776 steps/character; the old
`key-event` path costs 1,727. Even after separately removing the hot path's
avoidable `nthcdr` and printable-key dispatch work, scalar service still
prices at 1.576 frame-equivalents/character, nearly twice the 0.8-frame
ceiling.

The first admitted design is an **adaptive eight-event hybrid**:

- one native scalar boundary owns dequeue and PETSCII normalization;
- consecutive printable input is edited as a burst;
- state publication and dirty-span rendering are amortized over that burst;
- control/navigation input remains ordered and is never swallowed by the
  printable look-ahead;
- no new Lisp name and no new public primitive are introduced.

At an eight-event burst the real Workbench P0 composition measures 219.875
VM steps and 1.125 screen cells per character. With the bound target costs
and the unavoidable one line-cell allocation per printable character, that
is **0.768 frame-equivalents/character**, or **1.302 events/frame**. It clears
the one-event/frame producer by 30.2%, above the required 25% margin.

The workload is forty ordinary printable characters followed by Return,
through the real v1.6 Workbench resident composition. Boundaries are at the
real input consumer, and the measured interval includes edit and render work
before the next input boundary.

The frame equivalents use only already accepted target authorities:

- 40 MHz and 20 ms raster frames;
- the historical 1,100-cycle mean per VM operation;
- the measured approximately 1,500-cycle `scr_put_at` cost;
- one 89-frame collection per 192 allocated cells in steady state.

The exact measurements are the P0 instruction counts, screen-cell counts,
emitted bytecode sizes, and assembled native size. The frame conversion is a
hardware-calibrated projection, **not a new device timing**. The historical
961-frame/40-key IDE result remains a cross-check only; it is not silently
substituted for the current REPL.

The result also reconciles the owner's two observations. The ring path has a
small additional instruction cost but only one heap cell rather than four,
so its stationary service is better than the old path. It feels worse because
the old five-place queue discarded the excess while the 111-place ring keeps
it as visible latency.

## Why eight, and why adaptive

Four-event bursts remain above the 0.8-frame ceiling. Eight is the first
measured size that passes. The implementation must not wait for eight events:
it drains whatever is available, and it coalesces naturally once the producer
begins to outrun the scalar path. Thus a slow typist sees immediate echo,
while a burst enters the measured amortized regime before the ring can become
the latency reservoir seen in the First Red.

The permanent responsiveness gate therefore has two rows:

1. scalar/short-burst behavior remains semantically identical and begins
   draining immediately;
2. stationary bursts of eight or more sustain at least 1.25 events/frame.

The existing 94-event forced-collection row remains independent and mandatory:
94/94 ordered, event 6 present, no loss.

## PETSCII boundary

The uppercase First Red is part of the winner, not a follow-up. One generated
PETSCII normalization table has two consumers: public `key-event` and the raw
Comfort consumer. The parity gate starts from all **256 raw PETSCII bytes**.
Its boundary witnesses are:

- `$41..$5A` → lowercase ASCII `$61..$7A`;
- `$C1..$DA` → uppercase ASCII `$41..$5A`, with Shift retained for public
  event metadata;
- `$A0` → `$20`;
- RUN/STOP `$03` remains matrix authority and is not reclassified.

Fixtures that inject pre-normalized ASCII are rejected. Producer and payload
transfer fixtures remain non-atomic.

## Freight price

The executable prototypes produce these prices without a product link:

- the three touched Bank-2 objects shrink from 726 to 583 bytes: **−143 B**;
- the largest touched code object is 240 bytes, below the 255-byte ceiling;
- new interned names: **0**;
- new public primitives: **0**;
- the assembled native scalar/normalization body: **70 E000 bytes**.

Post-R1 and post-capture, E000 has 136 bytes free with a 54-byte floor, hence
82 spendable bytes. The body leaves exactly **12 bytes above the floor** for
the private-mode adapter. Ordinary text has only 6 free bytes and is not a
budget. The implementation card must therefore prove at the final ELF that
the shared-normalization refactor plus adapter fits those 12 E000 bytes and
consumes no ordinary text. If it does not, the price returns for relocation;
the floor and ordinary margin do not move.

## Recommendation

Authorize one implementation card for the eight-event hybrid, with the
following gates carried as walls:

- ≤0.8 calibrated frames/character for bursts of at least eight;
- adaptive draining without a fixed eight-event wait;
- 94/94 ordered across the forced collection, including event 6;
- exhaustive raw-PETSCII parity across both consumers;
- cursor, history, WYSIWYG, RUN/STOP and native fallback unchanged;
- final-ELF capacity proof for the 70+≤12-byte E000 seam and zero ordinary
  text growth.

Until that implementation is host- and review-green, Posten 1 and 2 remain
unaccepted and the device remains off.
