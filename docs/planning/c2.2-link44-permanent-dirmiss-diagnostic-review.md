# Link 44: permanent VM_DIRMISS detail seam — Class-C review

**Status (owner/reviewer decision 2026-07-22):** the status-plus-detail contract,
its fixtures and one product-shaped WPLTO capacity/placement probe are
authorized.  No promotable product link or hardware run is authorized by this
decision.

**Baseline:** Link 44 product SHA
`db3112e6503ca96d572cccb7a399c91eb06028faeaa05e595454fb9502b7f926`
remains untouched.

## 1. Why the bounded patch diagnosis stops here

The third and final Class-B cycle did not recover a lookup identity. Its three
captures of `c2_dma_list` are byteidentical, but decode as a 1,255-byte copy
from Bank 3 `$ec00` to Bank 0 `$c356`. The Link-44 manifest and map identify
that exact length and target as `.lisp65_rt_l65e`, the error-text-renderer
overlay.

That is incompatible with the capture premise. At a reached negative
`OP_CLOSURE` `dir_find` edge, `dir_find` has just called `sym_function`; the C2
product implementation leaves a two-byte Bank-5 `SYMFN_EXT` read in the same
descriptor. The observed descriptor is generic overlay traffic instead. The
screen capture shows the submitted form but no result, error or following
prompt, so it cannot independently establish the program counter either.

The historical cycle-2 and cycle-3 receipts remain immutable, but their
`device_state = intentionally held` fields are superseded by
`c2.2-link44-op-closure-cycle3-interpretation-correction.json`. The exact
conclusion is deliberately narrow:

- no lookup identity was captured;
- the `$8755` hold was not established;
- the `OP_CLOSURE` site is not proved to be the failing producer;
- the Class-B budget is 3/3 and there will be no fourth site patch.

## 3. Accepted decision: status plus detail, not another latch

Make the existing non-OK VM result a structured error seam:

1. The one out-of-line `vm_dirmiss_detail` seam sets `VM_DIRMISS` and returns
   the producer's already-live detail
   value. Symbol lookup sites return the exact `SYMI`; direct-entry failure may
   return its `BCODE` identity; a site with no valid identity returns `NIL`.
2. Every outer VM/evaluator layer propagates a non-OK detail unchanged. The
   innermost producer wins; an outer frame may enrich only an empty detail and
   may never replace a non-empty one.
3. The single `vm_check_status(detail)` boundary consumes `(status, detail)`.
   The detail reaches that boundary only in the ordinary `obj` return pair; it
   is not copied into a diagnostic global. For
   `VM_DIRMISS + SYMI` it calls the already existing `lisp_abort_symbol` seam;
   the existing L65E renderer already appends the symbol name. Non-symbol
   details retain the numeric undefined-function error without inventing a
   private string.
4. `lisp_abort_symbol` is the only persistent handoff: it writes the existing
   `pending_symbol` cell only at the terminal abort boundary. `pending_code`
   continues to carry the status-derived error code. C2J remains exclusively
   the rollback journal and is neither enlarged nor borrowed for diagnostics.
5. Success-result semantics remain unchanged. The detail is meaningful only
   while `vm_status` is non-OK, so no additional persistent BSS object and no
   GC root is required for immediate `SYMI`/`BCODE` values.

The admissible pre-terminal detail domain is exactly `SYMI`, `BCODE` or `NIL`.
Only `SYMI` is sent through the symbol renderer; `BCODE` and `NIL` retain the
numeric `VM_DIRMISS` diagnostic. Heap pointers are never accepted as error
detail and therefore need no lifetime or rooting convention.

This reuses the product's established “inner-most status wins” rule and its
existing symbol-aware error renderer. It makes diagnosticability a property of
the real error path rather than a separately instrumented product identity.

### Rejected default

A permanent four-byte global latch is not the default. The already measured
all-site prototype cost 181 resident text bytes: `vm_check_status +67`,
`vm_run_inner +58`, `vm_run_dir +56`. Link 44 has only 35 bytes of Bank-0 text
headroom. That prototype also duplicated the error-detail truth in mutable
state and would require a placement round before answering one key.

It remains a fallback only if the return-payload seam is disproved by an
explicit lifetime or unwind counterexample.

## 4. Required contract and mutation matrix

Before a promotable product link, a product-shaped WPLTO probe must prove all
of the following:

- all six `VM_DIRMISS` producers provide the contractual detail;
- `OP_CLOSURE`, `OP_CALL` and `OP_TAILCALL` preserve the exact literal object;
- both `vm_dir_add` failures preserve their definition/helper symbol;
- a nested inner miss survives every outer `goto done`, return and
  `vm_check_status` edge byteidentically;
- an outer miss cannot overwrite an existing inner detail;
- a success result is never interpreted as error detail;
- `SYMI` detail reaches `lisp_abort_symbol` and renders through the existing
  L65E overlay; `BCODE`/`NIL` remain fail-closed numeric diagnostics;
- RUN/STOP/longjmp cleanup does not leave a stale detail visible to the next
  form;
- no new product string, second error renderer or second status store appears.

Pinned negative mutations must include, at minimum:

1. omit each producer in turn (six reds);
2. replace the exact symbol with `NIL` at `OP_CALL` and `OP_TAILCALL`;
3. overwrite an inner detail in an outer frame;
4. reuse stale detail after the next successful form;
5. render a `BCODE` as though it were a symbol;
6. bypass `lisp_abort_symbol` for a valid `SYMI` detail.

The failing hardware form
`(list(peek 255 132)(peek 255 131)(peek 255 132))` becomes a permanent host
fixture. Its static/dynamic emission must be inspected so the expected call
sites are known before hardware, but the fixture may not predeclare which one
fails.

## 7. Link-45 hardware result: the non-symbol half is not diagnostic enough

Link 45 moved the call-free `vm_byte_args` hot leaf into the owned `$e000`
window, leaving 43 bytes of final Bank-0 text headroom and 256 bytes in the
window above the restored 115-byte floor.  All gates were fresh and the
hardware boot reached the Workbench banner and REPL.  The permanent fixture
then rendered:

```text
*** vm: undefined function
```

The SHA-bound screen and read-only post-error cells are recorded in
`c2.2-product-link45-dirmiss-detail-hardware-first-red.json`.  The exact text
is code 41, not code 28 with a symbol suffix.  The terminal therefore did not
receive a `SYMI` detail.  After rendering, `vm_status`, `pending_code` and
`pending_symbol` were all zero, and `c2_ready` was zero.  Cleanup and
fail-closed rollback worked; there is no stale-detail finding.

This result exposes a deliberate limit of the accepted v1 contract.  It maps
both `BCODE` and `NIL` to the same generic message.  Consequently the run
narrows the failure to the non-symbol domain but cannot distinguish the
direct transient main entry from another direct BCODE edge, nor can it name
the ordinal.  The hardware localization objective is therefore still red;
the symbol-aware path itself is neither disproved nor reached.

### Approved Class-C follow-up

**Decision (2026-07-22):** the BCODE-ordinal renderer, one product-shaped
WPLTO probe, and—only after a green probe—one successor product link and
hardware pre-smoke are approved.  The binding addendum is
`config/c2-vm-dirmiss-bcode-ordinal-contract.json`.

The existing L65E context field is extended from symbol-only semantics to the same
closed detail union already carried by `vm_dirmiss_detail`: `SYMI`, `BCODE` or
`NIL`.

- `SYMI` remains code 28 plus the canonical symbol name.
- `BCODE` remains code 41 but appends its raw 12-bit ordinal as exactly
  ` #xxx`, using three lowercase hexadecimal digits.  It is never passed to
  `symname` and never presented as a symbol.
- `NIL` remains the unchanged generic code-41 message.
- The existing `pending_symbol`/context `obj` cell carries the detail; there
  is no new latch, BSS byte, GC root or private error string.
- Mutations must reject BCODE-as-SYMI, NIL-with-fabricated-detail, truncated
  ordinals and a renderer that drops the BCODE suffix.

Reverse-scanning the symbol table is not the default: transient top-level
entries are legitimately anonymous, and a named symbol is not guaranteed to
exist for the failing BCODE.  The raw ordinal is the one truthful identity
available at every direct-entry producer.

This requires a new product-shaped WPLTO measurement before any link.  The
Link-45 L65E slice is 1,255 bytes under its dedicated 1,320-byte cap (inside
the general 1,792-byte runtime-overlay ceiling), but the whole
Session aggregate has only 98 bytes of headroom; neither local slice room nor
an estimated formatter size is a capacity credit.  Link 45 remains the
rollback candidate until that Class-C decision is reviewed.
