# v2.0.0 pre-plan — the working environment, completed

**Bound:** 2026-08-28, on owner decision: all three pillars, and the
`$22` escalation first.
**Position:** opens after the 2.5 housekeeping block closes. 2.5's two
audits (domain discipline, naming) are direct inputs to pillar 2, so the
order is not negotiable.
**Form:** a milestone spanning several blocks, not a single card. The
standing cut rules apply unchanged: at most two blocks in parallel with
separate touchpoints, one bounded repair round per daily-use blocker,
and on release day what is accepted ships.

## Why this is a major version

A major version is the only occasion that licenses **breaking changes**,
and they have accumulated: `(car 1)` → `nil` is shipped documented
behavior, `v16core` is a designator users type, and the canonical prompt
composition changes what `lisp65>` means. In a 1.x these would be carried
forever. **Owner correction, 2026-08-28: there is no known user base** — the
project has not been advertised broadly, so the earlier "advertised since
v1.3, breaking changes are expensive" premise is withdrawn. Breaking
changes are therefore cheap right now, and this is precisely the window
to spend that: renames need **no alias path** (which would have cost
slots and name bytes twice while both names lived), tier-2 domain
discipline is gated only on its hot-path measurement, and the migration
note becomes a courtesy rather than an obligation. Each breaking item
still gets the owner's word — cheap is not the same as unowned. The
discipline that catches real defects (gates, attributions, claim
boundaries) is untouched by this: ruthlessness applies to names and
semantics, never to proof. 2.0 is plausibly the release that gets shown
more widely, so the surface should be clean *before* that happens.

## Phase 0 — the `$22` escalation (critical path, runs first)

The unreproduced `$22` mixed-world defect gates the Comfort return *and*
the Block-3 return, i.e. more than half of pillar 1. It is therefore the
opening block, not a late risk:

1. Ship the **first-fault latch at `new_symbol()`** as a bounded
   instrument under the instrument law: bound atomic origin, neutrality
   proven (the observed path keeps its properties SHA-identically),
   removal by default once it has served.
2. One short device session on the mixed-world seam (external library
   over the final static plane, the boundary the v1.8 audit named).
3. **Branch on the outcome, decided before the session:**
   - *Writer named* → repair is priced, Comfort and Block-3 returns open
     as planned.
   - *No recurrence* → the seam is exercised without fault; Comfort
     returns carrying the latch as shipped mitigation (owner word), the
     Block-3 return follows it.
   - *Recurrence without a name* → both returns leave 2.0; pillar 1
     shrinks to the `$22`-independent items and the latch data becomes
     the next diagnosis block.

## Pillar 1 — the working environment, completed

Most of this exists already, sealed and review-green; the work is
return and integration, not invention.

- **Comfort REPL return.** Both historical killers are gone: the
  recovery stall (v1.7 A0, device-measured "practically immediate") and
  input loss (v1.9 Block A, device-measured 136/136/136/136). Sealed
  freight reloads unchanged; the sealed acceptance binding reruns on the
  current world.
- **Matcher and blinking cursor return.** Three review-green cards exist
  (shared resumable scanner with paint ownership, line-editor idle blink,
  IDE idle blink) plus the r10 placement world. A return starts from
  those cards.
- **Auto-closing delimiters** (owner request): its own pricing round —
  buffer semantics, skip-over, interaction with the over-close rule,
  toggle whose off state costs nothing on the key path.
- **Word motion and `C-k`**, explicitly excluded from the v1.6 cursor
  card and never delivered since.
- **Long input line legibility**: wrapping or a position indicator, so a
  line that scrolls past the edge stays followable — the defect that made
  a bound acceptance row impossible to execute.

## Pillar 2 — consistency and names (the breaking half)

Fed directly by the 2.5 audit tables.

- **Domain discipline, tier 1** (library sequence walks: `length` and
  everything that walks with `cdr`): no breaking-change word needed —
  the old results were garbage read out of foreign object fields. Type
  errors name the right function (`string-length`).
- **Domain discipline, tier 2** (`car`/`cdr` accept cons and `nil`
  only): measured against the responsiveness wall first, because these
  are the VM's hottest opcodes; then the owner's word, because
  `(car 1)` → `nil` is a shipped promise.
- **Renames** from the naming audit — with no user base, they are
  straight renames without alias freight; `v16core` is the flagship
  case. The old names are listed in the release text as a courtesy.
- **Canonical prompt composition (B-full)** if Comfort lands: Comfort
  owns `lisp65>`, the native C fallback becomes visibly exceptional.
  B-light stays the fallback path, not a competing model.

## Pillar 3 — speed where it hurts

- **IDE editor service time.** The v1.2.6 era measured ~24 frames per
  key; the input-fidelity saga proved the mechanism, and v1.9 shipped the
  ring as a resident facility the IDE can consume. **Measure the
  full-screen path before pricing it** — the one-line editor's timing is
  not a valid estimate for a full-screen renderer. **And price it against
  its alternative:** the recovered `(show 'name)` / `(edit 'name)`
  definition-granular workflow mitigates this debt instead of paying it,
  because a 10-50-line definition buffer moves the common editing case
  onto a structurally cheap path (and makes tiered syntax highlighting
  affordable again). Avoiding the expensive path may beat speeding it up;
  the comparison is mandatory before either is commissioned.
- **Boot time.** 36 s at v1.5, carried since with the snapshot idea
  parked: a world-bound, CRC-verified cache of the published
  post-library state, full decode as the invalidation fallback, the
  journal remaining the authority.
- **G1 `room`** is the enabling instrument for both (its register row
  already says the reopening condition is met); it enters as an
  instrument decision, not as freight for its own sake.

## Explicit non-goals

C2-full / Attic runtime refill (gated on upstream L10 or a self-owned
transport), any core work, the deep `defstruct` terminal-ingress fix,
Variant-A recovery upgrade (behind a text reclaim), BASIC-65 parity,
colour scroll, tick hook. These stay register rows with their evidence.
The upstream #670 reproducer is outward work that may ride any planned
contact but does not gate the release.

## Owner-only decisions inside this milestone

Each breaking item (tier-2 domain change, each rename, the prompt
composition), the Comfort return's residual-risk word if phase 0 ends
without a named writer, every device contact, the evidence-retention
word inherited from 2.5, and the two release halts.

## Risks, named up front

1. **`$22` is the schedule risk.** Phase 0 exists to resolve it early.
2. **Ordinary text capacity is tight** — B-light left 32 bytes of
   reserve. Every pillar-2 and pillar-3 card prices its text at the final
   link, never from a fragment (the v1.9 LTO lesson).
3. **Comfort has died twice.** Its return gets the same anti-rabbit-hole
   treatment as any other freight: one bounded repair round, then
   descope, with the sealed evidence intact.
4. **Scope drift.** The milestone is large by design; the cut rule is the
   defence — accepted freight ships, unfinished freight seals.

## Suggested midpoint: an owner preview build

Once pillar 1 is hardware-accepted, an owner-only preview medium (not a
public release) lets the environment be used daily before the breaking
changes land. Findings from real use have twice been the sharpest input
this project had; a preview makes that input arrive before the release
text is written, not after.

## 2.x era outlook (owner-agreed 2026-08-28: after 2.0)

Recorded so these do not look forgotten. 2.0 makes the workbench solid;
2.x makes it capable:

- **BASIC-65 parity libraries** (circle/line/screen/sound) and
  `m65-turtle`, the Logo hook. They are the largest consumers of library
  space, so they are coupled to the "load all standard libraries by
  default" question and thence to the Attic/C2-full capacity promise —
  which is why they are not 2.0 freight.
- **Interlisp programme, remaining stages:** polite DWIM error hints
  (never auto-correct; CL-name hints fed by the migration rewrite table)
  and the definition-granular `(show 'name)` / `(edit 'name)` workflow —
  whose stage 1 may be pulled forward if the pillar-3 comparison says it
  dominates renderer optimization.

## Exit

A public 2.0.0 whose release text carries: the completed environment, the
migration note for every breaking change, the retired Known Issues, and
an honest list of what remains parked.

## Reviewer disposition — phase-0 double occupancy — 2026-08-31

The composed checker caught a real double occupancy before a link was
spent: four emitted overlay wrappers hold 64 fixed raw accesses to
`$B582..$B591`, which the plain ELF section map did not report as an
owner. The pricing's "inactive historical claimant" premise was wrong —
the terminal-return guard is active. v1.9 is not defective; only the new
overlap is.

**The guard stays.** It is hardware-proven (Link 96, the first
`defstruct` result in the project's history ran under it) and it protects
against control flow escaping into data. Silently removing an active
protection instrument to make room for a diagnostic instrument inverts
their values and is refused.

**New permanent rule** (register it, not only the checker code):
*ownership includes fixed raw accesses, not just ELF sections.* Any
placement derivation enumerates section owners **and** fixed raw
accessors of the candidate interval, and treats "inactive" as a claim to
be proven, never assumed.

**Authorized now: one host-only re-pricing round, zero WPLTO, zero
links.** The frozen r1 seed stays frozen and is not resumed. The round
must:

1. derive a genuinely disjoint interval under the extended ownership
   rule, enumerating every claimant class for the candidate;
2. if no ordinary-region interval of sufficient size exists, price the
   alternatives explicitly rather than shrinking the record until it
   fits — a far-service or Bank-2 carrier for the payload, a smaller
   state footprint, or a different capture site — each with its cost and
   what it loses;
3. keep the record's discriminating content intact: caller, name pointer
   and up to 34 NUL-stopped bytes are the reason the instrument exists.

The remaining WPLTO/product-link authorization is deliberately withheld
until that re-priced placement is reviewed. Budget carried: 1 WPLTO
consumed and frozen as unqualified evidence, product link 0/1 unspent.

## Reviewer ruling — Comfort descope lifted; media-composition budget — 2026-08-31

Codex descoped Comfort on the grounds that the bound repair round is
spent. The reviewer had already ruled that the stale-medium round is not
Comfort's round, and the same reasoning covers the failed repair of that
medium: both rounds were spent on **media and session composition**
(stale `v16core` freight, then a reconstruction that overwrote nine
resident editor owners and mixed in 19 objects of another editor
generation). Comfort's own freight is byte-identical to its seal and
passes all nine cases over the real packed world in the correct
composition. Descoping it here would punish the feature for our
choreography.

**Durable criterion, so this is not a case-by-case indulgence:** the
one-round rule counts repair rounds of a feature's **own freight** after
a device red attributable to that freight. Rounds spent on media or
session composition — packing, designators, choreography — are not
feature rounds. They are not free either: they get their own bounded
budget, or media churn becomes its own rabbit hole.

**Media-composition budget for the Comfort return: exactly one further
medium, and it is the last.** It carries the corrected composition —
product plus unchanged `repl-comfort`, **no `v16core`** — and before
deployment the card proves mechanically that:

1. the session loads only `repl-comfort`, and a mutation reintroducing
   `v16core` (or any external copy of resident editor objects) falls;
2. the packed-medium closure gate holds: every callee referenced by a
   packed object is present in that medium;
3. no packed object overwrites a resident owner — the ownership rule
   applied to the library medium, which is where both failures lived.

If that medium does not carry the session, Comfort descopes from v2.0
