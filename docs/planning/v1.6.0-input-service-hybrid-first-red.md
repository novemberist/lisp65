# v1.6 adaptive input-service hybrid — pre-card First Red

Date: 2026-08-19
Authority: `2713cb03`

The released hybrid is mechanically viable but is not card-ready under its
zero-name price.  The host implementation reaches 0.775 calibrated
frames/character (1.291 events/frame, 29.1% margin), preserves the 250-character
line limit, and assembles a 67-byte native consumer under the 70-byte ceiling.
All 256 raw PETSCII inputs share the public/Comfort normalization authority;
`$A0` becomes `$20` and modes 0/1 remain public-only.

The First Red is the symbol contract.  Batched editing requires `%rl-put` to
continue a burst before rendering.  The only target-compilable form within the
255-byte object ceiling is tail recursion through `%rl-put`; that changes the
helper from one external caller to one external caller plus a self-edge.  It can
therefore no longer be inlined away by the accepted three-helper reclaim.
Materializing that entry spends one symbol slot and eight name bytes.  Against
the accepted device-calibrated floor this projects 31 free slots, below the
release-terminal minimum of 32.

Two apparent escapes were executed and rejected rather than assumed:

- a local `while` body needs a −157-byte branch, outside the rel8 contract;
- moving dirty-span flushing into the consumer leaves `%read-line-loop` at 298
  bytes, above the 255-byte code-object ceiling.

No product card was invoked: zero WPLTOs, product links, media builds, or device
contacts.  The card authorization is therefore unconsumed.  A successor needs a
new symbol price: reclaim one additional private single-use entry, converge a
public name, or explicitly buy symbol capacity.  That choice changes a bound
capacity promise and is not made by this implementation attempt.
