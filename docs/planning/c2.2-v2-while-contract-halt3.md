## Owner decision

Accepted as one complete product contract:

```lisp
(while test form*)
```

The decision authorizes the product-shaped implementation and exactly one
WPLTO probe. It does not authorize a product link or hardware run. If the complete
four-view implementation cannot retain every Link-76 wall, `while` is parked
with an exact scope number; geometry is not renegotiated.

## Semantic contract

`test` is required and is evaluated before every iteration in the surrounding
lexical environment. `nil` terminates; every other object continues. Body
forms are evaluated left-to-right and each value is discarded. A body may be
empty. Normal termination returns `nil`.

`while` creates no binding, catch frame or dynamic unwind extent. Errors and
RUN/STOP use the existing top-level abort landing. There is no `break`,
`continue`, `return-from`, `catch`, `throw` or condition restart in this cut.

The syntax fails closed when the test is absent, the argument list is
improper or either generated relative branch is out of range.

## Why this is not only a two-compiler edit

The F5 paper decision correctly selected `while` over `catch`/`throw`, but
its future-proof list named “both compilers” too narrowly. The bound-product
carrier incident has since made the missing view impossible to ignore.
`while` must agree in four execution views:

1. native C tree-walk evaluation (`eval`);
2. the native C bytecode compiler plus target VM;
3. the Python reference compiler plus host VM;
4. the device LCC plus the compiler carrier actually bound into the product.

The target and host VMs need no new opcode. Both already implement
`JFALSEREL` and `JMPREL`. The bytecode shape is:

```text
loop:
    test
    JFALSEREL exit
    body-form ; DROP
    ...
    JMPREL loop
exit:
    PUSHNIL
```

The signed rel8 contract is the full `[-128,127]` interval. Both exact meets
must compile and the two one-byte overflows must fail closed. This explicitly
closes the current LCC boundary asymmetry rather than inheriting it.

The tree walker uses a flat C loop, temporary existing GC-root-stack entries
only, and an explicit poll cadence so `(while t)` remains interruptible even
with no body forms.

## One surface truth

The cut updates and gates all of these together:

- migration contract, current/target special-form inventories;
- public Dialect-V2 surface catalog;
- native evaluator and native compiler inventories;
- Python compiler inventory;
- device-LCC source and dialect profile;
- generated compiler tier and the product-bound carrier;
- language and migration documentation.

The public catalog retains the repository's current `macro` classification
for compiler-owned forms such as `dotimes` and `dolist`; the implementation
is nevertheless a native special form and cannot be shadowed by a macro
binding. No separate macro expansion becomes a second truth.

## Proof and capacity gates

The host proof must cover zero and multiple iterations, ordered side effects,
non-boolean truth, exact test count, an empty body, allocation/GC in test and
body, malformed forms, both rel8 exact meets, both overflows and constant VM,
C and root-stack depth. The bound-carrier parity gate must execute `while`,
not merely find its name in source.

The proof also includes a code object whose `while` backedge crosses a streamed
target-VM code-window boundary. It reports logical VM steps and window refills
as separate quantities. A crossed backward edge is correct only if the target
window is reloaded; that implies one refill per admitted iteration for this
layout. This is a documented performance property of large streamed loop
bodies, not a correctness failure. A later device session may add a timing
line, but no hardware measurement is part of this authorization.

The product probe measures Bank-2 and resident deltas independently. It must
retain at least:

- 32 B bank-0 text noise reserve;
- the 54 B `$E000` floor;
- every fixed-block, BSS, island, session-family and aggregate wall inherited
  from Link 76.

No new VM opcode, resident state, permanent GC root, C2J field or overlay
record is permitted.

After a separately reviewed successor link, the single final bundled device
session carries the `while` smoke lines, the V1 `random` lines, the three IRQ
mask readbacks and the already queued DIRMISS diagnostic line.
