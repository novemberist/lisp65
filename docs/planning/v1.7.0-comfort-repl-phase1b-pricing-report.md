## Variant A — deliver `screen-write-string`

The paired final-LTO observation changed only
`LISP65_SCREEN_WRITE_STRING`. Ordinary `.text` grew from `0x92ae` to
`0x9635`, an exact 903-byte delta. The sealed product has 273 ordinary-text
bytes between the end of `.text` and the fixed mapped-far facade at `$b3b0`.
Applying the paired delta therefore crosses the facade by 630 bytes.

`.bss`, `.rodata`, the far-service and the facade were unchanged. The VM case
also introduces an 80-byte automatic `wbuf`; this is stack demand, not
resident state. A is consequently not a feature-toggle-sized change: it needs
an owner-priced relocation of at least 630 ordinary-text bytes or an
architectural split before it can become a candidate.

The price observation consumed two price-only WPLTO attempts: one successful
paired baseline and one capacity-rejected A link. It consumed no product card,
medium or device contact.

## Variant B — use the delivered fallback

The fallback stays within the editor's framebuffer ownership. A private
`%repl-prompt` asks `screen-bulk-p`; the selected product's resident answer is
NIL, so it writes the five prompt cells through `screen-put-char`. This is
deliberately not a sequential `write-string` shortcut: that would reintroduce
the two-writers/one-framebuffer defect already closed by the composed-display
gate.

The helper is 80 bytes. `%repl-step` shrinks from 255 to 251 bytes, so total
Bank-2 library growth is 76 bytes. The private name costs one symbol and 13
name-pool bytes. Against the sealed Comfort capacity world, bias-adjusted free
capacity moves from 33/594 to **32/581**. The 32/384 release floor holds with
197 name bytes but zero symbol-slot margin.

The responsiveness premise needed one correction. `screen-write-string` was
only the once-per-line prompt operation; the character edit/render service
never used it. Nevertheless the complete fallback world was re-executed:

- all nine Comfort cases pass against the primitive table derived from the
  final ELF;
- the 40-character stationary span is identical on both paths: 8,945 VM
  steps and 45 screen cells;
- the fallback delays the first input boundary by 32 VM steps once per line;
- recomputing the complete stationary price gives 0.773218 frames/character,
  1.29330 events/frame and 29.33% margin;
- amortizing that prompt delta over only 40 characters still gives 0.774318
  frames/character and 29.15% margin.

Both forms clear the standing 0.8 / 1.25 / 25% responsiveness wall.

## Permanent product-profile host gate

The P0 host VM now accepts an optional delivered-CALLPRIM set. Product-bound
suites obtain that set from the linked product's CALLPRIM table. On this
candidate the table has 84 entries; IDs 1, 2, 12, 26, 27 and 40 share the
linked tombstone at `$6c4a`.

The gate proves all three sides:

1. the B fallback passes all nine Comfort cases with the product-derived set;
2. the historical Comfort source is rejected at CALLPRIM 12 as a product
   tombstone;
3. both an unrestricted host and a mutation inventing delivery of ID 12 still
   produce the old nine-case false green, so the gate explicitly rejects that
   fixture class.

The permanent rule is therefore executable: **host qualification of
product-destined bytecode consumes the final product primitive table,
tombstones included.**
