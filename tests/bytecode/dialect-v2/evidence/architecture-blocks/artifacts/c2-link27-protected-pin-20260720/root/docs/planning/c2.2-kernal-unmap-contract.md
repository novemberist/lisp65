# C2.2 KERNAL-unmap and input-ownership contract

Status: **owner-commissioned contract; bounded probe not yet run**

Date recorded: 2026-07-19  
Commissioning source: `docs/planning/v1.2-scope-memo.md`, section
“KERNAL-unmap block — commissioned (owner go, 2026-07-20)”  
Machine-readable contract: `config/c2-kernal-unmap-contract.json`

## Claim boundary

This contract authorizes a bounded proof of the complete ownership transfer
described below. It does not authorize product bytes, a KERNAL-free product
claim, a capacity repin, or a fifth substitution link. Those require, in
order, a green probe receipt and separate review.

The block is indivisible. It transfers all of these responsibilities before
the KERNAL mapping is removed:

- typed keyboard events and their event-time modifiers;
- the RUN/STOP evaluation abort;
- IRQ and NMI ownership, including the frame source used by latency gates;
- Freezer return and map re-establishment;
- post-startup character output; and
- ownership of the CPU window `$e000..$ffff`.

Removing only the ROM mapping while retaining any one of those firmware
dependencies is a failed probe, not a partial success.

## Pinned hardware facts

The authority is the repository snapshot
`docs/reference/mega65-chipset-reference.pdf`, SHA-256

The PDF's printed page numbers differ from its physical PDF page numbers:

| VIC raster compare/IRQ registers `$D012/$D019/$D01A` | 50–51 | 64–65 |

The following facts are bound, not inferred:

- `$e000..$ffff` is one 8-KiB CPU-map slab; MAP overrides the legacy KERNAL
  banking there.
- `$D60A` reports queue presence and the modifiers captured for the event at
  the head of the queue. `$D619` reports that event as PETSCII; writing it
  advances/clears the ready event.
- `$D012`, `$D019` and `$D01A` expose the VIC raster compare, interrupt flag
  and mask required for an owned raster IRQ.

The contract does not infer instruction encodings or a Freezer return
sequence from those tables. The bounded probe must derive and disassemble the
actual MAP/vector sequence produced by the pinned llvm-mos toolchain.

## Gross and net capacity law

The gross opportunity is exactly 8,192 bytes of **16-bit CPU address space**.
It is not a Bank-0, EXT, Attic, symbol, name-pool or directory credit.

The preceding first-red receipt fixes the resident deficit at 3,639 bytes.
The real-link model is:

```text
replacement_residents =
    typed_queue_driver
  + irq_handler
  + nmi_and_freezer_return
  + frame_source
  + map_switch_and_guards
  + post_startup_output_seam
  + alignment_and_vectors

future_margin = 8192 - 3639 - replacement_residents
```

Every category is mandatory in the probe and link receipts, including
zero-valued categories. `future_margin` must be strictly positive. The
approximately 4.5-KiB figure in the scope memo is therefore a gross upper
bound before replacement residents, not a permitted result claim. Only the
real link may name the final margin.

## Ownership-transfer state machine

The only legal forward sequence is:

1. `firmware-owned`: cold boot, CRT startup and C2 staging retain the KERNAL.
2. `replacement-armed`: native output, typed input, abort, frame IRQ and the
   owned vectors have each passed their readiness checks while firmware is
   still mapped.
3. `handoff-closed`: interrupts are masked for the bounded MAP/vector commit;
   both old and new sources are represented by the transition record.
4. `product-owned`: the owned mapping is active, the new sources are live and
   advancing, and firmware services are unreachable from the post-unmap
   closure.
5. `freezer-suspended` / `freezer-return`: hardware may enter the Freezer;
   product execution may resume only after the mapping and vector generation
   have been re-established and checked.

Before `product-owned`, any readiness failure leaves the KERNAL mapped. After
the handoff, an unknown map or vector generation must fail closed to the
documented disk-reboot path; product code must never resume speculatively.
A platform reset is not a product restart: it restores the firmware boot
world and may reach BASIC until the disk boot path is invoked.

### Continuity invariants

At every state transition, including the bounded interrupt-masked handoff:

- at least one authoritative RUN/STOP source exists;
- at least one authoritative frame source exists;
- the new abort source is proven before STKEY `$91` is retired;
- the new frame source is installed and shown advancing before the old
  firmware-maintained source is retired; and
- a vector is never published before its target bytes and mapping are valid.

The handoff may mask delivery for a bounded critical section, but it may not
erase the source or lose a pending abort. A RUN/STOP event observed during the
critical section is latched and delivered before the next evaluator step.
Frame continuity is measured as a monotonic product counter: no duplicate,
backward or missing transition may be hidden by switching clocks.

## Typed queue and L-full inheritance

The product event is one atomic tuple `(key code modifiers)`. Code and
modifier bits are sampled from the same queue head, and the event is dequeued
exactly once after both have been captured. Blocking and non-blocking reads
share that operation. Queue-empty is not a key with code zero.

RUN/STOP has exactly one product meaning: abort a running evaluation to a
usable REPL. It is not an editor binding and is a no-op while idle. Its
hardware recognition may use the typed event or matrix path, but the chosen
source must be single and generated, not a second handwritten key table.

L-full evolves `config/v11-l-lite-keymap.json` through the existing generator;
the Lisp table, host cases, P0 cases and `docs/generated/ide-keymap.md` remain
one closure. The first required modifier bindings are physical `Control-Space`
for set-mark and `Meta-x` for the command launcher. Legacy `C-x Space` and
`C-x x` may remain compatibility bindings only if that choice is represented
in the same source. No physical Meta/Alt claim enters user documentation until
both injected queue cases and a real-key hardware sample pass.

## Interrupt, output and reset contract

- The bounded probe selects and pins one owned frame interrupt source. The
  primary candidate is VIC raster IRQ via `$D012/$D019/$D01A`; no CIA or
  firmware-jiffy assumption may survive implicitly.
- The owned IRQ acknowledges only the source it services, preserves the
  documented machine context and cannot call Lisp or allocate.
- The owned NMI path contains no normal evaluator work. It exists to preserve
  the platform/Freezer contract and to make the return mapping check
  unavoidable.
- The lone audited `CHROUT` edge belongs to CRT startup before `main`. Once the
  post-startup closure is entered, all output is native; no KERNAL output edge
  is permitted.
- Cold boot and hardware reset retain the firmware mapping. KERNAL removal is
  a post-boot product transition, never a permanent platform reconfiguration.

## Structural KERNAL-freedom gate

The link gate distinguishes the address window from the firmware identity:
C2-owned code may live in `$e000..$ffff`, but it must be in a named owned
section. The post-unmap closure must prove all of the following:

1. the linker map assigns the entire live portion of `$e000..$ffff` to named
   C2-owned sections and vectors;
2. no relocation, call edge or absolute operand targets KERNAL service entry
   points (including `$FFD2` and `$FFE4`) or the retired STKEY byte `$0091`;
3. every post-unmap edge into `$e000..$ffff` resolves to an owned symbol in
   the owned section, never merely to an address in the range;
4. no KERNAL, CBM-I/O or legacy GETIN object/archive member remains in the
   post-unmap link closure; and
5. the generated source/disassembly census contains exactly one input path,
   one abort source and one frame owner.

An execution test cannot substitute for this gate.

### Fixed cross-domain facade

The owned `$e000..$ffff` image may not bind directly to whole-program symbols
whose Bank-0 addresses can move under LTO. Its only calls into moving Bank-0
implementations pass through thirteen three-byte tail-jump vectors beginning at
`$b5a2`; every vector address is contract-pinned. The implementation target
may move, while the window-visible address may not.

The original twelve addresses remain unchanged. The thirteenth vector at
`$b5c6` is `c2_facade_gc_mark`, appended for the C2-owned block root walker.
Its addition moves the separately pinned I/O-reveal, MAP-switch and handoff
state sections by three bytes; none of those addresses is implicit.

The 408 bytes of boot-visible Bank-0 state, the five-byte `kb_cursor_off`
helper at `$c218`, the 40-byte `c2e_cons` facade target at `$c21d`, and seven
bytes of zero-page state
referenced by the window likewise live in explicitly placed sections (`$c080`
and `$c218` for Bank 0, `$0089` for zero page). The fixed Bank-0 code ends at
`$c245`, leaving 273 bytes before the runtime overlay. The session emitter's
346-byte mutable state lives
in a named owned-window state section because it does not exist in the
pre-ownership lifetime. These regions are governed by the same orphan-error
policy as code.
The link fails if a vector or state address moves, if a fixed section is absent
or changes size, if the enumerated pre-ownership closure reaches the
session-only code or state, or if disassembly finds a direct owned-window call
to low memory outside the vector set. This replaces 132 implicit
LTO-sensitive bindings with thirteen public vectors and declared storage and
lifetime geometry.

Pre-ownership graph nodes are identified by `(section, VMA)`, never by VMA
alone. Runtime-overlay sections intentionally share `$c356`; the gate derives
the boot-section set from the same pack specifications as the emitter and
keeps same-address roots distinct. Its permanent mutation set covers a boot
edge into session code, an operand into session state, and an edge through the
session-cons facade vector, as well as same-VMA section identity itself.

## Link-18 publish-last verifier binding

The product closure is linked exactly once against the SHA/CRC identity of the
owned window extracted from Link 17. That complete 8-KiB identity is a pre-link
input and must be reproduced byte for byte; it is never rebound after LTO.
The resident-island seed materializer remains a separately counted prerequisite
and is not a second product-closure link.

The four runtime-family verifier tuples live in one assembler-owned, non-LTO
section of exactly 32 bytes. Its frozen order is boot catalog, boot record,
session catalog, session record. The link contains recognizable sentinel words.
After both runtime families have been packed from that one ELF, the packer
replaces only this section in the PRG as a publish-last operation. Section size,
symbol offsets, the changed-byte range and all four manifest-derived tuples are
gated. No code is relinked to publish verifier data.

Packing is repeated from the same ELF after publication. The identity gate
validates the full image SHA/CRC and every slice payload SHA/CRC, then compares
every record field and every payload byte across the two packs. A permanently
pinned mutation flips one payload byte and must be rejected. Stable sizes alone
are never sufficient evidence.

Link 18 confirmed this binding model: one product-closure link reproduced the
pinned owned window, the 32-byte publication changed 30 bytes and no byte
outside the section, all 53 family-record occurrences and payloads were
identical across the repack, and the deliberate payload mutation was rejected.
The product PRG remained 41,542 bytes, equal to Link 17.

The first red moved to the KERNAL-freedom gate. Its original ownership model
required every direct `JMP` target in the owned window to equal an `nm` symbol
start. LTO emits local basic-block targets without symbols: Link 18 contains
113 such `JMP` occurrences to 47 unique decoded instruction boundaries, all
within the same named function and executable owned section. Conversely, the
model's unfiltered symbol table included absolute and weak KERNAL aliases,
which are not owned executable entries. Thus the gate is neither sound nor
complete at this boundary; KERNAL freedom remains unproved, not disproved.

The proposed correction is a section-qualified control-flow model. A direct
`JSR` or inter-function tail `JMP` must land exactly on a `T/t` function symbol
inside a named executable owned section. An intra-function `JMP` may land only
on a decoded instruction boundary inside that same function and section.
Absolute/weak aliases and all state/data sections are never ownership evidence.
Permanent mutations must reject a mid-instruction target, a state/data target,
an inter-function `+offset` target and a `JSR` to an internal basic block, while
accepting a real same-function basic-block jump. Any authorized replay operates
on the SHA-bound Link-18 artifacts without invoking the linker again.

The authorized artifact-only replay passed with zero new product links. The
qualified model inspected 275 direct edges into the CPU window: 161 owned entry
edges, 113 same-function symbol-less `JMP` edges, and the one separately audited
pre-main `CHROUT`. It ignored 95 absolute/weak aliases as ownership evidence and
reported zero violations. Its positive case and five negative mutations all
behaved as required, including rejection of an alias-disguised `$ffd2` exit.

The resulting structural balance reports 4,775 live bytes in the 8-KiB window
and 3,417 bytes of actual future margin. Relocated C2 residents contribute
4,595 bytes against the historical 3,639-byte deficit; replacement machinery
costs 482 bytes. The boot/session runtime families occupy 12,273/58,270 bytes,
leaving 53,263/7,266 bytes in their mutually exclusive stores. Bank 5 retains
31,696 bytes. The publish-last table is exactly neutral (32 bytes retired,
32 bytes introduced). These are structural link claims only; hardware and
promotion remain not-run.

## Freezer fidelity class

Freezer entry/return is hardware-only. Xemu may exercise the queue and mapping
mechanics as a non-authoritative dry run, but it cannot emit a Freezer safety
PASS. Before any full acceptance chain, a receipt-less fail-fast hardware
smoke must cover: typed modifier event, RUN/STOP during evaluation, advancing
frame counter, Freezer entry/return, preserved map generation, and one further
key event after return.

## Bounded-probe exit gate

The next authorized step is one isolated, non-product proof target. It must:

- materialize the full state machine and owned vector table;
- build the typed queue path and generated L-full closure;
- use the pinned toolchain to emit and disassemble the MAP/vector sequence;
- link the replacement residents into the 8-KiB window and report every byte
  category in the net equation;
- prove both continuity invariants at every cutpoint;
- run the contract's negative matrix and mutation tests; and
- emit no product artifact or fifth substitution-link claim.

If that receipt is green, review may authorize exactly one real substitution
link. Any red capacity or structural gate returns here under first-red
discipline; no floor, slice cap or claim may be softened.
